# CNGX3014

## Sidenav content outside a sidenav layout

This error is thrown when `<cngx-sidenav-content>` from `@cngx/ui/sidenav` is created without a `<cngx-sidenav-layout>` above it.

The content element does not lay itself out. The layout is a flex container that projects the start sidenav, the content and the end sidenav into one row, and the content takes the remaining space (`flex: 1`). That is what moves the main area aside when a sidenav opens in `push` or `side` mode. Outside the layout there is no such row, so the content would not make room for any panel. The constructor throws instead of rendering a layout that silently does not work.

```html
<!-- ERROR: no <cngx-sidenav-layout> above the content -->
<cngx-sidenav position="start">Navigation</cngx-sidenav>
<cngx-sidenav-content>
  <router-outlet />
</cngx-sidenav-content>
```

### Fixing the error

Wrap the sidenavs and the content in one layout, with the content as a direct child:

```html
<cngx-sidenav-layout>
  <cngx-sidenav position="start">Navigation</cngx-sidenav>
  <cngx-sidenav-content>
    <router-outlet />
  </cngx-sidenav-content>
</cngx-sidenav-layout>
```

The layout projects its direct children by selector. A `<cngx-sidenav-content>` nested in another element inside the layout passes this check but is not projected, so it does not render.

### Debugging the error

The message reads `CNGX3014: [cngx-sidenav-content] must be placed inside <cngx-sidenav-layout>.` In a production build the message is the bare code `CNGX3014`; the check still runs there.

The check runs once, in the constructor, and looks only at the element injector. Angular resolves it from where the content is declared, not from where it ends up in the DOM. A wrapper component whose template is `<cngx-sidenav-layout><ng-content /></cngx-sidenav-layout>` does not help content passed to it: `<cngx-sidenav-content>` written as the wrapper's content resolves from the template it was written in, where no layout is above it, so it throws. Declare the layout in the same template as the content, or let the wrapper's own template contain both.
