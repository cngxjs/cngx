# CNGX3014

## Sidenav content outside a sidenav layout

This error is thrown when `<cngx-sidenav-content>` from `@cngx/ui/sidenav` is created without a `<cngx-sidenav-layout>` above it.

The content element does not lay itself out. It reads the start and end sidenavs from the layout and derives its `margin-inline-start` and `margin-inline-end` from them, so the main area moves aside when a sidenav opens in `push` or `side` mode. Without the layout there are no sidenavs to read, and the content would sit under any panel that opens. The constructor throws instead.

```html
<!-- ERROR: no <cngx-sidenav-layout> above the content -->
<cngx-sidenav position="start">Navigation</cngx-sidenav>
<cngx-sidenav-content>
  <router-outlet />
</cngx-sidenav-content>
```

### Fixing the error

Wrap the sidenavs and the content in one layout, with the content as a direct child:

```html
<cngx-sidenav-layout>
  <cngx-sidenav position="start">Navigation</cngx-sidenav>
  <cngx-sidenav-content>
    <router-outlet />
  </cngx-sidenav-content>
</cngx-sidenav-layout>
```

The layout projects its direct children by selector. A `<cngx-sidenav-content>` nested in another element inside the layout passes this check but is not projected, so it does not render.

### Debugging the error

In a production build the message is the bare code `CNGX3014`; the check still runs there.

The check runs once, in the constructor, and looks only at the element injector. Angular resolves it from where the content is declared, not from where it ends up in the DOM. Content written in a component that is itself used inside the layout does not find it: the layout must be in the same template as the `<cngx-sidenav-content>`, or the content must be projected into it from the template that declares the layout.
