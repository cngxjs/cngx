# CNGX1046

## Step outside a stepper

This error is thrown when a `[cngxStep]` is created with neither a stepper nor a step group above it in the injector tree.

A step registers itself with the stepper's presenter, which owns the active step, the linear-mode gating and the step tree that the indicators render. Inside a `[cngxStepGroup]` the step registers through the group, so the tree keeps its nesting. `CngxStep` injects both hosts optionally and needs at least one; with neither, the step has no tree to join and no active state to read, so the constructor throws.

```html
<!-- ERROR: no stepper host above the step -->
<section>
  <div cngxStep label="Account">...</div>
</section>
```

### Fixing the error

Place the step inside an element that provides a stepper. Any of these does:

- an element carrying `[cngxStepper]` (the headless presenter from `@cngx/common/stepper`),
- one of the `@cngx/ui/stepper` organisms: `<cngx-stepper>`, `<cngx-dot-stepper>`, `<cngx-text-stepper>`, `<cngx-progress-bar-stepper>`,
- the Material bridge `[cngxMatStepper]` from `@cngx/ui/mat-stepper`.

```html
<div cngxStepper>
  <div cngxStep label="Account">...</div>
  <div cngxStep label="Confirm">...</div>
</div>
```

A step inside a `[cngxStepGroup]` is fine as long as the group itself sits inside a stepper (see [CNGX1047](cngx1047.html)).

### Debugging the error

The message reads `CNGX1046: [cngxStep] must be placed inside an element with [cngxStepper], such as <cngx-stepper>, directly or through a [cngxStepGroup] inside it.` In a production build the message is the bare code `CNGX1046`; the check still runs there, because a step without a stepper cannot work.

The check runs once, in the step's constructor, and looks only at the element injector. Angular resolves it from where the step is declared, not from where it ends up in the DOM. A step inside an `ng-template` declared within the stepper finds it even when the template is rendered somewhere else. A step written as content of a component that wraps `<ng-content>` in its own stepper does not find that stepper: projected content resolves from the template it was written in. A component created dynamically (a dialog, `ViewContainerRef.createComponent`) resolves from the injector passed to it, or from the view container's, so pass one that sees the stepper.
