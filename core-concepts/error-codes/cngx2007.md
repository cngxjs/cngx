# CNGX2007

## Typed control name not found in the form group

This error is thrown when `[cngxTypedControl]` from `@cngx/forms/controls` names a control that does not exist in the enclosing `[formGroup]`.

The directive resolves its control with `form.get(name)` on the `FormGroupDirective` above it and exposes the result as the `control` signal. A name that resolves to nothing leaves `control()` at `null` for good, and every template that reads it would silently render as if the control were valid and untouched. The directive treats the name as a contract instead and throws when it does not match.

```html
<!-- ERROR: the group has no control named "mail" -->
<form [formGroup]="form">
  <input formControlName="email" cngxTypedControl="mail" />
</form>
```

### Fixing the error

Use the exact key the control has in the `FormGroup`. For a control inside a nested group, pass the dotted path: the name is always resolved against the root `[formGroup]`, also when the element sits inside a `formGroupName`.

```html
<form [formGroup]="form">
  <input formControlName="email" cngxTypedControl="email" #email="cngxTypedControl" />
  <div formGroupName="address">
    <input formControlName="street" cngxTypedControl="address.street" />
  </div>
</form>
```

A directive outside any `[formGroup]` fails earlier, with Angular's `NullInjectorError` for `FormGroupDirective`, not with this code.

### Debugging the error

The message names the control that was not found. In a production build the message is the bare code `CNGX2007`; the check still runs there.

The check runs in an `effect()`, so the stack trace starts in Angular's effect runner rather than at the template line. It runs when the directive first renders and again whenever the bound name changes. It does not run again when the group's controls change, because `FormGroup` is not signal-based: a control added to the group after the directive has rendered is reported here even though `form.get()` would find it later. Add every control the template names when you build the form, and use `addControl` only for controls no `[cngxTypedControl]` refers to yet.
