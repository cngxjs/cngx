# CNGX1017

## Status reduced to a bare coloured dot

This warning is emitted when a `<cngx-status>` has `[glyph]="false"` and no visible `[label]`.

`CngxStatus` never relies on colour alone. The `tone` input drives two signals in the dot: its colour and a glyph (`✓` for `success`, `!` for `warning`, `✕` for `danger`, `i` for `info`, `•` for `neutral`). `[glyph]="false"` removes the glyph for a GitHub-style dot, which is fine as long as a visible label sits next to it. Without the label, the dot's colour is the only thing that tells `success` from `danger`.

A sighted user with a colour vision deficiency then cannot tell the states apart, which fails WCAG 1.4.1 (Use of Color). An `aria-label` on the host does not help: it is read by assistive technology, not seen by the person looking at the dot. That is why this check ignores `aria-label`, unlike [CNGX1016](cngx1016.html).

```html
<!-- WARNING: colour is the only signal left -->
<cngx-status [tone]="health()" [glyph]="false" [attr.aria-label]="healthLabel()" />
```

### Fixing the warning

#### Option 1: Show a visible label

Keep the bare dot and put the text next to it:

```html
<cngx-status [tone]="health()" [glyph]="false" [label]="healthLabel()" />
```

The label is visible copy; route it through your own i18n.

#### Option 2: Keep the glyph

If there is no room for text, drop `[glyph]="false"`. The glyph gives every tone a distinct shape. You still need an accessible name (see [CNGX1016](cngx1016.html)), but a sighted user can tell the states apart again.

### Debugging the warning

The message starts with `cngx-status: [glyph]="false" with no visible label` and does not identify the instance. Search your templates for `[glyph]="false"` on `<cngx-status>`.

The check runs in development mode only, once per instance, after the first render, and reads `glyph()` and `label()` at that moment. An empty string counts as no label. A status without label and without an `aria-label` logs [CNGX1016](cngx1016.html) as well; fixing it with a visible `[label]` clears both.
