# CNGX3026

## Unknown sidenav width class

This warning is emitted when a `<cngx-sidenav>` inside a `<cngx-sidenav-layout>` reads a `--cngx-sidenav-width-class` value it does not know. The layout stylesheet writes one of three values on the rail through a `@container` rule block: `compact` below `48rem`, `medium` from `48rem`, `expanded` from `64rem`. Any other non-empty value lands here, almost always a typo in a rule block that overrides the thresholds.

The rail then renders as `compact`: in `auto` mode it is a closed overlay drawer at every width, even on a wide desktop. Nothing fails; the layout never docks.

```css
/* WARNING: "wide" is not a width class */
@container cngx-sidenav-layout (min-inline-size: 64rem) {
  cngx-sidenav-layout > cngx-sidenav {
    --cngx-sidenav-width-class: wide;
  }
}
```

An empty value is not a typo: it is what a rail sees before the layout's first resize entry and outside a layout. It resolves to `compact` without a warning.

### Fixing the warning

Write one of the three classes. To move a threshold, override both rules of the block and keep the values:

```css
@container cngx-sidenav-layout (min-inline-size: 40rem) {
  cngx-sidenav-layout > cngx-sidenav {
    --cngx-sidenav-width-class: medium;
  }
}

@container cngx-sidenav-layout (min-inline-size: 72rem) {
  cngx-sidenav-layout > cngx-sidenav {
    --cngx-sidenav-width-class: expanded;
  }
}
```

### Debugging the warning

The message reads `CNGX3026: [cngx-sidenav] unknown --cngx-sidenav-width-class "<value>"; expected compact, medium or expanded. Rendering as compact.` and logs the value as context. Inspect the rail in the browser's dev tools: the computed `--cngx-sidenav-width-class` shows which rule wrote it.

The check runs in development mode only, each time the resolved value changes.
