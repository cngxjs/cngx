# CNGX1037

## Floating fallback registered without middleware

This warning is emitted when a popover is positioned by the Floating UI fallback and `provideFloatingFallback(computePosition)` was registered without middleware.

CNGX positions popovers with CSS Anchor Positioning. In a browser that does not support it, the popover falls back to Floating UI if the application registered it with `provideFloatingFallback()`. Floating UI's `computePosition` on its own only places the panel at the requested side of the anchor; keeping the panel on screen is the job of its `flip()` and `shift()` middleware, which you pass as the second argument.

Without middleware, a popover near the edge of the viewport is placed off screen or clipped: a menu opened from a button at the bottom of the page opens below the fold instead of flipping above the button, and a tooltip near the right edge is cut off instead of shifting left.

```ts
// WARNING: no flip/shift middleware
import { computePosition } from '@floating-ui/dom';

bootstrapApplication(AppComponent, {
  providers: [provideFloatingFallback(computePosition)],
});
```

### Fixing the warning

Pass the middleware on registration:

```ts
import { computePosition, flip, shift } from '@floating-ui/dom';

bootstrapApplication(AppComponent, {
  providers: [provideFloatingFallback(computePosition, [flip(), shift()])],
});
```

Do not add `offset()`: the popover prepends its own offset middleware, driven by its `[offset]` input (8 pixels by default), and a second `offset()` doubles the gap. Set `[offset]` on the popover to change the gap. Any middleware array that is not empty silences the warning; CNGX does not check which middleware you chose.

### Debugging the warning

The message starts with `CngxPopover: provideFloatingFallback(computePosition) was registered without middleware` and includes the fixed registration.

The check runs in development mode only, when a popover with an anchor is positioned by the fallback, and logs once per document. It never runs in a browser that supports CSS Anchor Positioning, because the fallback is not used there; to reproduce it in such a browser, open the page in one without anchor positioning support. Without a `provideFloatingFallback()` registration at all there is no fallback and no warning.
