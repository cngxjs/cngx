# CNGX1022

## Nested option groups

This error is reported when a `[cngxOptionGroup]` contains another `[cngxOptionGroup]` anywhere inside it. Inside a `<cngx-select-shell>` the same applies to `<cngx-optgroup>`, which carries `CngxOptionGroup` as a host directive.

Option groups are one level deep by design. A group renders `role="group"` with its `aria-label`, and its `options` signal collects only its *direct* `CngxOption` children. ARIA allows groups as children of a `listbox`, but not groups inside groups. `CngxSelectShell` builds its option model from the same structure: it walks the top-level options and groups, and for each group reads `options()`.

What goes wrong depends on the host. In `CngxSelectShell`, the options of the inner group are not direct children of the outer group, so they never reach the option model: they are missing from the panel's navigation, from search and from the trigger label. In a plain `CngxListbox`, the inner options are still found and navigable, but the nested `role="group"` structure is invalid ARIA and screen readers announce it inconsistently.

```html
<cngx-select-shell [label]="countryLabel()">
  <cngx-optgroup [label]="europeLabel()">
    <!-- ERROR: a group inside a group -->
    <cngx-optgroup [label]="dachLabel()">
      <cngx-option value="at">Austria</cngx-option>
      <cngx-option value="de">Germany</cngx-option>
    </cngx-optgroup>
  </cngx-optgroup>
</cngx-select-shell>
```

### Fixing the error

#### Option 1: Flatten to one level

Promote the inner groups and drop the outer one. Put the outer context into the group label if it matters:

```html
<cngx-optgroup [label]="dachLabel()">
  <cngx-option value="at">Austria</cngx-option>
  <cngx-option value="de">Germany</cngx-option>
</cngx-optgroup>
<cngx-optgroup [label]="beneluxLabel()">
  ...
</cngx-optgroup>
```

Group labels are read by screen readers; route them through your own i18n.

#### Option 2: Use a tree select

If the data really is a hierarchy deeper than one level, use `<cngx-tree-select>` from `@cngx/forms/select`. It renders the tree with `role="tree"` semantics, expand/collapse and keyboard navigation per level, which a listbox cannot express.

### Debugging the error

The message reads `[cngxOptionGroup] Nested option groups are unsupported` and does not name the group. Search for `cngxOptionGroup` or `<cngx-optgroup>` elements inside another one, including groups that a component renders through `<ng-content>`.

The check runs in development mode only, once per group, after the first render. It is reported by the *outer* group; with three levels of nesting, the outer and the middle group each report it. A nested group that is added later (inside an `@if`) is not detected.
