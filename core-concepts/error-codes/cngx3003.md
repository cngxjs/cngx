# CNGX3003

## Alert overflow label does not contain its visible text

This warning is emitted when `<cngx-alert-stack>` shows its "+N more" overflow button and the button's accessible name, from `alertOverflow(count)`, does not contain its visible text, from `alertOverflowVisible(count)`. Both are message functions in the `announcements` bundle of `CNGX_FEEDBACK_I18N`.

The button renders the visible text as its content and sets the accessible name through `aria-label`, which replaces the content for assistive technology. WCAG 2.5.3 (Label in Name) requires the name to contain the visible words: a speech-input user says "click plus three more", and voice control matches that against the accessible name. The English defaults are built to nest (`+3 more` inside `+3 more alerts`). A translation that overrides one key without the other, or rewords both independently, breaks the nesting.

The button still looks and works the same for mouse, keyboard and screen reader users. Only speech input fails to find it.

```ts
// WARNING: "Weitere Hinweise (3)" does not contain "+3 mehr"
provideFeedbackI18n({
  announcements: {
    alertOverflowVisible: (count) => `+${count} mehr`,
    alertOverflow: (count) => `Weitere Hinweise (${count})`,
  },
});
```

### Fixing the warning

#### Option 1: Build the name from the visible text

Override both keys together and start the accessible name with the visible label, adding context after it:

```ts
provideFeedbackI18n({
  announcements: {
    alertOverflowVisible: (count) => `+${count} mehr`,
    alertOverflow: (count) => `+${count} mehr Hinweise`,
  },
});
```

The same rule applies when you set the keys through `withFeedbackI18nLabels` inside `provideFeedback()`, or in the `feedback` section of a language pack.

### Debugging the warning

The message quotes both strings, the `aria-label` first and the visible label second, as they resolved for the current count and language. It starts with `CNGX3003: [cngx-alert-stack] the overflow aria-label` followed by both strings in quotes. The comparison is a case-insensitive substring check, so `+3 MORE` inside `+3 more alerts` passes, but a changed word order or a reformatted number does not.

The check runs in development mode only, inside an effect, whenever the stack overflows (hidden count above zero). Each alert stack instance reports a given name/label pair once; a different count or a language switch yields a new pair and can warn again. If the warning appears only for some counts, look at plural branches: a `one` form that differs from the `other` form can break containment for a count of 1 alone.
