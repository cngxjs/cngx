# CNGX2033

## A Reactive Forms atom also bound by a parent value

This warning is emitted when a value atom carries `[formControl]` or `formControlName` and a parent binding on its value at the same time, usually `[(value)]="mirror"`. `CngxFormBridge` connects the atom to the form control. A parent binding updates the atom's value without telling the bridge, so the write never reaches the control (the `ControlValueAccessor` contract only forwards user changes). The atom shows the bound value, `form.value` keeps the control value, and validation runs against the control value.

```html
<!-- WARNING: a write to mirror changes the checkbox, but never ctrl. -->
<cngx-checkbox [formControl]="ctrl" [(value)]="mirror">I accept the terms</cngx-checkbox>
```

### Fixing the warning

Give the value one owner: the form control. Drop the binding and write the control instead (`setValue`, `patchValue`, `reset`). Read the value back from `ctrl.value`, `valueChanges` or the form.

```html
<cngx-checkbox [formControl]="ctrl">I accept the terms</cngx-checkbox>
```

```ts
this.ctrl.setValue(true);
```

The same goes for `[selected]` on `cngx-chip-group` or `cngxChipInteraction` and `[selectedValues]` on `cngx-checkbox-group`, `cngx-multi-chip-group` and `cngx-button-multi-toggle-group`, and for `[value]` on the mask, numeric, format and phone inputs. A `(valueChange)` listener without a binding is fine: it only reads.

### Why the bridge does not forward the parent write

A form control treats every value from its accessor as a user change: it marks itself dirty and runs `updateOn` and validation as an interaction. A parent binding is a programmatic write, the same as loading a model. Forwarding it would dirty the control on every parent update.

### Debugging the warning

The message starts with `CNGX2033:` followed by the host element in brackets, and the host element is logged after the message. The check runs in development mode only, once per atom, when the atom's value changes without the change passing through the atom itself (a click, the keyboard, typing) or through the form control (`setValue`, `patchValue`, `reset`). A two-way binding that only ever mirrors those changes stays silent; the warning comes on the first parent write that differs. Atoms in `cngx-form-field` with a Signal Forms field are covered by [`CNGX2032`](./cngx2032.md) instead. In production the warning is stripped.
