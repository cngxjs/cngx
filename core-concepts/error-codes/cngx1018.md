# CNGX1018

## Tag group label without a semantic list

This warning is emitted when a `<cngx-tag-group>` has a `[label]` but `[semanticList]` resolves to `false`.

`CngxTagGroup` is a layout container. It binds `[label]` straight to `aria-label` on its host, and it sets `role="list"` only when `semanticList` is `true`. The same flag cascades to the projected tags: each `CngxTag` reads it through `CNGX_TAG_GROUP` and renders `role="listitem"` only inside a semantic list.

With a label and no list role, the `aria-label` lands on an element without a role. ARIA does not allow naming such an element, so most screen readers drop the label, and the tags are read as loose text without "list, 4 items". The label you wrote has no effect, and nothing in the page shows it.

```html
<!-- WARNING: the label sits on an element without a role -->
<cngx-tag-group [label]="topicsLabel()">
  @for (topic of topics(); track topic.id) {
    <span cngxTag>{{ topic.name }}</span>
  }
</cngx-tag-group>
```

### Fixing the warning

#### Option 1: Make the group a list

If the tags are a set the user should hear as one, a list is the right semantics. Add `[semanticList]="true"`:

```html
<cngx-tag-group [label]="topicsLabel()" [semanticList]="true">
  @for (topic of topics(); track topic.id) {
    <span cngxTag>{{ topic.name }}</span>
  }
</cngx-tag-group>
```

The group now renders `role="list"` with the label, and every direct `CngxTag` child gets `role="listitem"`. The label is user-facing copy; route it through your own i18n.

To make every tag group a list by default, set it app-wide with `provideTagConfig(withTagGroupDefaults({ semanticList: true }))` from `@cngx/common/display`.

#### Option 2: Remove the label

If the tags are decoration (a row of keywords inside a card that already has a heading), the group needs no name. Drop `[label]`.

### Debugging the warning

The message starts with `CNGX1018: [cngx-tag-group] [label] is bound without [semanticList]="true"` and does not identify the instance. Search your templates for `<cngx-tag-group` with a `label` binding.

The check runs in development mode only, once per instance, after the first render. It reads the resolved `semanticList`, so a `withTagGroupDefaults({ semanticList: true })` default counts as `true`. A label or flag that changes after the first render is not checked again.
