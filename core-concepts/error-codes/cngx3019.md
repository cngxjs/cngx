# CNGX3019

## Accordion item outside an accordion group

This error is thrown when `<cngx-accordion-item>` from `@cngx/ui/accordion` is created without a `<cngx-accordion-group>` above it.

An item does not track its own open state. The group owns the open set (`[multi]`, `[(openIds)]`), the heading level every item header uses, the skin and the keyboard navigation across items; each item registers with the group and reads all of that from it. Outside a group an item has no open set to join and no heading level to render, so the constructor throws instead of rendering a header that cannot expand.

```html
<!-- ERROR: no <cngx-accordion-group> above the item -->
<cngx-accordion-item>
  <span cngxAccordionItemTitle>Shipping</span>
  Ships within two days.
</cngx-accordion-item>
```

### Fixing the error

Wrap the items in a group, even a group of one:

```html
<cngx-accordion-group>
  <cngx-accordion-item>
    <span cngxAccordionItemTitle>Shipping</span>
    Ships within two days.
  </cngx-accordion-item>
</cngx-accordion-group>
```

For a single disclosure without the group's skin and heading, use `[cngxExpandable]` from `@cngx/common/interactive` instead of a one-item accordion.

### Debugging the error

The message reads `CNGX3019: [cngx-accordion-item] must be placed inside <cngx-accordion-group>.` In a production build the message is the bare code `CNGX3019`; the check still runs there.

The check runs once, in the constructor, and looks only at the element injector. Angular resolves it from where the item is declared, not from where it ends up in the DOM. An item passed as content to a wrapper component whose template contains the `<cngx-accordion-group>` resolves from the template it was written in, where no group is above it, so it throws. Declare the group in the same template as its items.
