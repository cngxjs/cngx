# CNGX1021

## Duplicate name in the error registry

This warning is emitted when `CngxErrorRegistry` already holds a scope or an aggregator under a name, and a different instance registers with the same name. Scopes register through `[cngxErrorScopeName]` or `injectErrorScope(name)`, aggregators through `[cngxErrorAggregatorName]` or `injectErrorAggregator(name)`, whenever `provideErrorRegistry()` is in the providers.

The registry is a lookup by name: `getScope`, `getAggregator`, `reveal(name)` and `reset(name)` resolve exactly one instance per name. On a collision the registry keeps the instance that registered first and ignores the new one (swap-is-noop). Scopes and aggregators have separate name spaces, so a scope and an aggregator may share a name.

The second instance works on its own, but code that drives it by name does not reach it. `reveal('checkout')` from a submit handler reveals only the first scope, and `hasAnyError` / `totalErrorCount` leave the second aggregator out. When the first instance is destroyed, it unregisters the name and the second one does not take over: the name stays empty until the second instance is recreated or renamed.

The usual cause is a reusable form component with a fixed name that renders twice, in a list, in two tabs, or in a dialog over a page that shows the same form:

```html
<!-- address-form.component.html, rendered once for billing and once for shipping -->
<!-- WARNING: both instances register the scope "address" -->
<form cngxErrorScope cngxErrorScopeName="address">
  ...
</form>
```

### Fixing the warning

#### Option 1: Derive the name from an input

Let the parent pass something that tells the instances apart:

```ts
export class AddressForm {
  readonly kind = input.required<'billing' | 'shipping'>();
  protected readonly scopeName = computed(() => `address-${this.kind()}`);
}
```

```html
<form cngxErrorScope [cngxErrorScopeName]="scopeName()">
  ...
</form>
```

The directives re-register when the name input changes, so a computed name is fine.

#### Option 2: Replace the instance on purpose

If the new instance is meant to take over the name, the old one has to leave first. With the directives that happens when the old one is destroyed or renamed. With the programmatic API, call `unregisterScope(name, oldScope)` (or `unregisterAggregator(name, oldAggregator)`) before you register the new instance. Unregistering only works with the instance that holds the name; passing any other instance is a no-op.

### Debugging the warning

The message names the kind and the name, for example `CNGX1021: registerScope(): a scope named "address" is already registered` or `CNGX1021: registerAggregator(): an aggregator named "address" is already registered`. Search for that string in `cngxErrorScopeName`, `cngxErrorAggregatorName`, `injectErrorScope` and `injectErrorAggregator` calls.

The check runs in development mode only, each time a different instance registers under a taken name. Registering the same instance twice is silent. The directives register after the first render, so the instance that renders first holds the name. Without `provideErrorRegistry()` nothing registers and this warning never fires. Duplicate source keys inside one aggregator are a separate warning, [CNGX1020](cngx1020.html).
