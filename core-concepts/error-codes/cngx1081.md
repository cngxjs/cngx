# CNGX1081

## Second popover trigger takes the close listener

This warning is emitted when a second `CngxPopoverTrigger` from `@cngx/common/popover` binds to a popover that already has a trigger.

A `CngxPopover` holds one close listener. Its trigger registers it, and the popover calls it synchronously at the end of every close so the trigger can return focus. The slot has room for one listener, and the last registration wins: the earlier trigger keeps its ARIA attributes but no longer restores focus when the popover closes. Nothing throws.

```html
<!-- WARNING: only #second restores focus -->
<button id="first" [cngxPopoverTrigger]="pop" [restoreFocus]="true">Open</button>
<button id="second" [cngxPopoverTrigger]="pop" [restoreFocus]="true">Open too</button>
<div cngxPopover #pop="cngxPopover">Content</div>
```

### Fixing the warning

Bind one `CngxPopoverTrigger` per popover. When several controls open the same content, give each its own popover, or keep one trigger and let the other controls call `pop.show()` without the trigger directive.

```html
<button [cngxPopoverTrigger]="pop" [restoreFocus]="true" (click)="pop.toggle()">Open</button>
<button type="button" (click)="pop.show()">Open from elsewhere</button>
<div cngxPopover #pop="cngxPopover">Content</div>
```

### Debugging the warning

The message starts with `CNGX1081: [cngxPopover] a second CngxPopoverTrigger registered on this popover and replaced the first one.` The context argument is the popover element.

The check runs in development mode only, when the second trigger registers. Re-registering the same trigger does not warn. In production the last trigger takes the slot the same way, without a warning.
