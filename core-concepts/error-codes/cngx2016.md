# CNGX2016

## OTP slot outside an OTP input

This error is thrown when `input[cngxOtpSlot]` from `@cngx/forms/input` is created without a `[cngxOtpInput]` above it.

A slot is one character box of a one-time-code field. It holds no value of its own: the surrounding `[cngxOtpInput]` owns the code, its length and the completed event, and each slot reads and writes its character there, moves focus to the next or previous slot and hands a pasted code to the container to spread over all slots. Without the container a slot has nowhere to store its character, so the constructor throws instead of rendering a box whose input is lost.

```html
<!-- ERROR: no OTP container above the slots -->
<input [cngxOtpSlot]="0" />
<input [cngxOtpSlot]="1" />
```

### Fixing the error

Render the slots inside the container, and let it drive how many there are:

```html
<div cngxOtpInput [length]="6" #otp="cngxOtpInput" (completed)="verify($event)">
  @for (i of otp.indices(); track i) {
    <input [cngxOtpSlot]="i" />
  }
</div>
```

### Debugging the error

The message reads `CNGX2016: [cngxOtpSlot] must be placed inside an element with [cngxOtpInput].` In a production build the message is the bare code `CNGX2016`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A parent that another component renders in its own template, around content you project into it, is not above the projected element.
