# CNGX3007

## Mat-tabs overflow could not anchor

This warning is emitted when `[cngxMatTabs]` cannot find Material's tab header, `.mat-mdc-tab-header`, inside its `<mat-tab-group>` host after the configured number of attempts (`anchorMaxAttempts`, default 5).

`[cngxMatTabs]` adds a "More" overflow menu to a `<mat-tab-group>`. It creates a `<cngx-tab-overflow>` through its own `ViewContainerRef`, which places it next to the host element, then moves that element into `.mat-mdc-tab-header` so the "More" button pins to the strip's trailing edge. The move waits for Material to render the header: it is attempted after the first render and retried after each following application render until the header exists or the budget runs out. `.mat-mdc-tab-header` is Material's private markup; cngx depends on that class name.

When the budget runs out, the overflow stays where it was created, beside `<mat-tab-group>` rather than inside the strip. The styles that align it with the tabs no longer apply, and the overflow molecule cannot find the tab strip either, so the menu does not list the clipped tabs.

```html
<!-- WARNING: the rendered header no longer carries .mat-mdc-tab-header -->
<mat-tab-group cngxMatTabs [attr.aria-label]="settingsLabel()">
  <mat-tab [label]="profileLabel()">...</mat-tab>
</mat-tab-group>
```

Material renders the header in the group's own first render, so with a supported Material version the first attempt normally succeeds. The usual causes are a Material version whose header markup differs, a test double or custom component standing in for `MatTabGroup`, or a render pass that does not complete.

### Fixing the warning

#### Option 1: Check the rendered header markup

Inspect the `<mat-tab-group>` in the browser's element panel. If no descendant carries `.mat-mdc-tab-header`, the Material version is not compatible with the bridge; report it as a cngx bug with the `@angular/material` version. In unit tests, render the real `MatTabsModule` components rather than stubs when the test exercises `[cngxMatTabs]`.

#### Option 2: Raise the attempt budget

If the header does appear, but only after several render passes, raise the budget:

```ts
provideMatTabsConfig(withAnchorRetryAttempts(10));
```

Use `provideMatTabsConfigAt(withAnchorRetryAttempts(10))` in a component's `providers` to raise it for one view only.

### Debugging the warning

The message names the attempt count, for example `after 5 attempts`, which is the resolved `anchorMaxAttempts`. The lookup is `querySelector('.mat-mdc-tab-header')` on the `<mat-tab-group>` element. The message also suggests checking for a never-true `*ngIf` or `@defer`; that applies only to a condition inside the group, because `[cngxMatTabs]` must sit on the `<mat-tab-group>` itself (it injects `MatTabGroup` from its own element and fails with a DI error otherwise).

The check runs in development mode only, once per `[cngxMatTabs]` instance. Attempts are counted per application render through `afterNextRender`, not per animation frame, so the loop does not run during server-side rendering and waits while nothing renders.

[CNGX3012](cngx3012.html) usually follows this warning, because the overflow then fails to find the tab strip. The decoration retries for error and rejection state use a separate, fixed budget and report [CNGX3005](cngx3005.html).
