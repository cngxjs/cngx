# CNGX2023

## Array operator received a non-array value

This warning is emitted when a filter expression from `@cngx/forms/filter-builder` uses one of the array operators, `between`, `in` or `notIn`, but its value has another shape.

The three operators compare against more than one value:

|Operator|Expected value|
|-|-|
|`between`|`[min, max]`, an array of exactly two bounds|
|`in`|an array of values|
|`notIn`|an array of values|

The built-in value editors write a single value: a text, number or date input emits a scalar. A field that lists `between`, `in` or `notIn` in its `operators` but keeps the default editor stores a scalar in the expression, such as `30` instead of `[30, 40]`. CNGX cannot guess what a scalar means for a range, and wrapping it into `[x]` for `in` would hide the missing editor, so the expression evaluates to `false` for every item. The list filters down to nothing.

```ts
const fields: FilterFieldDef[] = [
  // WARNING: between is listed, but the default number editor writes a single number
  { key: 'age', label: 'Age', editorType: 'number', operators: ['between', 'gte', 'lte'] },
];
```

### Fixing the warning

#### Option 1: Bind a value editor that writes the array shape

Project a `*cngxFilterBuilderValueEditor` template that renders a matching editor for the array operators and falls back to a plain input for the others. The slot context carries the `expression`, so the template can switch on `expression.operator`. The examples app shows a two-input range editor for `between` under `forms/filter-builder/custom-operators/between-range-editor-via-value-editor-slot`.

#### Option 2: Remove the operator from the field

If the field does not need a range or list match, drop `between`, `in` and `notIn` from its `operators`. They are not in the default operator lists; a field offers them only when its `operators` names them.

#### Option 3: Fix stored or programmatic values

If the expression comes from a saved filter or from code (`createFilterExpression('age', 'between', 30)`), write the array shape there.

### Debugging the warning

The message starts with `CNGX2023: evaluateExpression(): operator "between"` (or `"in"`, `"notIn"`) and names the expected shape. Search your `fields` for the operator and check which value editor the field gets.

The check runs in development mode only and warns once per operator key for the lifetime of the application, so a large filtered list does not flood the console; later expressions with the same operator and a wrong value are not reported again. A `between` array with a `null` or `undefined` bound is not a wrong shape: it is a half-filled range and matches every item until both bounds are set.
