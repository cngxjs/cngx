# CNGX1007

## Non-numeric chart data without a summary accessor

This warning is emitted when `<cngx-chart>` receives `[data]` whose first item does not convert to a finite number, and no `[summaryAccessor]` is bound.

The chart is exposed to assistive technology as one labelled graphic. It builds that label (the auto-summary) and the screen-reader data table from one number per data item. It gets those numbers from `[summaryAccessor]`, a `(item, index) => number` function. The default accessor is `Number(item)`, which only makes sense for a plain numeric array. Layers such as `[cngxLine]` have their own `[accessor]` for drawing and do not feed the summary.

So with an array of objects, the drawn chart is correct, while the summary and the data table are built from `NaN`. Sighted users see nothing wrong; screen-reader users get a meaningless description:

```html
<!-- WARNING: sales() holds objects, and the chart summarises them with Number(item) -->
<cngx-chart [data]="sales()">
  <svg:g cngxAxis position="left" [domain]="[0, 50000]"></svg:g>
  <svg:g cngxLine [accessor]="revenueOf"></svg:g>
</cngx-chart>
```

### Fixing the warning

#### Option 1: Bind a summary accessor

Pass the same projection the marks use:

```html
<cngx-chart [data]="sales()" [summaryAccessor]="revenueOf">
  <svg:g cngxAxis position="left" [domain]="[0, 50000]"></svg:g>
  <svg:g cngxLine [accessor]="revenueOf"></svg:g>
</cngx-chart>
```

```ts
protected readonly revenueOf = (sale: Sale): number => sale.revenue;
```

Define the accessor as a stable field, not an inline arrow in the template, so the chart does not re-project the data on every change detection.

#### Option 2: Pass numeric data

If the chart shows a single series, map the data to numbers before binding it, for example `revenues = computed(() => this.sales().map((s) => s.revenue))`, and bind `[data]="revenues()"`. The default accessor then works.

### Debugging the warning

The message is fixed text and does not name the chart. It starts with `CNGX1007: [cngx-chart] data is non-numeric and no [summaryAccessor] is bound.` and goes on with the fallback and the two fixes. Look for `<cngx-chart>` instances whose `[data]` holds objects and that have no `[summaryAccessor]`; `NaN` values in the chart's summary text or in its screen-reader data table confirm the instance.

The check runs in development mode only, once per chart, after the first render. It looks only at the first item and only at that moment: data that is still empty on first render (loaded asynchronously) is not checked, and data that arrives later is never checked. It is skipped whenever any `[summaryAccessor]` is bound, even one that returns `NaN`.
