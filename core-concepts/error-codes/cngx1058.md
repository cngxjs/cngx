# CNGX1058

## Menu item outside a menu

This warning is emitted when a menu item from `@cngx/common/interactive` (`[cngxMenuItem]`, `[cngxMenuItemCheckbox]`, `[cngxMenuItemRadio]`, or a custom item built on `injectMenuItemCore()`) is created without a `[cngxMenu]` around it.

A menu item does not act on its own click. The menu tracks which item is active (through the active-descendant pattern), and a click asks the menu to highlight the item and activate it; the menu then runs the item's action, emits its selection and closes. Without a menu the click has nobody to ask, so it does nothing: the item renders, takes the pointer, and never fires. Nothing throws, so the item just looks dead.

```html
<!-- WARNING: the items sit in a plain list, not in a menu -->
<ul>
  <li cngxMenuItem value="rename">Rename</li>
  <li cngxMenuItem value="delete">Delete</li>
</ul>
```

### Fixing the warning

Put the items inside an element with `[cngxMenu]`, usually the panel a menu trigger opens:

```html
<ul cngxMenu label="File actions" (itemActivated)="run($event)">
  <li cngxMenuItem value="rename">Rename</li>
  <li cngxMenuItem value="delete">Delete</li>
</ul>
```

For a plain list of buttons outside a menu, use `<button type="button">` with a `(click)` handler instead of a menu item.

### Debugging the warning

The message starts with `CNGX1058: injectMenuItemCore(): the menu item has no surrounding [cngxMenu]`. It does not name the item; look for menu items whose template has no `[cngxMenu]` above them.

The check runs in development mode only, once per item, when the item is created. It looks for the menu through the element injector, from where the item is declared, so an item passed as content into a component that renders the `[cngxMenu]` in its own template does not find it and warns.
