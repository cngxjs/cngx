# CNGX2013

## Unknown filter logic

This error is thrown when a `FilterGroup` from `@cngx/forms/filter-builder` carries a `logic` value other than `'and'`, `'or'` or `'xor'`.

`FilterLogic` is typed as `'and' | 'or' | 'xor'`, so a tree built in code with `createFilterGroup` cannot hold anything else. A tree that comes from outside the type system can: deserialised JSON, a value from local storage or a URL, a preset written by hand, a snapshot from an older version of your app. The filter builder has no meaning for an unknown combinator, and treating it as `'and'` would filter the list in a way nobody asked for, so it throws.

`ensureFilterTreeIds` checks every group and throws. The `[cngxFilterBuilderPresenter]` directive, which `<cngx-filter-builder>` hosts, runs it in an effect on its `value` model, so a bad tree bound or written to `value` is reported as soon as the effect runs, through Angular's `ErrorHandler`. The tree stays in `value`: the presenter's `predicate()` evaluates it and throws CNGX2013 again wherever it is read, until a valid tree replaces it. A tree passed straight to `toFilterPredicate` without that step throws when the predicate first evaluates the group, inside whatever reads the predicate.

```typescript
const saved = JSON.parse(localStorage.getItem('filters') ?? 'null') as FilterGroup;
// saved.logic is "AND" from an older version of the app
ensureFilterTreeIds(saved); // ERROR: CNGX2013
```

### Fixing the error

Normalise `logic` where the tree enters your app, before it reaches the filter builder, and decide there what an unknown value means for you:

```typescript
import { type FilterGroup, type FilterLogic, type FilterNode } from '@cngx/forms/filter-builder';

const LOGICS: readonly FilterLogic[] = ['and', 'or', 'xor'];

function normaliseLogic(group: FilterGroup): FilterGroup {
  const lower = String(group.logic).toLowerCase();
  const logic = LOGICS.find((l) => l === lower) ?? 'and';
  const filters = group.filters.map((node: FilterNode) =>
    node.type === 'group' ? normaliseLogic(node) : node,
  );
  return { ...group, logic, filters };
}
```

If the stored data can be arbitrarily broken, validate the whole shape with your schema library instead and discard what does not match.

### Debugging the error

The message names where the value was found and quotes it: `CNGX2013: ensureFilterTreeIds(): unknown filter logic "AND"` at the write, `CNGX2013: toFilterPredicate(): unknown filter logic "AND"` during evaluation. In a production build the message is the bare code `CNGX2013`; the check still runs there.

Search for where the tree is read from storage, a URL or an API, and log it before it reaches `ensureFilterTreeIds` or the presenter's `value`. A value that differs only in case, or a legacy name such as `"all"` / `"any"`, points to data written by another version of the app.
