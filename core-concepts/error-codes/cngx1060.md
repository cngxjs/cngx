# CNGX1060

## Accordion panel outside an accordion

This error is thrown when `[cngxAccordionPanel]` from `@cngx/common/interactive` is created without an accordion above it.

The panel directive sits on an accordion header button. It holds no open state of its own: `aria-expanded` is derived from the accordion's set of open panels, a click asks the accordion to toggle the panel, and arrow-key navigation goes through the accordion's keyboard handler. The accordion is `[cngxAccordion]`, which `<cngx-accordion-group>`, `<cngx-data-grid-accordion>` and `[cngxMatAccordion]` from `@cngx/ui` carry for you. Without it the header cannot open or close anything, so the constructor throws instead of rendering a button that does nothing.

```html
<!-- ERROR: no accordion above the header -->
<button cngxAccordionPanel panelId="shipping" controls="shipping-region">Shipping</button>
```

### Fixing the error

Wrap the headers in the element that carries the accordion:

```html
<div cngxAccordion>
  <button cngxAccordionPanel panelId="shipping" controls="shipping-region">Shipping</button>
  <section id="shipping-region">...</section>
</div>
```

With `<cngx-accordion-group>` you do not place the directive yourself; each `<cngx-accordion-item>` renders its header with it.

### Debugging the error

The message reads `CNGX1060: [cngxAccordionPanel] must be placed inside an element with [cngxAccordion], such as <cngx-accordion-group>.` In a production build the message is the bare code `CNGX1060`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A parent that another component renders in its own template, around content you project into it, is not above the projected element.
