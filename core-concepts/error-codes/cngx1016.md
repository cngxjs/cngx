# CNGX1016

## Status without an accessible name

This warning is emitted when a `<cngx-status>` renders without a `[label]` and without an `aria-label` or `aria-labelledby` attribute on its host.

`CngxStatus` draws a tone dot and, when `[label]` is set, a text span next to it. The dot is `aria-hidden="true"`: its colour and its glyph are decoration for sighted users, and the label is the only part assistive technology is meant to read. Without a label there is nothing in the accessibility tree that says what the status is.

Nothing breaks visually. A sighted user still sees a coloured dot with a glyph, so the gap goes unnoticed until someone tests with a screen reader, which reads nothing at all for the element. A status with `live="polite"` or `live="assertive"` is worse off: the live region updates, but it has no text to announce.

```html
<!-- WARNING: no label, the status is silent for a screen reader -->
<cngx-status [tone]="health()" />
```

### Fixing the warning

#### Option 1: Set a visible label

Bind `[label]` to the text the tone stands for:

```html
<cngx-status [tone]="health()" [label]="healthLabel()" />
```

```ts
protected readonly healthLabel = computed(() => this.i18n.healthLabels()[this.health()]);
```

The label is visible text, so route it through your own i18n like any other copy. Keep it in sync with the tone in a `computed()`; a label that still says "Operational" while the dot turns red is worse than no label.

#### Option 2: Point at text that already exists

If the status text is already on screen, for example in a table cell next to the dot, `aria-labelledby` on the host silences the warning:

```html
<span id="db-state">{{ dbStateLabel() }}</span>
<cngx-status [tone]="dbTone()" aria-labelledby="db-state" />
```

The `<cngx-status>` host has no `role`, and ARIA does not allow naming an element without one, so screen readers may ignore `aria-label` and `aria-labelledby` there. Prefer Option 1 whenever the layout allows it.

### Debugging the warning

The message starts with `cngx-status:` and does not identify the instance. Search your templates for `<cngx-status` without a `label` binding.

The check runs in development mode only, once per instance, after the first render. It reads `[label]` and the host's `aria-label` / `aria-labelledby` attributes at that moment; a label that arrives later (from an HTTP response, say) does not clear a warning that has already been logged, and an empty string counts as no label. A status with `[glyph]="false"` and no label also triggers [CNGX1017](cngx1017.html), which an `aria-label` does not fix.
