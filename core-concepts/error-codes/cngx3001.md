# CNGX3001

## No Router for a router-sync directive

This warning is emitted when one of the `@cngx/ui` router-sync directives is on the page but the injector has no `Router`: `CngxBreadcrumbRouterSync` (`<cngx-breadcrumb cngxRouterSync>`), `CngxBreadcrumbSiblingsRouterSync` (`<cngx-breadcrumb-siblings cngxRouterSync>`) or `CngxTocRouterSync` (`[cngxTocRouterSync]` next to `<cngx-toc>`). `CngxTocRouterSync` also needs an `ActivatedRoute` and warns when either is missing.

These directives inject `Router` optionally, so that `@cngx/ui` does not force `@angular/router` on apps that never route. The constructor decides once: with a router it subscribes to `NavigationEnd` (breadcrumbs) or to the TOC's activations and the route fragment (TOC); without one it skips all of that. The breadcrumb directives then publish a constant empty list through their source token, and the TOC directive neither writes `#section` into the URL nor scrolls to a deep-linked section on load.

Nothing throws. Because the router source wins over the component's own `[items]` / `[siblings]` input, the breadcrumb bar renders an empty trail even if the input is bound, and the TOC still works as a scroll-spy but deep links are lost. The directive stays inactive for the lifetime of the host; providing a router later does not revive it.

```ts
// WARNING: no provideRouter(...), but the template uses <cngx-breadcrumb cngxRouterSync />
bootstrapApplication(AppComponent, {
  providers: [provideFeedback(withToasts())],
});
```

### Fixing the warning

#### Option 1: Provide the router

Register the router in the application config, and give each route that should appear in the trail a label under `data.breadcrumb` (or the key set with the directive's `dataKey` input):

```ts
bootstrapApplication(AppComponent, {
  providers: [provideRouter(routes)],
});
```

In a unit test, add `provideRouter([])` to the `TestBed` providers when the component under test uses one of these directives.

#### Option 2: Drop the router-sync attribute

If the view is not routed, remove `cngxRouterSync` / `cngxTocRouterSync` and drive the component through its inputs: `[items]` on `<cngx-breadcrumb>`, `[siblings]` on `<cngx-breadcrumb-siblings>`. Without the attribute no source token is provided, so the input is what renders.

### Debugging the warning

The message starts with `CNGX3001: ` and the directive (`[cngxRouterSync] on <cngx-breadcrumb>`, `[cngxRouterSync] on <cngx-breadcrumb-siblings>` or `[cngxTocRouterSync]`) and ends with the feature it would enable: router-driven crumbs, router-driven siblings or fragment deep-linking.

The check runs in development mode only, once per directive instance, after the first render. It is not deduplicated: three breadcrumb bars without a router print three lines. The check looks only at the injector; it does not inspect your route config, so a provided router whose routes carry no `data.breadcrumb` produces an empty trail without this warning. `CngxTocRouterSync` needs both `Router` and `ActivatedRoute`; `provideRouter` supplies both.

The `@cngx/common` router-sync directives (stepper, tabs, query-param sync, paginator routing) report the same condition as [CNGX1031](cngx1031.html). `CngxSidenavRouterSync` is a `@cngx/ui` directive but delegates to `injectQueryParamSync()`, so it reports CNGX1031 too.
