# CNGX0008

## Preference axis written without its installer

This warning is emitted when the signal of a theming preference axis from `@cngx/core` is written (`set` or `update`) while the axis installer is not in the application config. The axes are density, text scale, motion, contrast and touch targets; their installers are `provideDensity`, `provideTextScale`, `provideMotion`, `provideContrast` and `provideTouchTargets`, or `provideA11yPreferences` for the first four.

Without the installer, `injectDensity()` (and its siblings) still returns a writable signal, the token's root default. Nothing reflects that signal onto `<html>`, so the write changes what JavaScript reads but not the page: `data-density` and the other attributes stay as they were, and the token CSS never sees the new value. Nothing throws.

```ts
// app.config.ts has no provideDensity()
export class DensityPicker {
  private readonly density = injectDensity();

  protected handleCompact(): void {
    // WARNING: the signal says compact, the page stays comfortable
    this.density.set('compact');
  }
}
```

### Fixing the warning

Install the axis once in the application config:

```ts
bootstrapApplication(App, { providers: [provideDensity()] });
```

To install all four user-facing axes together, with optional persistence, use `provideA11yPreferences(withPersistence())`.

### Debugging the warning

The message names the missing installer and the attribute, for example `CNGX0008: provideDensity() is not installed, so this write changes the signal but not <html data-density>`. The stack trace of the warning points at the write.

The check runs in development mode only and fires on every write to the default signal; it is not deduplicated. Reading the signal never warns, and a write after the installer is in place never warns.
