# CNGX1025

## Submenu without a popover or menu

This warning is emitted when a `[cngxMenuItemSubmenu]` has no complete submenu wiring after the first render: either the popover (the `cngxMenuItemSubmenu` value) or the inner menu (`[submenuMenu]`) is missing, and no wrapping component provides `CNGX_MENU_SUBMENU_WIRING`.

The directive needs two references to work. The popover is what it shows, hides and anchors to the parent row. The inner `CngxMenu` is where focus goes when the submenu opens, and what the surrounding menu trigger routes ArrowRight and ArrowLeft to. Both come either from the inputs or from `CNGX_MENU_SUBMENU_WIRING`, which components like `<cngx-context-menu-item>` provide. Until both are present, the directive stays inert on purpose: it renders neither `aria-haspopup` nor `aria-expanded`, so it never promises a submenu it cannot open.

The row then looks and reads like an ordinary menu item: screen readers are not told it has a submenu, and ArrowRight has no inner menu to move focus into.

```html
<ul cngxMenu [label]="fileMenuLabel()">
  <!-- WARNING: the popover is bound, the inner menu is not -->
  <li cngxMenuItem value="recent" [cngxMenuItemSubmenu]="recentPop">
    {{ openRecentLabel() }}
  </li>
</ul>
```

### Fixing the warning

#### Option 1: Bind the popover and the inner menu

Bind the submenu's `cngxPopover` to `[cngxMenuItemSubmenu]` and its `cngxMenu` to `[submenuMenu]`:

```html
<ul cngxMenu [label]="fileMenuLabel()">
  <li cngxMenuItem value="recent" [cngxMenuItemSubmenu]="recentPop" [submenuMenu]="recentMenu">
    {{ openRecentLabel() }}
  </li>
</ul>

<div cngxPopover #recentPop="cngxPopover" placement="right-start" [positionTryFallbacks]="submenuFallbacks">
  <ul cngxMenu #recentMenu="cngxMenu" [label]="recentFilesLabel()">
    ...
  </ul>
</div>
```

`submenuFallbacks` is `CNGX_SUBMENU_TRY_FALLBACKS` from `@cngx/common/interactive`, exposed as a component field (see [CNGX1026](cngx1026.html)). Labels are user-facing copy; route them through your own i18n.

#### Option 2: Use a component that provides the wiring

`<cngx-context-menu-item [submenu]="exportMenu">` from `@cngx/ui/context-menu` provides `CNGX_MENU_SUBMENU_WIRING` and resolves both references from the sibling `<cngx-context-menu>`. A custom wrapper component can do the same by providing the token itself.

### Debugging the warning

The message starts with `CNGX1025: [cngxMenuItemSubmenu] has no popover/menu source` and does not name the element. Search for `cngxMenuItemSubmenu` and check that both inputs are bound, and that the template reference variables point at the right elements (`#recentPop="cngxPopover"`, `#recentMenu="cngxMenu"`).

The check runs in development mode only, once per submenu directive, after the first render. When a component provides `CNGX_MENU_SUBMENU_WIRING`, the check stays silent even if that wiring resolves nothing yet, because the wiring can fill in later. A submenu directive without a sibling `[cngxMenuItem]` is reported separately as [CNGX1024](cngx1024.html).
