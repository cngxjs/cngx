# CNGX1003

## Unrecognised event key on `[cngxAudio]`

This warning is emitted when the `[cngxAudio]` binding contains a key that is neither a supported DOM event nor an async-status key.

`[cngxAudio]` parses its binding as comma-separated `event:earcon` pairs and attaches one listener per recognised event. It supports a fixed set: `click`, `focus`, `blur`, `pointerenter`, `pointerleave`, `submit`, `change` and `input`. Any other key, and any pair without a colon, is set aside and gets no listener.

The other pairs in the binding keep working, so a misspelled or unsupported event looks like an earcon that is "sometimes" missing. Common causes are a typo, an event outside the set (`mouseenter`, `keydown`, `dblclick`), or a missing colon:

```html
<!-- WARNING: "mouseenter" is not a supported event -->
<a href="/reports" [cngxAudio]="'mouseenter:notification, click:tap'">Reports</a>
```

### Fixing the warning

#### Option 1: Use a supported event

Map the key to the closest supported event. For hover, use the pointer events:

```html
<a href="/reports" [cngxAudio]="'pointerenter:notification, click:tap'">Reports</a>
```

#### Option 2: Play the earcon from your own handler

For an event outside the set, listen to it yourself and play the earcon through the engine:

```ts
import { injectCngxAudio } from '@cngx/common/audio';

export class ReportsLink {
  private readonly audio = injectCngxAudio();

  protected handleDoubleClick(): void {
    this.audio.play('notification');
  }
}
```

```html
<a href="/reports" (dblclick)="handleDoubleClick()">Reports</a>
```

`play()` goes through the same mute, reduced-motion, autoplay and debounce gates as the directive.

### Debugging the warning

The message lists the keys it did not recognise, for example `CNGX1003: [cngxAudio] Unrecognised event keys "mouseenter"`, followed by the supported set. A pair without a colon is listed as the whole pair text.

The check runs in development mode only, once per directive instance, after the first render, against the binding value at that moment. Status keys such as `success` are reported as [CNGX1002](cngx1002.html), not here. `[cngxAudioStatus]` does not warn about unknown keys at all; it ignores them silently.
