# CNGX2018

## Select search outside a select shell

This error is thrown when `<cngx-select-search>` from `@cngx/forms/select` is created without a `<cngx-select-shell>` above it.

The search box filters the options of a declarative select. It holds no term of its own: it reads and writes the search term of the surrounding shell, which filters its projected `<cngx-option>` elements, and it forwards the arrow keys, Enter and Escape to the shell's listbox and panel. Without a shell the term filters nothing and the keys reach no listbox, so the constructor throws instead of rendering a search box that has no effect.

```html
<!-- ERROR: the search box sits outside the shell -->
<cngx-select-search placeholder="Filter countries" />
<cngx-select-shell [(value)]="country">
  <cngx-option value="at">Austria</cngx-option>
</cngx-select-shell>
```

### Fixing the error

Project the search box into the shell, next to the options:

```html
<cngx-select-shell [(value)]="country">
  <cngx-select-search placeholder="Filter countries" />
  <cngx-option value="at">Austria</cngx-option>
  <cngx-option value="de">Germany</cngx-option>
</cngx-select-shell>
```

The other select components (`<cngx-select>`, `<cngx-combobox>` and so on) bring their own search input; `<cngx-select-search>` is only for `<cngx-select-shell>`.

### Debugging the error

The message reads `CNGX2018: [cngx-select-search] must be placed inside <cngx-select-shell>.` In a production build the message is the bare code `CNGX2018`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A parent that another component renders in its own template, around content you project into it, is not above the projected element.
