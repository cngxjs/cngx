# CNGX2005

## cngxPasteTransform stacked on cngxInputMask

This warning is emitted when `[cngxPasteTransform]` is placed on an `<input>` that also carries `cngxInputMask`.

Both directives listen for `paste` on the same element and both cancel the native paste to insert the text themselves. `CngxPasteTransform` runs your function over the clipboard text, writes the result into `el.value` at the caret and dispatches an `input` event. `CngxInputMask` reads the untransformed clipboard text and inserts it character by character through its slot filter, updating its own `value` model. Neither knows about the other.

The result is pasted text applied twice through two uncoordinated paths: the field can show the text doubled, or a mix of the cleaned and the raw version, and the mask's raw value can disagree with what is on screen. Nothing throws.

```html
<!-- WARNING: two paste handlers on one masked input -->
<input cngxInputMask="iban" [cngxPasteTransform]="stripSpaces" />
```

### Fixing the warning

#### Option 1: Let the mask do the cleanup

Remove `cngxPasteTransform`. The mask already drops pasted characters that do not fit a slot, so separators and whitespace are filtered out without a paste transform. For per-character changes, such as upper-casing, use the mask's `[transform]` input, which runs on every accepted character, typed or pasted:

```html
<input cngxInputMask="iban" [transform]="toUpperCase" />
```

```ts
protected readonly toUpperCase = (char: string) => char.toUpperCase();
```

#### Option 2: Define the accepted characters with `customTokens`

When the cleanup is about which characters a position accepts, express it in the pattern. A custom token carries its own `pattern` and an optional `transform`; a character that is not a token, such as `#`, is a literal:

```html
<input
  cngxInputMask="#HHHHHH"
  [customTokens]="{ H: { pattern: /[0-9a-fA-F]/, transform: toUpperCase } }"
/>
```

Use `withCustomTokens` to register the same tokens app-wide.

### Debugging the warning

The message names no element; it starts with `CNGX2005: [cngxPasteTransform]: stacked on a cngxInputMask input`. Search your templates for inputs that carry both `cngxPasteTransform` and `cngxInputMask`, including inputs where one of them is applied through a host directive.

The check runs in development mode only, once per `CngxPasteTransform` instance, when it is created. It looks for a `CngxInputMask` on the same element only; a mask on a different input does not trigger it. `cngxPasteTransform` stays fine on plain `cngxInput` fields and on `<textarea>`.
