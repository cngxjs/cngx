# CNGX1069

## Empty or non-finite pitch domain

This warning is emitted when `[cngxAudioPitch]` from `@cngx/common/audio` gets a `[pitchDomain]` whose two ends are equal, such as `[5, 5]`, or whose ends are not both finite numbers, such as `[NaN, 100]`.

The directive maps a value onto `[pitchRange]` by its position inside the domain. A domain with no span has no positions, and neither has one with a `NaN` or infinite end: every value lands on the same point, so every tone plays the low end of `[pitchRange]`. The ear hears a constant pitch while the value moves, which is the opposite of what pitch mode is for. Nothing throws.

```html
<!-- WARNING: min and max come from the same signal, the domain is empty -->
<input type="range"
  [cngxAudioPitch]="level()"
  [pitchDomain]="[limit(), limit()]" />
```

An inverted domain is not an error: `[100, 0]` maps 100 to the low end of the range and 0 to the high end.

### Fixing the warning

Give the domain a non-zero span, the range the value actually moves through:

```html
<input type="range" min="0" max="100"
  [cngxAudioPitch]="level()"
  [pitchDomain]="[0, 100]" />
```

When the bounds are computed and can meet (a data range that collapses to one point) or come out as `NaN` (a parse of an empty field, a division by zero), widen or default them before binding, or set `[audioDisabled]` while they are equal.

### Debugging the warning

The message starts with `CNGX1069: [cngxAudioPitch] [pitchDomain] [` and names the domain and the frequency every value plays. Search the templates for `[pitchDomain]` bindings whose ends come from the same source.

The check runs in development mode only. `[pitchDomain]` is a live input, so it warns each time the domain changes into an empty or non-finite one; re-binding the same tuple stays silent, and a valid domain in between makes the next one warn again.
