# CNGX1029

## Duplicate tree node id

This error is reported when `createTreeController` gets the same id from `nodeIdFn` for two different nodes.

The controller keys everything by node id: the `expandedIds` set, the `isExpanded(id)` signals, `findById`, `parentOf` and the first-child lookup behind keyboard navigation. Two nodes with one id share one entry in each of them. Expanding one expands the other, and every id lookup returns only the node that came later in the tree; the earlier one is shadowed. The tree still renders, so the bug shows up as wrong expansion or focus jumping to the wrong node, not as a crash.

The most common cause is an id that is unique only among siblings:

```ts
// ERROR: two different "Settings" folders produce the id "settings"
const tree = createTreeController<Folder>({
  nodes: this.folders,
  nodeIdFn: (folder) => folder.slug,
});
```

### Fixing the error

#### Option 1: Use a key that is unique across the whole tree

Use the record's primary key:

```ts
const tree = createTreeController<Folder>({
  nodes: this.folders,
  nodeIdFn: (folder) => folder.id,
});
```

#### Option 2: Build the id from the path

If the records have no global key, combine the node with its ancestors. `nodeIdFn` receives the index path as its second argument, but an index path changes whenever the tree is sorted or filtered, so prefer the ancestors' own keys:

```ts
nodeIdFn: (folder) => `${folder.parentSlug}/${folder.slug}`,
```

The id has to stay the same across sorting and filtering; otherwise expansion state and focus are lost every time the order changes.

### Debugging the error

The message quotes the duplicate id. It starts with `CNGX1029: createTreeController(): duplicate node id` followed by the id. The controller reports each id once per controller, however often the tree re-derives, so one line means one id, not one occurrence. Search your data for records that produce that id.

`flattenTree` from `@cngx/utils` checks the same condition on its own and warns with [CNGX0901](cngx0901.html). The two codes fire together when a tree controller flattens a tree with duplicate ids; fix the id and both go away. A duplicate *selection* key (from `keyFn`) is a separate error, [CNGX1030](cngx1030.html).
