# CNGX1051

## Tree controller without a node id function

This error is thrown when `createTreeController()` from `@cngx/common/interactive` is called without a `nodeIdFn` and no app-wide default is configured.

The tree controller keys its state by node id: the expanded set (`expandedIds`), the `initiallyExpanded` list and the `byId` lookup that navigation and rendering go through. A tree has no natural key, and falling back to the node's position would make every id shift when a node is inserted or removed, so the expanded state would jump to a different node. The controller therefore needs an id function and throws when it has none.

The id function resolves in this order: `nodeIdFn` in the options, then `withDefaultNodeIdFn(...)` from the nearest `provideTreeConfig()` / `provideTreeConfigAt()`. There is no library default.

```typescript
// ERROR: no nodeIdFn and no provideTreeConfig(withDefaultNodeIdFn(...))
readonly tree = createTreeController<Folder>({ nodes: this.folders });
```

### Fixing the error

#### Option 1: Pass it per controller

Return a value that is stable for the node across data reloads, usually the record's own id:

```typescript
readonly tree = createTreeController<Folder>({
  nodes: this.folders,
  nodeIdFn: (folder) => folder.id,
});
```

The function also receives the node's path (`(value, path) => string`). Use the path only when the records have no id of their own and the tree never reorders.

#### Option 2: Configure an app-wide default

When every tree in the app shares the same record shape, set the default once:

```typescript
bootstrapApplication(AppComponent, {
  providers: [provideTreeConfig(withDefaultNodeIdFn<Folder>((folder) => folder.id))],
});
```

Use `provideTreeConfigAt(...)` in a component's `providers` to scope the default to one subtree.

### Debugging the error

In a production build the message is the bare code `CNGX1051`; the check still runs there, because a tree cannot be keyed without the function.

The controller reads the config once, when it is created, from the injection context it is created in. A `provideTreeConfigAt()` placed on a sibling or a child component is not visible to it. `<cngx-tree-select>` declares `[nodeIdFn]` as a required input, so a missing binding there fails at compile time instead of reaching this check.
