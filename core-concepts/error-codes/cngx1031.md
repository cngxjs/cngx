# CNGX1031

## Router not set up for a router-sync directive

This warning is emitted when one of the `@cngx/common` URL-sync surfaces runs in an app that has not set up the router, so there is no `ActivatedRoute` to inject:

- `[cngxStepperRouterSync]` (`CngxStepperRouterSync`) - the active step in `#step=<id>` or `?step=<id>`
- `[cngxTabsFragmentSync]` (`CngxTabsFragmentSync`) - the active tab in `#tab=<id>`
- `[cngxTabsRouteSync]` (`CngxTabsRouteSync`) - one route per tab
- `[cngxPaginateRouting]` (`CngxPaginateRouting`) - `?page` and `?pageSize`
- `injectQueryParamSync()` - a signal mirrored into one query parameter, used by `CngxSidenavRouterSync` in `@cngx/ui`

All of them inject `Router` and `ActivatedRoute` optionally, so that `@cngx/common` does not force `@angular/router` on apps that never route. `Router` is `providedIn: 'root'` and resolves even without `provideRouter(...)`, so the surfaces treat a missing `ActivatedRoute` as the sign that the router is not set up; `provideRouter(...)` and `RouterModule.forRoot(...)` supply it. Each one decides once, when it is created: with both it seeds its state from the URL and writes changes back; without them it skips all of that and the host keeps its own local state.

Nothing throws. The stepper, the tabs, the paginator and the sidenav keep working, but nothing reaches the URL: a reload drops the active step, tab, page or open state, a shared link does not restore it, and the browser's back button does not step through it. `CngxTabsRouteSync` selects tabs without navigating. The directive stays inactive for the lifetime of the host; providing a router later does not revive it.

```ts
// WARNING: no provideRouter(...), but a template uses <cngx-stepper cngxStepperRouterSync>
bootstrapApplication(AppComponent, {
  providers: [provideStepperConfig(withStepperRouterSync('queryParam', 'phase'))],
});
```

### Fixing the warning

#### Option 1: Provide the router

Register the router in the application config:

```ts
bootstrapApplication(AppComponent, {
  providers: [provideRouter(routes)],
});
```

`CngxTabsRouteSync` also needs a child route per tab, whose segment matches the tab id by default, and a `<router-outlet>` for the routed content; the fragment and query-parameter surfaces work with any route. In a unit test, add `provideRouter([])` to the `TestBed` providers when the component under test uses one of these directives.

#### Option 2: Drop the router-sync attribute

If the view is not routed, remove the attribute (`cngxStepperRouterSync`, `cngxTabsFragmentSync`, `cngxTabsRouteSync`, `cngxPaginateRouting`, or the sidenav's `cngxSidenavRouterSync`) or the `injectQueryParamSync()` call. The host component keeps its state locally, as it does without the directive.

### Debugging the warning

The message starts with `CNGX1031: ` and the surface (`[cngxStepperRouterSync]`, `[cngxTabsFragmentSync]`, `[cngxTabsRouteSync]`, `[cngxPaginateRouting]` or `injectQueryParamSync()`), followed by the same text for every surface and the feature it would enable, for example `CNGX1031: [cngxStepperRouterSync] no Router / ActivatedRoute available - the URL sync is a no-op. Provide @angular/router via provideRouter(...) to enable deep-linking.` A sidenav without a router reports `injectQueryParamSync`, because its router-sync directive delegates to it.

The check runs in development mode only, once per instance. The stepper and tab directives warn after the first render; the paginator directive and `injectQueryParamSync()` warn while they are created. It is not deduplicated: three paginators without a router print three lines. `injectQueryParamSync()` returns after the warning; it never reaches a required `ActivatedRoute` inject, so a missing router setup does not fail with `NG0201`.

The `@cngx/ui` router-sync directives (breadcrumb, breadcrumb siblings, TOC) report the same condition as [CNGX3001](cngx3001.html).
