# CNGX2030

## A field label without a control

This warning is emitted when a `cngx-form-field` renders a `cngxLabel` but discovers no control. The field finds its control through `CNGX_FORM_FIELD_CONTROL`, which `cngxInput`, the select family, the common form atoms and the field bridges provide. A plain `<input>` provides nothing, so the field gives it no id, the label has no `for` target, and a click on the label focuses nothing.

```html
<!-- WARNING: the input is not a field control. -->
<cngx-form-field [field]="f.email">
  <label cngxLabel>Email</label>
  <input type="email" />
</cngx-form-field>
```

### Fixing the warning

Mark the input as the field's control:

```html
<cngx-form-field [field]="f.email">
  <label cngxLabel>Email</label>
  <input cngxInput type="email" [formField]="f.email" />
</cngx-form-field>
```

For a third-party control, add `cngxBindField` (Material) or the matching field bridge (`cngxListboxFieldBridge`, `cngxSliderFieldBridge`, `cngxRangeSliderFieldBridge`).

### Debugging the warning

The message starts with `CNGX2030: [cngxLabel]` followed by the field name. The check runs once per label after its first render, in development mode only.
