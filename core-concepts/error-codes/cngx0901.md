# CNGX0901

## Duplicate node id in a tree

This warning is emitted when `flattenTree` from `@cngx/utils` gets the same id from its `idFn` for two nodes of one tree. Everything that flattens through it can trigger it: `createTreeController` (`nodeIdFn`), `<cngx-tree-select>` (`[nodeIdFn]`) and `<cngx-treetable>` (`[nodeId]`).

`flattenTree` turns the tree into a flat list in depth-first order. Each flat node stores its own `id` and the ids of all its ancestors in `parentIds`; `isNodeVisible` decides whether a row shows by checking every id in that chain against the expanded set. Ids therefore have to be unique across the whole forest, not only among siblings.

With a duplicate, two unrelated branches share one entry in the expanded set and in every id lookup. Expanding one folder also reveals the children of the other, and selection and focus land on the wrong node. The tree still renders, so nothing crashes. The most common cause is an id that is unique only among siblings:

```html
<!-- WARNING: two different "Settings" folders produce the id "settings" -->
<cngx-treetable [tree]="folders" [nodeId]="bySlug" />
```

```ts
protected readonly bySlug = (folder: Folder) => folder.slug;
```

### Fixing the warning

#### Option 1: Use a key that is unique across the whole tree

Use the record's primary key:

```ts
protected readonly byId = (folder: Folder) => folder.id;
```

#### Option 2: Build the id from the ancestors

If the records have no global key, combine the node's key with the keys of all its ancestors, from the root down. The immediate parent alone is not enough: two "Settings" folders under two "Admin" folders still collide. Add the chain when you map the response, for example as a `slugPath` array, and join it:

```ts
protected readonly byPath = (folder: Folder) => folder.slugPath.join('/');
```

The id function also receives the index path as its second argument, but an index path changes whenever the tree is sorted or filtered, which drops expansion and selection state.

`flattenTree` called without an id function, and `<cngx-treetable>` without `[nodeId]`, fall back to the index path (`0.1.2`; the treetable joins with `-`), which is always unique, so they never warn. `createTreeController` and `<cngx-tree-select>` have no such fallback: their id function is required, so for them the id function is always yours to fix.

### Debugging the warning

The message quotes the duplicate id, for example `flattenTree: duplicate node id "settings"`. Search your data for the records that produce it.

The check runs in development mode only, during each flatten. It is not deduplicated across calls: every later occurrence of an id already seen in the same pass logs a line, and the tree is flattened again whenever its input changes, so one bad id can log repeatedly.

When the tree comes from `createTreeController` (including `<cngx-tree-select>`), the controller checks the same condition itself and reports it as the error [CNGX1029](cngx1029.html), once per id. The two fire together; fix the id and both go away. A duplicate selection key from `keyFn` is [CNGX1030](cngx1030.html).
