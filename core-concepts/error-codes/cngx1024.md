# CNGX1024

## Submenu directive without a menu item

This warning is emitted when `[cngxMenuItemSubmenu]` sits on an element that does not also carry `[cngxMenuItem]`.

`CngxMenuItemSubmenu` is a companion, not a menu item of its own. It adds `aria-haspopup="menu"` and `aria-expanded` and registers itself with the surrounding `CngxMenu` as a submenu source, but `role="menuitem"` and the highlight state belong to `CngxMenuItem`. When the menu receives ArrowRight or an activation key, it looks up the active item's id among its registered submenus. That id comes from `CngxMenuItem`, and the submenu directive mirrors it only when the menu item is on the same element.

Without the sibling, the submenu falls back to its own generated id, and the menu's active-descendant navigation never highlights the element because it is not a menu item. The parent row renders and looks right, but keyboard users cannot highlight it, and ArrowRight never opens its submenu.

```html
<ul cngxMenu [label]="fileMenuLabel()">
  <!-- WARNING: no cngxMenuItem on the submenu row -->
  <li [cngxMenuItemSubmenu]="recentPop" [submenuMenu]="recentMenu">
    {{ openRecentLabel() }}
  </li>
</ul>
```

### Fixing the warning

#### Option 1: Put both directives on the same element

```html
<ul cngxMenu [label]="fileMenuLabel()">
  <li cngxMenuItem value="recent" [cngxMenuItemSubmenu]="recentPop" [submenuMenu]="recentMenu">
    {{ openRecentLabel() }}
  </li>
</ul>
```

Labels are user-facing copy; route them through your own i18n.

#### Option 2: Use the context menu item component

`<cngx-context-menu-item>` from `@cngx/ui/context-menu` composes `CngxMenuItem` and `CngxMenuItemSubmenu` as host directives and wires the popover for you. Bind `[submenu]` to a sibling `<cngx-context-menu>`.

### Debugging the warning

The message starts with `[cngxMenuItemSubmenu] applied without a sibling [cngxMenuItem] on the same host element` and does not name the element. Search for `cngxMenuItemSubmenu` and check that the same element has `cngxMenuItem`; a `cngxMenuItem` on a parent or child element does not count.

The check runs in development mode only, once per submenu directive, after the first render. If the submenu also has no popover or menu bound, [CNGX1025](cngx1025.html) is logged as well.
