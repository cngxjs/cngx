# CNGX1072

## Button group without an accessible name

This warning is emitted when an element with `cngxButtonGroup` from `@cngx/common/button` renders without an `aria-label` or an `aria-labelledby` on the host.

The directive sets `role="group"` on its host. A screen reader announces a group when focus enters it, and the group's name is what tells the user which buttons belong together: "History, group" before "Undo", "Text style, group" before "Bold". Without a name the user hears "group" and nothing else, or the group is skipped, and a row of "Left", "Center", "Right" loses its context (WCAG 1.3.1 Info and Relationships, WCAG 4.1.2 Name, Role, Value). Sighted users see the frame and never notice. Nothing throws.

```html
<!-- WARNING: role="group" without a name -->
<div cngxButtonGroup variant="outline">
  <button cngxButton>Undo</button>
  <button cngxButton>Redo</button>
</div>
```

### Fixing the warning

Name what the buttons do together, on the host:

```html
<div cngxButtonGroup variant="outline" aria-label="History">
  <button cngxButton>Undo</button>
  <button cngxButton>Redo</button>
</div>
```

The name is your copy, so route it through your own translations. Use `aria-labelledby` when a visible heading or label already names the group. In a toolbar built from nested groups, every sub-group needs its own name ("Text style", "Alignment"), and the outer group needs one too.

### Debugging the warning

The message starts with `CNGX1072: [cngxButtonGroup] has no accessible name.` and passes the host element as context, so the console links straight to the group. The check runs once after the first render, so a name bound later through `[attr.aria-label]` still counts if it is set by then. A whitespace-only value counts as no name.

The check runs in development mode only. In production the group renders the same, without a warning.
