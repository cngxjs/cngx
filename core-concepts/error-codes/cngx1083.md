# CNGX1083

## Dot nav badge without a label

This warning is emitted when a `CngxNavBadge` from `@cngx/common/interactive` renders a visible dot (`variant="dot"` with a non-empty `value`) and has no `ariaLabel`.

The badge host is always `aria-hidden="true"`, so the dot itself never reaches the accessibility tree. Its only way into the link name is `ariaLabel`, which the badge renders as visually hidden text right after itself, inside the link. Without it, a sighted user sees that something is new and a screen reader user hears only the link text. Nothing throws.

```html
<!-- WARNING: the dot means nothing to assistive technology -->
<a cngxNavLink href="/updates">
  Updates
  <span cngxNavBadge variant="dot" [value]="1"></span>
</a>
```

### Fixing the warning

Set `ariaLabel` to what the dot means. It is read as part of the link name ("Updates New updates").

```html
<a cngxNavLink href="/updates">
  Updates
  <span cngxNavBadge variant="dot" [value]="1" ariaLabel="New updates"></span>
</a>
```

When the dot carries no information the link text does not already give, drop the dot instead of labelling it.

### Debugging the warning

The message starts with `CNGX1083: [cngxNavBadge] a dot badge without ariaLabel adds nothing to the link name`. The context argument is the badge host element.

The check runs once per badge in development mode only, after its first render. An empty dot (`value` of `0`, `''`, `null` or `undefined`) and a count or status badge do not warn. In production the dot renders the same way, without a warning.
