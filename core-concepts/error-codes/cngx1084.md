# CNGX1084

## Error state on a form-field control

This warning is emitted when a `[cngxErrorState]` from `@cngx/common/interactive` sits on an element that also provides `CNGX_FORM_FIELD_CONTROL`, for example an `<input cngxInput>` inside a `cngx-form-field`.

Both directives bind `aria-invalid` and `aria-errormessage` on the same host. Only one binding wins, so the attributes can contradict the error state the form field shows: `aria-invalid="true"` on a pristine, valid field, or the reverse. The `cngx-error` class can disagree with the field's own error styling in the same way. Nothing throws.

```html
<cngx-form-field [field]="email">
  <!-- WARNING: cngxInput already reports the error state of the field -->
  <input cngxInput [cngxErrorState]="emailInvalid()" cngxErrorMessageId="email-error" />
</cngx-form-field>
```

### Fixing the warning

Remove `[cngxErrorState]` from the control. The control reports its error state to `cngx-form-field`, which owns the ARIA wiring and the error message.

```html
<cngx-form-field [field]="email">
  <input cngxInput />
</cngx-form-field>
```

Keep `[cngxErrorState]` for hosts that are not form-field controls: a custom widget, a third-party input, a card or a fieldset.

### Debugging the warning

The message starts with `CNGX1084: [cngxErrorState] shares its host with a form-field control`. The context argument is the host element.

The check runs once per directive instance in development mode only, at construction. It looks at the host element only; a control on an ancestor does not warn. In production nothing is checked.
