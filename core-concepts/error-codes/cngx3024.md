# CNGX3024

## Breadcrumb overflow menu outside a breadcrumb

This error is thrown when `<cngx-breadcrumb-overflow>` from `@cngx/ui/breadcrumb` is created without a breadcrumb above it.

The overflow component is the ellipsis menu that lists the crumbs a breadcrumb trail has collapsed. It holds no crumbs of its own: the collapse set comes from the surrounding `[cngxBreadcrumb]`, which counts the items and applies `[maxVisible]`. Without it the menu has nothing to list, so the constructor throws instead of rendering a trigger that never opens anything.

```html
<!-- ERROR: no breadcrumb above the overflow menu -->
<ol>
  <li><a cngxBreadcrumbItem href="/">Home</a></li>
  <li><cngx-breadcrumb-overflow /></li>
</ol>
```

### Fixing the error

#### Option 1: Put the menu inside a hand-built breadcrumb

```html
<nav cngxBreadcrumb aria-label="Breadcrumb" [maxVisible]="4">
  <ol>
    <li><a cngxBreadcrumbItem href="/">Home</a></li>
    <li><cngx-breadcrumb-overflow /></li>
    <li><a cngxBreadcrumbItem>Settings</a></li>
  </ol>
</nav>
```

#### Option 2: Use the breadcrumb bar

`<cngx-breadcrumb>` renders its own overflow menu when crumbs collapse; you do not place `<cngx-breadcrumb-overflow>` inside it. Project `*cngxBreadcrumbOverflowItem` into the bar to customise the menu rows.

### Debugging the error

The message reads `CNGX3024: [cngx-breadcrumb-overflow] must be placed inside an element with [cngxBreadcrumb].` In a production build the message is the bare code `CNGX3024`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A parent that another component renders in its own template, around content you project into it, is not above the projected element.
