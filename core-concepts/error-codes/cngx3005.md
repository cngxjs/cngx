# CNGX3005

## Mat-tabs decoration retry ceiling reached

This warning is emitted when `[cngxMatTabs]` on a `<mat-tab-group>` needs to decorate a Material tab button and the button is still missing after 5 retries. Two decorations can hit the ceiling: the rejection decoration (a refused tab switch, from a commit action) and the aggregator decoration (a tab whose panel reports errors, for example through `[cngxMatTabErrorFlag]`).

Material owns the tab header DOM, and cngx tab ids never reach it. The decorations therefore find a button by position: they query `.mat-mdc-tab` elements inside the host and take the one at the tab's index, then add a class, a visually hidden descriptor span and an `aria-describedby` reference. When the decoration effect runs before Material has stamped the buttons, the lookup misses and the projector schedules one retry per application render (`afterNextRender`), up to 5 attempts. After the fifth miss it stops and warns.

The decorated state is the only signal for that tab: the error class is not applied and the descriptor that tells a screen reader why the tab is flagged is not attached. The tab group itself keeps working. The decoration is attempted again on the next change of the error or rejection state.

```html
<!-- WARNING: no rendered .mat-mdc-tab button matches the flagged tab's index -->
<mat-tab-group cngxMatTabs>
  <mat-tab [label]="profileLabel()" [cngxMatTabErrorFlag]="profileInvalid()">...</mat-tab>
</mat-tab-group>
```

The template above is correct. It warns when the buttons Material renders do not carry `.mat-mdc-tab` (a Material version with different markup, or a stub in a test), or when rendering stalls so that five render passes go by without the buttons appearing.

### Fixing the warning

#### Option 1: Check the Material markup

Inspect the rendered tab buttons in the browser's element panel. If they no longer carry the `.mat-mdc-tab` class, the decoration cannot find them; report it as a cngx bug with the `@angular/material` version. In unit tests, render the real `MatTabsModule` components rather than stubs when the test asserts on decorations.

### Debugging the warning

The message names the decoration (`aggregator` or `rejection`) and the attempt count (`5`). For the aggregator it starts with `CNGX3005: [cngxMatTabs] aggregator decoration retry ceiling reached (5 attempts) - MatTabHeader did not render`. The ceiling is fixed for the decorations; `withAnchorRetryAttempts` configures a different loop, the overflow anchor described in [CNGX3007](cngx3007.html).

The check runs in development mode only. The retry counter resets after a successful decoration and after the warning, so a state that keeps changing while the buttons stay missing can warn repeatedly. The lookup counts `.mat-mdc-tab` elements under the `<mat-tab-group>` host and matches them by index to the `<mat-tab>` children in query order. If the warning appears although the tabs are visible, compare the number of rendered `.mat-mdc-tab` buttons with the number of `<mat-tab>` children; a custom header or a Material change that renders fewer buttons leaves the later tabs undecorated.
