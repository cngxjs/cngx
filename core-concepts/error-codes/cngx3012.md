# CNGX3012

## Tab overflow could not find the tab strip

This warning is emitted when `<cngx-tab-overflow>` cannot locate the tab strip it should observe, after 60 attempts.

The overflow lists the tabs that are clipped out of the strip. It does that with an `IntersectionObserver` whose root is the strip's scroll viewport, observing each tab button. It finds the strip through a DOM adapter: for `<cngx-tab-group>` the default adapter walks up from the overflow element to `.cngx-tabs__strip-wrapper` and takes its `.cngx-tabs__strip`; under `[cngxMatTabs]` the Material adapter walks up to `.mat-mdc-tab-header`. `<cngx-tab-group>` places the overflow inside the strip wrapper through a dedicated `<ng-content select="cngx-tab-overflow">` slot, which only matches the element when it is a direct child of the group. The lookup starts after the first render and repeats once per animation frame.

When all 60 attempts fail, no observer is attached. The "More" button reports no hidden tabs, so tabs that are scrolled out of view are reachable only by scrolling the strip or with the arrow keys, not through the menu.

```html
<cngx-tab-group [attr.aria-label]="sectionsLabel()">
  <!-- WARNING: the wrapper keeps the overflow out of the strip slot -->
  <div class="toolbar">
    <cngx-tab-overflow />
  </div>
  <div cngxTab [label]="overviewLabel()">...</div>
</cngx-tab-group>
```

### Fixing the warning

#### Option 1: Make the overflow a direct child of the tab group

Put `<cngx-tab-overflow>` directly inside `<cngx-tab-group>`, without a wrapping element, so the strip slot picks it up:

```html
<cngx-tab-group [attr.aria-label]="sectionsLabel()">
  <cngx-tab-overflow />
  <div cngxTab [label]="overviewLabel()">...</div>
</cngx-tab-group>
```

With Material tabs, do not add `<cngx-tab-overflow>` yourself; `[cngxMatTabs]` creates and places it.

#### Option 2: Provide a DOM adapter for a custom strip

If you render the tab strip with your own markup (an ejected skin, a custom host), the default class lookup cannot match it. Provide an adapter through `CNGX_TAB_OVERFLOW_DOM_ADAPTER_FACTORY` whose `resolveStripRoot` returns your strip element and whose `resolveTabButton` returns each tab's button.

### Debugging the warning

The message starts with `CNGX3012: [cngx-tab-overflow]` and names the attempt count, 60. The lookup goes up from the `<cngx-tab-overflow>` element with `closest()`, so the strip wrapper must be one of its ancestors in the rendered DOM; inspect the element and check its parent chain.

The check runs in development mode only, once per overflow instance. The 60 attempts are animation frames, roughly one second in a visible tab; in a background browser tab, frames are paused and the countdown waits. The loop is not restarted when a hidden strip becomes visible again; the overflow has to be destroyed and recreated.

An overflow placed outside any tab group never reaches this check: it fails earlier with a DI error for `CNGX_TAB_PANEL_HOST`. Under `[cngxMatTabs]`, this warning usually follows [CNGX3007](cngx3007.html), where the overflow could not be moved into the Material header in the first place.
