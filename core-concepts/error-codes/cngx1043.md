# CNGX1043

## Focusable content in a timeline opposite slot

This warning is emitted when the `[cngxTimelineOpposite]` slot of a `<cngx-timeline-item>` contains a focusable element: a link, a button, a form field, a `<summary>`, or anything with `tabindex` or `contenteditable`.

The opposite slot is for a short label on the far side of the rail, typically a year or a time. It is projected ahead of the row body in the DOM, so it is read first in every layout, which is the right reading order for a label. The visual side, however, follows the timeline's `placement`: under `placement="end"` or `"alternate"` the slot paints on the opposite side of the rail from the body.

An interactive element in the slot therefore takes keyboard focus before the row it belongs to, while it is painted somewhere else. A keyboard user tabs into a link on the far side of the rail before reaching the entry it belongs to, and the focus order no longer follows what the eye reads (WCAG 2.4.3 Focus Order). No placement can fix that, because the paint follows the layout while the DOM order does not.

```html
<!-- WARNING: a link in the opposite slot -->
<cngx-timeline-item status="done">
  <span cngxTimelineOpposite><a href="/releases/2019">2019</a></span>
  <p>Founded</p>
</cngx-timeline-item>
```

### Fixing the warning

Keep the opposite content plain text and put controls in the body:

```html
<cngx-timeline-item status="done">
  <span cngxTimelineOpposite>2019</span>
  <p>Founded. <a href="/releases/2019">Read the 2019 release notes</a></p>
</cngx-timeline-item>
```

### Debugging the warning

The message starts with `CNGX1043: [cngx-timeline-item] focusable content inside [cngxTimelineOpposite]`. The second console argument is the `<cngx-timeline-item>` element; hover it in the console to highlight the row on the page.

The check runs in development mode only, once per row, after the first render, and looks at every direct `[cngxTimelineOpposite]` child of the item: the slot element itself (an `<a cngxTimelineOpposite>`) and its descendants. Content that becomes focusable later (a link rendered after data loads) is not reported. An element with `tabindex="-1"` matches the check too, although it is not in the tab order; remove the `tabindex` or move the element to the body.
