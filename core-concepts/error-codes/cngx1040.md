# CNGX1040

## Commit controller ignored the settle option

This warning is emitted when a stepper cancels an in-flight commit with `cancel({ settle: true })` and the commit state is still `pending` afterwards. That only happens with a custom `CNGX_COMMIT_CONTROLLER_FACTORY` override whose `cancel()` does not honour the `settle` option.

A stepper with a `[commitAction]` runs it through a commit controller before it moves to the next step; while it runs, the commit state is `pending` and the stepper is `busy()`. When the user steps back (`selectPrevious()`) or the stepper is reset (`reset()`) during a commit, the stepper supersedes that commit and calls `cancel({ settle: true })`, which must cancel the runner and return the state to `idle`. Without `settle`, `cancel()` keeps the current status, which is right when the host is destroyed and wrong when it lives on.

If the custom controller ignores `settle`, the state stays `pending` after the back-move. `busy()` latches `true`: the Next button stays disabled, the step stays marked busy, and nothing clears it until another commit completes.

```ts
// WARNING: cancel() drops the options
{
  provide: CNGX_COMMIT_CONTROLLER_FACTORY,
  useValue: <T>() => {
    const inner = createCommitController<T>();
    return { ...inner, cancel: () => inner.cancel() };
  },
}
```

### Fixing the warning

Forward the options, and when `settle` is `true`, set the state back to `idle` after cancelling the runner:

```ts
{
  provide: CNGX_COMMIT_CONTROLLER_FACTORY,
  useValue: <T>() => {
    const inner = createCommitController<T>();
    return { ...inner, cancel: (options) => inner.cancel(options) };
  },
}
```

A controller that wraps `createCommitController` gets the settle behaviour by forwarding the argument. A controller written from scratch has to implement it: cancel the active runner, drop its late callbacks, and with `settle: true` move `state` to `idle`.

### Debugging the warning

The message starts with `[cngxStepper] the commit controller ignored cancel({ settle: true })`. Find the `CNGX_COMMIT_CONTROLLER_FACTORY` provider in your application; the default controller never triggers this warning.

The check runs in development mode only, right after the stepper cancels a pending commit, which is on `selectPrevious()` and `reset()` while `busy()` is `true`. It reads the commit state once, synchronously after `cancel()`, so a controller that settles asynchronously (in a microtask or a timer) is reported too, even if it settles a moment later; settle synchronously.
