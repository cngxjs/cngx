# CNGX3023

## Tab overflow outside a tab group

This error is thrown when `<cngx-tab-overflow>` from `@cngx/ui/tabs` is created without a tab group above it.

The overflow component adds a "More" button to a tab strip that is too narrow for all its tabs. It holds no tabs of its own: it reads the tab list and the active tab from the surrounding tab group, watches which tab buttons are clipped by the strip, lists those in its popover and selects the chosen tab through the group. `<cngx-tab-group>` and `[cngxMatTabs]` on a `<mat-tab-group>` provide that group. Without one there are no tabs to list, so the constructor throws instead of rendering a button that opens an empty menu.

```html
<!-- ERROR: the overflow sits next to the tab group, not inside it -->
<cngx-tab-group aria-label="Reports">...</cngx-tab-group>
<cngx-tab-overflow />
```

### Fixing the error

Project it into the tab group:

```html
<cngx-tab-group aria-label="Reports">
  <div cngxTab label="Summary">...</div>
  <div cngxTab label="Details">...</div>
  <cngx-tab-overflow />
</cngx-tab-group>
```

With `[cngxMatTabs]` you do not place it yourself: the directive mounts the overflow on the Material tab header.

### Debugging the error

The message reads `CNGX3023: [cngx-tab-overflow] must be placed inside <cngx-tab-group> or <mat-tab-group cngxMatTabs>.` In a production build the message is the bare code `CNGX3023`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A parent that another component renders in its own template, around content you project into it, is not above the projected element.
