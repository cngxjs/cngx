# CNGX3020

## Tab error directive outside a cngxMatTabs group

This error is thrown when `[cngxMatTabError]` or `[cngxMatTabErrorFlag]` from `@cngx/ui/mat-tabs` is created somewhere other than on a `<mat-tab>` inside a `<mat-tab-group cngxMatTabs>`.

Both directives mark one Material tab as invalid. They do not decorate anything themselves: they look up the `<mat-tab>` they sit on in the registry that `[cngxMatTabs]` keeps for its group, and write the error into that tab's entry. The `cngxMatTabs` group then draws the badge on the tab button and wires the screen-reader description. Two things are needed for that: the directive must sit on the `<mat-tab>` element itself, and the group around it must carry `cngxMatTabs`. Without either, the error would go nowhere, so the constructor throws instead of marking a tab that never shows it.

```html
<!-- ERROR: the group has no cngxMatTabs, so no registry receives the flag -->
<mat-tab-group>
  <mat-tab label="Address" [cngxMatTabErrorFlag]="addressInvalid()">...</mat-tab>
</mat-tab-group>
```

### Fixing the error

Add `cngxMatTabs` to the group and put the directive on the `<mat-tab>` element:

```html
<mat-tab-group cngxMatTabs>
  <mat-tab label="Address" [cngxMatTabErrorFlag]="addressInvalid()">...</mat-tab>
</mat-tab-group>
```

A directive on an element inside the tab's content (a form, a `<div>` in the tab body) also throws: move it up to the `<mat-tab>`.

### Debugging the error

The message names the directive, for example `CNGX3020: [cngxMatTabErrorFlag] must be placed on a <mat-tab> inside <mat-tab-group cngxMatTabs>.` In a production build the message is the bare code `CNGX3020`; the check still runs there.

The check runs once, in the constructor. The group is looked up only within the template the `<mat-tab>` is declared in, so a `<mat-tab>` passed as content to a wrapper component whose own template contains the `<mat-tab-group cngxMatTabs>` does not find it. Declare the group and its tabs in the same template.
