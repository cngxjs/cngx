# CNGX2026

## Tree select compareWith set without keyFn

This warning is raised in development mode when a `cngx-tree-select` gets a custom `[compareWith]` but no `[keyFn]`.

`CngxTreeSelect` keeps one identity for its values. The selection controller, the tree index behind `findByValue`, the chips, the counts and the row `aria-checked` state all key a value by `keyFn`. Without a `keyFn` that key is the value itself, so two object instances that describe the same node are two different members. A comparator cannot become a key: `compareWith` only answers "are these two equal", it cannot index a set.

With object values that arrive as fresh instances, for example a selection loaded from the server, the result is a control that disagrees with itself. The rows render unchecked because the controller misses the new instances, the chips fall back to `String(value)` because the tree index misses them, while `compareWith` would have matched them by id.

```html
<!-- WARNING: compareWith matches by id, the selection keys by reference -->
<cngx-tree-select
  [nodes]="nodes"
  [nodeIdFn]="idOf"
  [compareWith]="sameId"
  [(values)]="selected"
/>
```

### Fixing the warning

Pass a `[keyFn]` that returns the domain id. It drives every identity check of the tree select, so `[compareWith]` is no longer needed:

```html
<cngx-tree-select
  [nodes]="nodes"
  [nodeIdFn]="idOf"
  [keyFn]="idOf"
  [(values)]="selected"
/>
```

```ts
readonly idOf = (row: Row): string => row.id;
```

Primitive values (strings, numbers) need neither input: the default reference comparison already matches them.

### Debugging the warning

The message starts with `CNGX2026: [cngx-tree-select] [compareWith] is set without [keyFn]`. It is written once per instance, after the first render, and only in development mode; production builds drop the check.

Search your templates for the `cngx-tree-select` that binds `[compareWith]` and add the matching `[keyFn]`. A `[compareWith]` bound to `Object.is` does not warn, because it is the reference comparison the selection uses anyway.
