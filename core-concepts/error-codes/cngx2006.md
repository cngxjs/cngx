# CNGX2006

## Input bound through DefaultValueAccessor

This warning is emitted when an `<input>` with `cngxNumericInput`, `cngxInputFormat` or `cngxInputMask` gets an Angular forms directive (`[formControl]`, `formControlName` or `[ngModel]`), but Angular's `DefaultValueAccessor` became its value accessor instead of `CngxFormBridge`.

These directives keep two values apart: the display text in the element (`1,430.00`, `(555) 123-4567`) and the parsed value in their `value` model (`1430`, `'5551234567'`). `CngxFormBridge`, the one `ControlValueAccessor` in cngx, connects the form control to that model through `CNGX_CONTROL_VALUE`. It attaches by selector, for example `input[cngxNumericInput][formControl]`, but only when the component that renders the input imports it. Without it, Angular falls back to `DefaultValueAccessor`, which reads and writes the element's raw text.

Nothing throws, but the form holds the wrong value. A numeric input sends display strings instead of numbers, a formatted input switches between raw and formatted text on focus and blur, and a masked input's typed text never reaches the control.

```ts
@Component({
  imports: [ReactiveFormsModule, CngxNumericInput],
  template: `
    <!-- WARNING: CngxFormBridge is not imported, DefaultValueAccessor takes over -->
    <input cngxNumericInput [decimals]="2" [formControl]="amount" />
  `,
})
export class PriceForm {
  readonly amount = new FormControl<number | null>(null);
}
```

### Fixing the warning

#### Option 1: Import `CngxFormBridge` for Reactive Forms

Add the bridge to the component's `imports`. It attaches by selector, so the template does not change:

```ts
import { CngxFormBridge } from '@cngx/forms/controls';

@Component({
  imports: [ReactiveFormsModule, CngxNumericInput, CngxFormBridge],
  template: `<input cngxNumericInput [decimals]="2" [formControl]="amount" />`,
})
```

Angular prefers a custom accessor over `DefaultValueAccessor`, so with the bridge in scope the control holds the parsed value: `number | null` for `cngxNumericInput`, the raw unmasked string for `cngxInputMask`, the unformatted value for `cngxInputFormat`. `setValue` expects that same parsed value.

#### Option 2: Use Signal Forms or the `value` model

`[ngModel]` is not covered by the bridge. Bind the directive's `value` model with `[(value)]`, or use Signal Forms with `[formField]`, which binds the directive directly without an accessor:

```html
<input cngxNumericInput [decimals]="2" [(value)]="amount" />
<input cngxNumericInput [decimals]="2" [formField]="f.amount" />
```

### Debugging the warning

The message starts with `CNGX2006: ` and the directive's selector in brackets, `[cngxNumericInput]`, `[cngxInputFormat]` or `[cngxInputMask]`, and names the symptom for that directive. For `[cngxInputMask]` it starts with `CNGX2006: [cngxInputMask] This masked input uses Angular's DefaultValueAccessor, so typed text never reaches the form control.` It does not identify the element; search the templates for that directive combined with `formControl`, `formControlName` or `ngModel`, and check each rendering component's `imports`.

The check runs in development mode only, once per directive instance, after its first render, because the accessor is resolved lazily. It only looks at the `NgControl` on the same element and only reports when its accessor is exactly `DefaultValueAccessor`; inputs without a forms directive are never checked. For a third-party control that implements its own `ControlValueAccessor` and needs to sit inside `<cngx-form-field>`, use `[cngxBindField]` instead.
