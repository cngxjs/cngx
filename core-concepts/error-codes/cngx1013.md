# CNGX1013

## Recycler scroll element not found on first render

This warning is emitted when the `scrollElement` passed to `injectRecycler` is a CSS selector and no element matches it after the first render.

`injectRecycler` usually runs in a field initializer, before the template exists, so the recycler resolves its scroll container lazily. It tries inside an effect, retries once after the next render, and, for a string selector, then starts a `MutationObserver` on the whole document that attaches the recycler as soon as a matching element appears. That covers containers that mount late on purpose: a list behind an `@if` waiting for data, or a skeleton that is swapped for content.

Until the element is found, the recycler has no scroll position and no viewport height, so it renders no real window and the list stays empty or shows placeholders only. If the selector never matches, it stays that way, and the observer keeps watching the document until the recycler is destroyed:

```ts
// WARNING: the template uses class="results-scroll", not ".result-scroll"
readonly recycler = injectRecycler({
  scrollElement: '.result-scroll',
  totalCount: () => this.results().length,
  estimateSize: 48,
});
```

### Fixing the warning

#### Option 1: Do nothing if the container mounts later on purpose

If the scroll container is rendered after data arrives, the warning is expected; the recycler attaches when the element appears. Confirm the list fills in once the container is in the DOM.

#### Option 2: Correct the selector

Check the selector against the rendered DOM. The selector is resolved with `document.querySelector`, so it is global: with two instances of the same component on one page, both recyclers attach to the first matching element. Give the container a selector that is unique on the page, or use Option 3.

#### Option 3: Pass the element instead of a selector

When the component's own host element is the scroll container, pass it directly:

```ts
private readonly host = inject<ElementRef<HTMLElement>>(ElementRef);

readonly recycler = injectRecycler({
  scrollElement: this.host.nativeElement,
  totalCount: () => this.results().length,
  estimateSize: 48,
});
```

An `HTMLElement` or `ElementRef` never triggers this warning and is not affected by other instances on the page.

### Debugging the warning

The message quotes the selector, for example `recycler scrollElement '.result-scroll' not found on first render`. Search the rendered DOM for it with `document.querySelectorAll` in the browser console; zero matches means a wrong selector, more than one means instances share a container.

The check runs in development mode only, once per recycler, after the first render, and only for string selectors. An `ElementRef` whose `nativeElement` is still `null` gets one silent retry after the next render and no warning; if it is still `null` then, the recycler never attaches.
