# CNGX1049

## Ordinal scale with an empty palette

This error is thrown when `createOrdinalScale(domain, colors)` from `@cngx/common/chart` is called with an empty `colors` array.

The ordinal scale maps each domain value to a palette entry and cycles the palette when the domain is longer (`colors[i % colors.length]`). An unknown value falls back to the first entry. With no entries there is nothing to map to and no fallback, so every lookup would return `undefined` and the series would render without a fill. The factory throws at construction time instead, before any series reads from it.

```typescript
// ERROR: the palette is empty
const color = createOrdinalScale(['north', 'south'], []);
```

### Fixing the error

Pass at least one color. A palette shorter than the domain is fine; it repeats:

```typescript
const color = createOrdinalScale(['north', 'south', 'east'], ['#2563eb', '#16a34a']);
```

When the palette comes from configuration or an API, guard the empty case where you load it and fall back to a default palette, rather than letting the scale receive `[]`.

### Debugging the error

The message reads `CNGX1049: createOrdinalScale(): colors palette must not be empty`. In a production build the message is the bare code `CNGX1049`; the check still runs there, because the scale cannot work without a color.

The check runs once, when the scale is created, and the stack trace points at the `createOrdinalScale` call. A palette that is empty only sometimes usually comes from a `computed()` over async data whose first value is `[]`: the scale is created before the colors arrive. Create the scale inside the same `computed()` and only once the palette is non-empty.
