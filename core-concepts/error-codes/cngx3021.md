# CNGX3021

## Router sync outside its sidenav or table of contents

This error is thrown when `[cngxSidenavRouterSync]` from `@cngx/ui/sidenav` is created without a `<cngx-sidenav>`, or `[cngxTocRouterSync]` from `@cngx/ui/toc` without a `<cngx-toc>`, on its element or above it in the same template.

Both directives deep-link a component's state into the URL: the sidenav sync keeps its open state in a query parameter (`?nav=open`), the table-of-contents sync writes the active section into the fragment (`#pricing`) and scrolls to it on load. Neither has state of its own. They read and drive the component they sit on, so without that component they have nothing to sync, and the constructor throws instead of leaving a URL that never changes.

```html
<!-- ERROR: the sync sits on the layout, not on the sidenav -->
<cngx-sidenav-layout cngxSidenavRouterSync>
  <cngx-sidenav position="start">Navigation</cngx-sidenav>
  <cngx-sidenav-content>...</cngx-sidenav-content>
</cngx-sidenav-layout>
```

### Fixing the error

Put the directive on the component it syncs:

```html
<cngx-sidenav position="start" cngxSidenavRouterSync>Navigation</cngx-sidenav>
```

```html
<cngx-toc [items]="sections" cngxTocRouterSync />
```

### Debugging the error

The message names the directive and the component it needs, for example `CNGX3021: [cngxSidenavRouterSync] must be placed on or inside <cngx-sidenav>.` In a production build the message is the bare code `CNGX3021`; the check still runs there.

The check runs once, in the constructor. It looks at the directive's own element and its ancestors within the template it is declared in, so a sidenav or table of contents on a child element does not count, and neither does one rendered by another component around content you pass in. A missing `Router` is a different case: it is reported as the warning [CNGX3001](cngx3001.html) or [CNGX1031](cngx1031.html), and the directive becomes a no-op.
