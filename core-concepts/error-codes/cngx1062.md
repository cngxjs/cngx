# CNGX1062

## Slider thumb outside a range track

This error is thrown when `[cngxSliderThumb]` from `@cngx/common/interactive` is created without a range track above it.

A thumb drives one end of a two-thumb range slider. It holds no value of its own: it reads the shared minimum, maximum, step and the current range from the surrounding `[cngxRangeSliderTrack]`, keeps its end between the bounds the other thumb sets, and writes changes back to the track. `<cngx-range-slider>` carries the track and renders both thumbs for you. Without a track the thumb has no value to show or change, so the constructor throws instead of rendering a slider that ignores input.

```html
<!-- ERROR: no range track above the thumbs -->
<div class="price-range">
  <span cngxSliderThumb="start"></span>
  <span cngxSliderThumb="end"></span>
</div>
```

### Fixing the error

Put the thumbs inside the element that carries the track, and bind the range there:

```html
<div cngxRangeSliderTrack [(value)]="price" [min]="0" [max]="500">
  <span cngxSliderThumb="start" aria-label="Minimum price"></span>
  <span cngxSliderThumb="end" aria-label="Maximum price"></span>
</div>
```

For the standard look use `<cngx-range-slider>`, which needs no thumbs from you.

### Debugging the error

The message reads `CNGX1062: [cngxSliderThumb] must be placed inside an element with [cngxRangeSliderTrack], such as <cngx-range-slider>.` In a production build the message is the bare code `CNGX1062`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A parent that another component renders in its own template, around content you project into it, is not above the projected element.
