# CNGX1073

## Split button without a main cngxButton

This warning is emitted when an element with `cngxSplitButton` from `@cngx/common/menu-button` renders without a main button among its direct children: a button that provides `CNGX_BUTTON_STATE` next to the `cngxIconMenuButton` caret. Every host of `CngxButtonBrain` provides it: `cngxButton`, `cngxIconButton`, `cngxActionButton` and custom button hosts.

A split button is a main button that runs the default action and a caret (`cngxIconMenuButton`) that opens the alternatives. The caret derives its state from the main button: while the main action is disabled or running its `cngxAsyncClick`, the caret is blocked too and an open menu closes. The directive finds the main button by looking at its direct children only, and never takes the caret for it, so a `cngxAsyncClick` button inside the projected menu never counts as the main action. Without a main button the caret stays active while the default action is unavailable or still running, and a user can start a second action on top of the first. Nothing throws.

```html
<!-- WARNING: the main button is wrapped, the split cannot see it -->
<div cngxSplitButton aria-label="Publish">
  <span><button cngxButton [cngxAsyncClick]="publish">Publish</button></span>
  <button cngxIconMenuButton [menu]="menu" [popover]="pop"></button>
</div>
```

### Fixing the warning

Place the main `<button cngxButton>` (or another button host such as `<button cngxIconButton>` or `<button cngxActionButton>`) as a direct child of the split button, before the caret. An `ng-container` (an `@if`, an `@for`) in between is fine; an element wrapper is not.

```html
<div cngxSplitButton aria-label="Publish">
  <button cngxButton [cngxAsyncClick]="publish">Publish</button>
  <button cngxIconMenuButton [menu]="menu" [popover]="pop"></button>
</div>
```

Run the main action through a `cngxButton` with a co-hosted `cngxAsyncClick`; its busy state, `aria-busy` and announcement carry over to the caret's blocked state without extra wiring.

### Debugging the warning

The message starts with `CNGX1073: [cngxSplitButton] has no main cngxButton.` and passes the host element as context, so the console links straight to the split button. The check runs once after the first render, so a main button that appears later through `@if` is not seen by the check, but the caret still follows it once it renders.

The check runs in development mode only. In production the split button renders the same, without a warning.
