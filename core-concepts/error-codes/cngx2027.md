# CNGX2027

## quickCreateAction settled without the created item

This error is raised when the `[quickCreateAction]` of an action select resolves to `undefined` instead of the newly created item.

`CngxActionSelect` and `CngxActionMultiSelect` turn a drafted label into a new option through `[quickCreateAction]`. The value the action resolves to is the created item: the select adds it to its local items, selects it, emits `created` and announces it. A result of `undefined` names no item, so there is nothing to add or select. Settling it as a success would close the panel with no new option and no feedback at all.

The select therefore settles such a create as an error. The quick-create error UI and its Retry callback appear, the failure is announced assertively like any rejected create, and `commitError` emits the error.

```ts
readonly create: CngxSelectCreateAction<Tag> = (term, draft) =>
  // ERROR: the API returns 204 without a body, the stream emits undefined
  this.api.createTag(draft.label);
```

All result shapes are covered: a sync `undefined`, a Promise that resolves `undefined` and an Observable that emits `undefined`.

### Fixing the error

Resolve to the created item. When the server answers without a body, build the item from the draft:

```ts
readonly create: CngxSelectCreateAction<Tag> = (term, draft) =>
  this.api.createTag(draft.label).pipe(map((res) => res ?? { id: draft.label, name: draft.label }));
```

### Debugging the error

The settled error is a `CngxRuntimeError` with `code` set to `'CNGX2027'`. In development mode its message starts with `CNGX2027: quickCreateAction() settled without the created item`; in production the message is the bare code, `CNGX2027`. It reaches the action slot as `error` and `hasError`, the live-region announcement and `CNGX_STATEFUL` consumers such as `CngxToastOn` as an ordinary `error` transition.

Search your code for the `[quickCreateAction]` binding of the select that failed and check what the action returns on success.
