# CNGX2015

## Field bridge without a form field

This warning is emitted when a field bridge from `@cngx/forms/field` is created without a `<cngx-form-field>` above it. The bridges are `[cngxBindField]`, `[cngxListboxFieldBridge]`, `[cngxSliderFieldBridge]` and `[cngxRangeSliderFieldBridge]`.

A bridge connects a control that knows nothing about forms (a native or Material input, a `[cngxListbox]`, a `<cngx-slider>`) to a form field. It reads the bound `Field<T>` from the surrounding `<cngx-form-field [field]="...">` presenter, syncs the value both ways, and projects the field's `id`, `aria-describedby`, `aria-invalid`, `aria-required` and disabled state onto the control. Without a form field there is nothing to read from: the control works as a plain control, the value never reaches the form, and the label, hint and error wiring is missing. Nothing throws, so the form simply never sees the control.

```html
<!-- WARNING: the bridge is not inside a form field -->
<label for="color">Color</label>
<input id="color" matInput cngxBindField />
```

### Fixing the warning

Wrap the control in a form field and bind the field there:

```html
<cngx-form-field [field]="form.color">
  <label cngxLabel>Color</label>
  <input matInput cngxBindField />
</cngx-form-field>
```

If the control is not meant to be part of a form, remove the bridge directive.

### Debugging the warning

The message names the bridge, for example `CNGX2015: [cngxBindField] has no form field to bind to, so it does nothing.` It does not identify the element; search your templates for that selector outside a `<cngx-form-field>`.

The check runs in development mode only, once per bridge, when the bridge is created. It looks for the form field through the element injector, from where the control is declared, so a control passed as content into a component that renders the `<cngx-form-field>` in its own template does not find it and warns.
