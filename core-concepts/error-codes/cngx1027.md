# CNGX1027

## Menu host is not focusable

This warning is emitted when `CngxMenu.focus()` runs while the `[cngxMenu]` host element has a negative `tabIndex`. `CngxContextMenuTrigger` calls `focus()` right after it opens a context menu; your own code may call it through the `cngxMenu` export.

`CngxMenu` uses active-descendant navigation: DOM focus stays on the menu container and `aria-activedescendant` points at the highlighted item. Keyboard input only reaches the menu while the container itself has focus, so the host carries `tabindex="0"` by default. The warning means something replaced that: a `tabindex="-1"` or a `[attr.tabindex]` binding in your template, which takes precedence over the directive's default.

If the binding removes the attribute entirely (`[attr.tabindex]="null"`), the host is no longer focusable and `focus()` does nothing: after a right-click the menu opens but arrow keys still go to the page behind it. With `tabindex="-1"` the browser still accepts the programmatic focus, but the menu drops out of the Tab sequence, so a keyboard user who tabs away cannot tab back into it.

```html
<!-- WARNING: tabindex="-1" overrides the menu's tabindex="0" -->
<ul cngxMenu [label]="rowActionsLabel()" tabindex="-1">
  <li cngxMenuItem value="edit">{{ editLabel() }}</li>
</ul>
```

### Fixing the warning

#### Option 1: Keep the default tab index

Remove the `tabindex` override from the `[cngxMenu]` element, or set it to `0` explicitly:

```html
<ul cngxMenu [label]="rowActionsLabel()" tabindex="0">
  <li cngxMenuItem value="edit">{{ editLabel() }}</li>
</ul>
```

The menu items carry `tabindex="-1"` themselves; that is correct and not what this warning is about. Labels are user-facing copy; route them through your own i18n.

### Debugging the warning

The message starts with `CngxMenu.focus(): host element has tabindex < 0` and does not name the menu. Inspect the `[cngxMenu]` element in the DOM and look at its `tabindex` attribute, then search your templates for the binding that sets it, including bindings added by a wrapping component.

The check runs in development mode only, when `focus()` is called, and logs once per host element. It reads the element's `tabIndex` property, which is `-1` both for an explicit `tabindex="-1"` and for an element that has no `tabindex` attribute and is not focusable by default.
