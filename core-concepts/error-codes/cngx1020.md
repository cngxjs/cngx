# CNGX1020

## Duplicate error source key

This warning is emitted when an error aggregator receives a source whose key is already registered by a different source. In templates this is two `[cngxErrorSource]` directives with the same key under one `[cngxErrorAggregator]`; in code it is `addSource()` on a contract from `injectErrorAggregator`.

The aggregator keeps its sources in a map keyed by the source key. `hasError`, `errorCount`, `activeErrors`, `errorLabels` and the `announcement` text are all derived from that map. A second source with the same key replaces the first one (last wins), so the first source's condition is no longer read at all.

The failure is silent. The aggregator stops reporting an error that is still there, the error count is one too low, and the error disappears from the live announcement. Removal makes it worse: `removeSource` removes by key, so when either of the two sources is destroyed, the key is gone and neither condition is counted any more.

```html
<fieldset cngxErrorAggregator>
  <span cngxErrorSource="required" [when]="emailMissing()" [label]="emailRequiredLabel()"></span>

  <!-- WARNING: "required" is already registered by the email source -->
  <span cngxErrorSource="required" [when]="phoneMissing()" [label]="phoneRequiredLabel()"></span>
</fieldset>
```

### Fixing the warning

#### Option 1: Give every source its own key

The key only has to be unique within its aggregator. Combine the field with the rule:

```html
<span cngxErrorSource="email-required" [when]="emailMissing()" [label]="emailRequiredLabel()"></span>
<span cngxErrorSource="phone-required" [when]="phoneMissing()" [label]="phoneRequiredLabel()"></span>
```

Sources rendered in a loop need the row's identity in the key, for example `[cngxErrorSource]="'row-' + row.id + '-required'"`. The labels are announced to screen readers; route them through your own i18n.

#### Option 2: Merge the conditions

If both sources describe the same error on purpose, register one source with the combined condition:

```html
<span cngxErrorSource="contact-required" [when]="emailMissing() || phoneMissing()" [label]="contactRequiredLabel()"></span>
```

### Debugging the warning

The message quotes the key, for example `CNGX1020: addSource(): an error source with key "required" is already registered`. Search the aggregator's subtree for `cngxErrorSource` bindings that produce that key.

The check runs in development mode only, on every `addSource` call that brings a different entry under an existing key. `CngxErrorSource` re-registers whenever its key or label changes, so a label change does not trigger it on its own. Keys are scoped to the nearest aggregator; the same key under two different aggregators is fine. Duplicate *names* of whole aggregators or scopes in the registry are a separate warning, [CNGX1021](cngx1021.html).
