# CNGX1041

## Feature dropped for a missing `_target`

This warning is emitted when `provideCngxStepper(...)` or `provideCngxTabs(...)` receives a feature that carries no `_target` discriminator.

Both providers accept two kinds of feature in one call: config features (orientation, linear mode, router sync and so on) and i18n features (labels). Each feature is tagged with `_target: 'config'` or `_target: 'i18n'`, and the provider routes it to the matching token by that tag. The `with*` helpers and `withStepperI18nLabels(...)` / `withTabsI18nLabels(...)` set it for you; `defineStepperConfigFeature(...)` / `defineTabsConfigFeature(...)` set it on a hand-written config feature.

A feature without the tag is dropped. Routing it by shape would risk writing an i18n override into the config token, so the provider leaves it out and the setting it carries has no effect.

```ts
// WARNING: a bare mutator, no _target
const compact = (config) => ({ ...config, defaultOrientation: 'vertical' });

providers: [provideCngxStepper(withStepperLinear(true), compact)];
```

### Fixing the warning

#### Option 1: Use the matching helper

Most settings have a `with*` helper; use it instead of a hand-written mutator:

```ts
providers: [provideCngxStepper(withStepperLinear(true), withStepperDefaultOrientation('vertical'))];
```

#### Option 2: Brand the feature

For a setting without a helper, wrap the mutator so it carries the tag:

```ts
const compact = defineStepperConfigFeature((config) => ({ ...config, defaultOrientation: 'vertical' }));

providers: [provideCngxStepper(withStepperLinear(true), compact)];
```

Use `defineTabsConfigFeature(...)` for `provideCngxTabs`, and `withStepperI18nLabels(...)` / `withTabsI18nLabels(...)` for labels.

### Debugging the warning

The message starts with `[provideCngxStepper]` or `[provideCngxTabs]` and says a feature was dropped. It does not say which one; check every argument of that call that is not a `with*` helper. A feature written before the `_target` tag existed, or one created by spreading another object, is the usual cause.

The check runs in development mode only, once per dropped feature, when the provider call is evaluated. The other features of the same call are still applied.
