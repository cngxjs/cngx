# CNGX1041

## Feature dropped for a missing `_target`

This warning is emitted when `provideCngxStepper(...)` or `provideCngxTabs(...)` receives a feature that carries no `_target` discriminator.

Both providers accept two kinds of feature in one call: config features (orientation, linear mode, router sync and so on) and i18n features (labels). Each feature is tagged with `_target: 'config'` or `_target: 'i18n'`, and the provider routes it to the matching token by that tag. The `with*` helpers of `@cngx/common/stepper` and `@cngx/common/tabs` set it for you, and so do `withStepperI18nLabels(...)` / `withTabsI18nLabels(...)`. The same applies to the component-scoped twins `provideCngxStepperAt(...)` and `provideCngxTabsAt(...)`.

A feature without the tag is dropped. Routing it by shape would risk writing an i18n override into the config token, so the provider leaves it out and the setting it carries has no effect. The feature types require the tag, so such a feature reaches the provider only past the type checker: a cast, an `any`, plain JavaScript, or a feature object rebuilt by spreading another one.

```ts
import { type CngxStepperConfig, type CngxStepperFeature, provideCngxStepper, withStepperLinear } from '@cngx/common/stepper';

// WARNING: a hand-written mutator cast to the feature type, no _target
const compact = ((config: CngxStepperConfig) => ({
  ...config,
  defaultOrientation: 'vertical',
})) as unknown as CngxStepperFeature;

export const providers = [provideCngxStepper(withStepperLinear(true), compact)];
```

### Fixing the warning

Use the matching `with*` helper instead of a hand-written mutator, and the i18n helper for labels:

```ts
import {
  provideCngxStepper,
  withStepperDefaultOrientation,
  withStepperI18nLabels,
  withStepperLinear,
} from '@cngx/common/stepper';

export const providers = [
  provideCngxStepper(
    withStepperLinear(true),
    withStepperDefaultOrientation('vertical'),
    withStepperI18nLabels({ stepperLabel: 'Checkout steps' }),
  ),
];
```

For one component subtree, pass the same helpers to `provideCngxStepperAt(...)` in `providers` or `viewProviders`. Tabs work the same way: `provideCngxTabs(...)` / `provideCngxTabsAt(...)` with the `withTabs*` / `withTab*` helpers and `withTabsI18nLabels(...)`.

### Debugging the warning

The message starts with the name of the function that dropped the feature, `CNGX1041: provideCngxStepper()`, `CNGX1041: provideCngxStepperAt()`, `CNGX1041: provideCngxTabs()` or `CNGX1041: provideCngxTabsAt()`, and says a feature was dropped. It does not say which one; check every argument of that call that is not a `with*` helper. A feature written before the `_target` tag existed, or one created by spreading another object, is the usual cause.

The check runs in development mode only, once per dropped feature, when the provider call is evaluated. The other features of the same call are still applied.
