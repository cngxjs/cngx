# CNGX1066

## Sheet part outside a popover sheet

This error is thrown when one of the sheet parts from `@cngx/common/popover` is created without a `[cngxPopoverSheet]` above it: `[cngxPopoverSheetHeader]`, `[cngxPopoverSheetTitle]`, `[cngxPopoverSheetHandle]` or `[cngxPopoverSheetInitialFocus]`.

The parts hold no state of their own. The title gives the sheet its accessible name (the sheet points `aria-labelledby` at it), the initial-focus part tells the sheet where focus goes on open, and the header and handle route a `cngxSwipeDismiss` swipe into the sheet's close request. Without a sheet the title names nothing, focus never reaches the marked element and a swipe closes nothing, so the constructor throws instead of leaving a part that silently does nothing.

```html
<!-- ERROR: the title sits next to the popover, not inside it -->
<h2 cngxPopoverSheetTitle>City</h2>
<div cngxPopover cngxPopoverSheet>
  <ul>...</ul>
</div>
```

### Fixing the error

Move the part inside the element that carries `[cngxPopoverSheet]`:

```html
<div cngxPopover cngxPopoverSheet>
  <header cngxPopoverSheetHeader>
    <h2 cngxPopoverSheetTitle>City</h2>
  </header>
  <ul>...</ul>
</div>
```

### Debugging the error

The message names the part, for example `CNGX1066: [cngxPopoverSheetTitle] must be placed inside an element with [cngxPopoverSheet].` In a production build the message is the bare code `CNGX1066`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A sheet that another component renders in its own template, around content you project into it, is not above the projected part.
