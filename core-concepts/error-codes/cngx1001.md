# CNGX1001

## Unknown earcon

This warning is emitted when the audio engine is asked to play an earcon name that it has no entry for. The name comes from the right-hand side of a `[cngxAudio]`, `[cngxAudioStatus]` or `[cngxAudioZone]` binding, or from a direct `injectCngxAudio().play(name)` call.

The engine keeps one map of earcons per engine instance: the six built-ins (`tap`, `success`, `error`, `warning`, `notification`, `complete`), merged with everything passed to `withEarcons({ ... })` in `provideCngxAudio(...)`, plus whatever was added later with `register(name, config)`. `play()` looks the name up in that map and, when it finds nothing, returns without playing.

The binding grammar does not validate earcon names, so a typo parses fine, the listener is attached, and the click or status transition happens as usual. The only symptom is that the sound is missing, which is easy to miss when testing with audio muted:

```html
<!-- WARNING: "sucess" is not a registered earcon -->
<button type="button" [cngxAudio]="'click:sucess'">Save</button>
```

### Fixing the warning

#### Option 1: Use a registered name

Correct the name to one of the built-ins or to an earcon your app registers:

```html
<button type="button" [cngxAudio]="'click:success'">Save</button>
```

#### Option 2: Register the earcon

Register custom earcons app-wide when you provide the audio system. Each earcon is a sequence of tone steps (`freq` in Hz, `duration` in ms, with optional `type`, `gain` and `delay`):

```ts
import { provideCngxAudio, withEarcons } from '@cngx/common/audio';

bootstrapApplication(App, {
  providers: [
    provideCngxAudio(
      withEarcons({
        chime: {
          sequence: [
            { freq: 880, duration: 60 },
            { freq: 1320, duration: 90 },
          ],
        },
      }),
    ),
  ],
});
```

For an earcon that only exists after some runtime step, call `injectCngxAudio().register('chime', config)` before the first play. A name registered under an existing key replaces that earcon.

### Debugging the warning

The message quotes the name, for example `CNGX1001: [cngxAudio] Unknown earcon "sucess"`. Search your templates and `play()` calls for that string.

The check runs in development mode only, and only when a play actually gets through the engine's gates: audio not muted, reduced motion not blocking it, the autoplay gate armed by a first user gesture, an `AudioContext` available, and the name outside its debounce window. Before the first click or key press on the page, an unknown name stays silent in the console too. Each unknown name is reported once per engine instance; later plays of the same name do not warn again.

The debounce check runs before the lookup, so an unknown name still takes its debounce slot. If code registers the earcon right after a failed play and plays it again within the debounce window (`withDebounceMs`, 100 ms by default), that second play is skipped as a repeat.
