# CNGX3018

## Paginator segment outside a paginator

This error is thrown when a paginator segment from `@cngx/ui/paginator` (`<cngx-pgn-pages>`, `<cngx-pgn-prev>`, `<cngx-pgn-range>`, `<cngx-pgn-load-more>` and the other `cngx-pgn-*` parts) is created without the paginator that drives it above it.

A segment holds no paging state. It reads the page index, the page count and the busy state from the surrounding paginator and calls back into it to navigate. `<cngx-paginator>` and `<cngx-incremental-list>` provide that model to their content. `<cngx-pgn-alpha>` is the exception: it works on a bucket model instead, which `[cngxBucketPaginate]` provides. Without its parent a segment has nothing to show and nothing to navigate, so the constructor throws instead of rendering a dead control.

```html
<!-- ERROR: the segments sit next to the paginator, not inside it -->
<cngx-paginator [total]="total()" />
<cngx-pgn-prev />
<cngx-pgn-pages />
<cngx-pgn-next />
```

### Fixing the error

Place the segments inside the paginator they belong to:

```html
<cngx-paginator [total]="total()">
  <cngx-pgn-prev />
  <cngx-pgn-pages />
  <cngx-pgn-next />
</cngx-paginator>
```

A load-more or infinite-scroll trigger can also sit inside `<cngx-incremental-list>`, which provides the same model. Place `<cngx-pgn-alpha>` inside an element with `[cngxBucketPaginate]`:

```html
<div cngxBucketPaginate [buckets]="buckets">
  <cngx-pgn-alpha />
</div>
```

### Debugging the error

The message names the segment, for example `CNGX3018: [cngx-pgn-pages] must be placed inside <cngx-paginator> or <cngx-incremental-list>.`, or, for the bucket strip, `CNGX3018: [cngx-pgn-alpha] must be placed inside an element with [cngxBucketPaginate].` In a production build the message is the bare code `CNGX3018`; the check still runs there.

The check runs once, in the constructor, and looks only at the element injector. Angular resolves it from where the segment is declared, not from where it ends up in the DOM. A segment passed as content to a wrapper component whose template contains the `<cngx-paginator>` resolves from the template it was written in, where no paginator is above it, so it throws. Declare the paginator in the same template as its segments.
