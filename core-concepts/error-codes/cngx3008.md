# CNGX3008

## Action button toasts configured twice

This warning is emitted when a `<cngx-action-button>` has its own `toastSuccess` or `toastError` input set and the same element also carries the `[cngxToastOn]` directive.

`CngxActionButton` raises toasts itself: when its async status moves to `success` or `error`, it calls `CngxToaster` with the `toastSuccess` / `toastError` text. `CngxToastOn` does the same for whatever state it watches. Both directives declare inputs named `toastSuccess` and `toastError`, so a single attribute on the element feeds both of them. If `[cngxToastOn]` watches the button's own state, every success and every failure raises the toast twice.

`CngxToaster` merges identical toasts (same message, severity and title) raised within its dedup window (1000 ms by default, `withToasts({ dedupWindow })`) into one toast with a repeat count. So the usual result is not two toasts but one toast with a repeat marker, which tells the user the event happened twice. When the second call lands outside the window, two separate toasts appear.

```html
<!-- WARNING: toastSuccess reaches both CngxActionButton and CngxToastOn -->
<cngx-action-button
  [action]="save"
  #btn="cngxActionButton"
  [cngxToastOn]="btn.state"
  [toastSuccess]="savedLabel()"
>
  Save
</cngx-action-button>
```

### Fixing the warning

#### Option 1: Use the button's own toast inputs

Remove `[cngxToastOn]`. The button raises the toasts, including `toastErrorDetail`, `toastSuccessDuration` and `toastErrorDuration`:

```html
<cngx-action-button [action]="save" [toastSuccess]="savedLabel()" [toastError]="saveFailedLabel()">
  Save
</cngx-action-button>
```

#### Option 2: Move the bridge off the button

If the toast should follow a different state than the button's (a form submit state, a parent workflow), put `[cngxToastOn]` on an element that is not the `<cngx-action-button>`, so its `toastSuccess` / `toastError` inputs no longer bind to the button as well.

### Debugging the warning

The message starts with `CNGX3008: [cngx-action-button]` and names both input pairs. It has no instance identifier; search your templates for `cngx-action-button` elements that also carry `cngxToastOn`.

The check runs in development mode only, once per button, after its first render, so it sees the `toastSuccess` and `toastError` values the template bound. A text bound only later (an input that starts `undefined` and is set after the first render) is not reported. The check looks only at `[cngxToastOn]` on the same element; a `[cngxToastOn]` on an ancestor that watches the same state also duplicates toasts but is not detected.

A `[cngxToastOn]` without a state source is a separate error, [CNGX3002](cngx3002.html).
