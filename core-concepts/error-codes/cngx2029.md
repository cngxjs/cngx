# CNGX2029

## Two elements carry one field id

This warning is emitted when more than one element on the page carries the input id of a `cngx-form-field` (`cngx-{name}-input`). The field builds its ids from the field name, so two fields with the same name, or two controls inside one field, end up with the same id. A `<label for>` then names only the first of them, `aria-describedby` and `aria-errormessage` point at whichever element the browser finds first, and the error summary can focus the wrong control.

Two cases cause it. Signal Forms names are unique per form, so the usual source is `adaptFormControl()`, whose name the caller picks:

```ts
// WARNING: both fields are named 'email', both inputs get id "cngx-email-input".
readonly billing = adaptFormControl(this.billingEmail, 'email', inject(DestroyRef));
readonly shipping = adaptFormControl(this.shippingEmail, 'email', inject(DestroyRef));
```

The other is a field that holds two controls; each one takes the field's input id:

```html
<!-- WARNING: two inputs, one id. -->
<cngx-form-field [field]="f.pair">
  <input cngxInput [formField]="f.pair" />
  <input cngxInput />
</cngx-form-field>
```

### Fixing the warning

Give every adapted field a name that is unique on the page:

```ts
readonly billing = adaptFormControl(this.billingEmail, 'billingEmail', inject(DestroyRef));
readonly shipping = adaptFormControl(this.shippingEmail, 'shippingEmail', inject(DestroyRef));
```

Put one control in each `cngx-form-field`. A prefix or suffix control (a currency picker) belongs in `cngxPrefix` / `cngxSuffix`, which take their own id.

### Debugging the warning

The message starts with `CNGX2029: [cngx-form-field]` followed by the number of elements and the id. Search the DOM for that id to find the elements. The check runs after each render in development mode only; in production the duplicate ids stay, without a warning.
