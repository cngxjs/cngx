# CNGX3016

## Toast without a CngxToaster

This error is thrown when `<cngx-toast>` or `[cngxToastOn]` from `@cngx/ui/feedback` is created and no `CngxToaster` can be injected for it.

Both hand their toasts to `CngxToaster`, the service `<cngx-toast-outlet>` renders from. `<cngx-toast>` shows a toast when its `[when]` input turns `true` and dismisses it when it turns `false`; `[cngxToastOn]` shows one on an async state's `success` or `error` transition. The toaster is not provided in root, so an app that never set it up has nowhere to show toasts, and both throw in their constructor instead of dropping every toast silently.

```typescript
// ERROR: provideFeedback() without withToasts(), and no provideToasts()
bootstrapApplication(AppComponent, {
  providers: [provideFeedback(withAlerts())],
});
```

### Fixing the error

Add `withToasts()` to `provideFeedback()`, or call `provideToasts()` when you do not use `provideFeedback()`. Render the toasts with one `<cngx-toast-outlet>`, usually in the root component:

```typescript
bootstrapApplication(AppComponent, {
  providers: [provideFeedback(withToasts())],
});
```

```html
<router-outlet />
<cngx-toast-outlet />
```

`provideToasts()` returns environment providers: it goes into `bootstrapApplication` or a route's `providers`, not into a component's `providers`.

### Debugging the error

The message starts with `CNGX3016: ` and the selector that threw: `[cngx-toast]` or `[cngxToastOn]`. In a production build the message is the bare code `CNGX3016`; the check still runs there.

The lookup follows the element injector tree from where the element is declared, then the environment injectors. Projected content resolves from the template it was written in, and a component created dynamically (a dialog, `ViewContainerRef.createComponent`) resolves from the injector passed to it. A toaster provided only in a lazy route's `providers` is not visible outside that route.
