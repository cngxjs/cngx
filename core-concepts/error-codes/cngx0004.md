# CNGX0004

## Registry key already registered

This warning is emitted when `register(key, value)` on a registry created with `createKeyedRegistry` from `@cngx/core/utils` receives a value for a key that a different value already holds.

The registry is built for the teardown race of keyed children: when Angular recreates a child, the successor's `register` can run before the predecessor's `DestroyRef` callback. To keep that race harmless, `unregister(key, value)` only removes the entry while `value` is still the holder, and `register` never replaces a live entry. A second value under a taken key is ignored (swap-is-noop), and readers keep the instance they already resolved.

The second registrant therefore believes it is registered but is invisible to everyone reading `entries`, `values` or `get(key)`. Nothing throws; the symptom is a child that never shows up, or a stale instance that keeps answering. The usual cause is a key that is not unique, such as a label or an index:

```ts
const panels = createKeyedRegistry<Panel>({ name: 'AppPanelHost' });

for (const panel of [detailsA, detailsB]) {
  // WARNING: both panels have the title "Details"; the second one is dropped
  panels.register(panel.title, panel);
}
```

### Fixing the warning

#### Option 1: Give each registrant a unique key

Use an id that cannot collide, for example one from `nextUid(prefix)` in `@cngx/core/utils`, or a domain id. Unregister with the same key and the same instance:

```ts
@Directive({ selector: '[appPanel]' })
export class AppPanel {
  private readonly host = inject(AppPanelHost);
  private readonly key = nextUid('app-panel');

  constructor() {
    this.host.panels.register(this.key, this);
    inject(DestroyRef).onDestroy(() => this.host.panels.unregister(this.key, this));
  }
}
```

#### Option 2: Unregister the holder before a deliberate swap

When replacing the entry is the intent, remove the current holder first. `unregister` needs the holder itself, not only the key:

```ts
const current = registry.get(key);
if (current) {
  registry.unregister(key, current);
}
registry.register(key, next);
```

### Debugging the warning

The message starts with `CNGX0004: createKeyedRegistry(): `, then names the registry by its `name` option and quotes the key, for example `CNGX0004: createKeyedRegistry(): AppPanelHost already holds "Details"`. A registry created without `name` reports as `cngx registry`; pass a `name` so the line points at the owner.

The check runs in development mode only, on every colliding `register` call; it is not deduplicated. Registering the same value under the same key again is a no-op and does not warn. The single-slot sibling, `createSlotRegistry`, is last-write-wins and never warns.
