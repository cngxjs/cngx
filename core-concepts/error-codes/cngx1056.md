# CNGX1056

## Stepper control without a stepper

This warning is emitted when a stepper control from `@cngx/common/stepper` has no stepper to work with: `[cngxStepperNext]`, `[cngxStepperPrevious]`, `[cngxStepperComplete]` or `<cngx-stepper-count>` with no `[host]` binding and no stepper presenter above it.

The controls are free-standing on purpose, so a Next button or a "Step 2 of 4" caption can sit anywhere in the layout. Each one finds its stepper in one of two ways: from the stepper it is placed in (`<cngx-stepper>`, any element with `[cngxStepper]`), or from an explicit `[host]` input when it sits outside, for example in a page header. With neither, a navigation button stays disabled for good (`aria-disabled="true"`, clicks do nothing), the finish button never becomes active, and the count renders nothing. Nothing throws, so the control just looks broken.

```html
<!-- WARNING: the buttons sit next to the stepper, not inside it, and have no [host] -->
<cngx-stepper>...</cngx-stepper>
<footer>
  <button type="button" cngxStepperPrevious>Back</button>
  <button type="button" cngxStepperNext>Next</button>
</footer>
```

### Fixing the warning

#### Option 1: Place the control inside the stepper

A control inside the stepper finds it without any binding:

```html
<cngx-stepper>
  ...
  <button type="button" cngxStepperNext>Next</button>
</cngx-stepper>
```

#### Option 2: Bind `[host]` for a control outside the stepper

Export the stepper as a template reference and pass its presenter:

```html
<cngx-stepper #wizard="cngxStepper">...</cngx-stepper>
<footer>
  <button type="button" cngxStepperPrevious [host]="wizard.presenter">Back</button>
  <button type="button" cngxStepperNext [host]="wizard.presenter">Next</button>
</footer>
```

On a plain element with `[cngxStepper]`, the exported reference is the presenter itself: `<div cngxStepper #s="cngxStepper">` and `[host]="s"`.

### Debugging the warning

The message names the control, for example `CNGX1056: [cngxStepperNext] has no stepper.` It does not identify the element; search your templates for that selector outside a stepper and without `[host]`.

The check runs in development mode only, once per control, after its first render, so a `[host]` bound in the same template is already in place. A `[host]` that is `null` at that moment counts as missing even if it is set later; a control whose host arrives asynchronously warns once and then works.
