# CNGX2003

## Filter value references an unknown field

This warning is emitted when the `FilterGroup` bound to `value` on `<cngx-filter-builder>` contains expressions whose `field` key matches no `key` in `fields`.

The builder resolves each expression's field through a key map built from `fields`. That definition is what the row needs for its operator list, its value editor and its label, and what `evaluateExpression` needs to read the item's value. An expression whose key is not in the map has none of these.

The row still renders, but with an empty operator list, and at evaluation time the expression returns `false` for every item, before the empty-value no-op is checked. In an `and` group one such row excludes everything. The usual cause is a saved filter that outlived a renamed or removed field:

```ts
readonly fields: FilterFieldDef[] = [
  { key: 'status', label: this.labels.status, editorType: 'string' },
];

readonly filter = signal<FilterGroup>(
  createFilterGroup('and', [
    // WARNING: 'state' was renamed to 'status'; no field has this key
    createFilterExpression('state', 'eq', 'active'),
  ]),
);
```

### Fixing the warning

#### Option 1: Migrate the stored value when you load it

Rewrite renamed keys, or drop expressions for removed fields, before the value reaches the builder:

```ts
const renamed: Record<string, string> = { state: 'status' };

function migrate(group: FilterGroup): FilterGroup {
  return {
    ...group,
    filters: group.filters.map((node) =>
      node.type === 'group' ? migrate(node) : { ...node, field: renamed[node.field] ?? node.field },
    ),
  };
}
```

#### Option 2: Add the missing field

If the field is still filterable, add an entry with that `key` to `fields`.

### Debugging the warning

The message lists every unknown key, comma-separated, for example `CNGX2003: [cngxFilterBuilderPresenter] value() references unknown field key(s): state, owner`. Search your stored filters and the code that builds the initial value for those keys.

The check runs in development mode only, once per builder instance, after its first render, against the value at that moment. Later writes to `value`, from your code or from the user, are not checked. An expression whose `field` is an empty string also counts as unknown and shows up as an empty entry in the list. If `fields` itself is empty, every key is unknown; fix [CNGX2002](cngx2002.html) first. An unknown *operator* key is a separate warning, [CNGX2001](cngx2001.html).
