# CNGX1045

## Tab or tab link outside a tab group

This error is thrown when a `[cngxTab]` or a `[cngxTabLink]` is created without a tab group above it in the injector tree.

A tab is not self-contained: it registers itself with the group's presenter, and the presenter owns which tab is active, the keyboard navigation over the tab strip and the error aggregation. Both directives inject that presenter through `CNGX_TAB_GROUP_HOST`. Without it there is nothing to register with and no active state to derive `selected` from, so the constructor throws instead of rendering a tab that can never be selected.

```html
<!-- ERROR: no [cngxTabGroup] host above the tab -->
<div>
  <div cngxTab label="Profile">...</div>
</div>
```

### Fixing the error

Place the tab inside an element that provides a tab group. Any of these does:

- an element carrying `[cngxTabGroup]` (the headless presenter from `@cngx/common/tabs`),
- `<cngx-tab-group>` or `<cngx-tab-nav>` from `@cngx/ui/tabs`,
- the Material bridges `[cngxMatTabs]` and `[cngxMatTabNav]` from `@cngx/ui/mat-tabs`.

```html
<div cngxTabGroup>
  <div cngxTab label="Profile">...</div>
  <div cngxTab label="Security">...</div>
</div>
```

A `[cngxTabLink]` belongs inside `<cngx-tab-nav>` (or another `[cngxTabGroup]` host), next to the router outlet it drives.

### Debugging the error

The message starts with the directive that threw: `CngxTab` or `CngxTabLink`. In a production build the message is the bare code `CNGX1045`; the check still runs there, because a tab without a group cannot work.

The check runs once, in the directive's constructor, and looks only at the injector. A tab inside an `ng-template` or a component that is rendered somewhere else (a portal, a dialog, a dynamically created view) resolves its injector from where the view is created, not from where the template is written. If the template looks right, check where the view is instantiated and whether that injector sees the group.
