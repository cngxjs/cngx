# CNGX1053

## Button toggle without a group

This error is thrown when a `[cngxButtonToggle]` is created without a `<cngx-button-toggle-group>` or a `<cngx-button-multi-toggle-group>` above it in the injector tree.

The button toggle holds no value state. Its pressed or checked state is derived from the group (`value` for the single group, `selectedValues` for the multi group), a click writes through the group, and the group owns the roving tabindex across its toggles. Without a group there is nothing to read or write, so the button would render as permanently unpressed and ignore clicks. It throws instead.

```html
<!-- ERROR: no group above the toggle -->
<button cngxButtonToggle value="bold">Bold</button>
```

### Fixing the error

#### Option 1: Put it in a group

Pick the group by how many values may be active at once:

```html
<cngx-button-toggle-group label="Alignment" [(value)]="align">
  <button cngxButtonToggle value="start">Start</button>
  <button cngxButtonToggle value="center">Center</button>
</cngx-button-toggle-group>

<cngx-button-multi-toggle-group label="Style" [(selectedValues)]="styles">
  <button cngxButtonToggle value="bold">Bold</button>
  <button cngxButtonToggle value="italic">Italic</button>
</cngx-button-multi-toggle-group>
```

#### Option 2: Use a standalone toggle

For a single on/off control that is not part of a set, use `CngxToggle` (`<cngx-toggle>` / `[cngxToggle]`) from `@cngx/common/interactive`. It owns its state as a two-way `[(value)]` model and needs no parent. It is a switch (`role="switch"`, `aria-checked`), not a pressed button, so screen readers announce it as on/off; choose it when that is the meaning, not as a drop-in for a toggle button.

### Debugging the error

In a production build the message is the bare code `CNGX1053`; the check still runs there, because a toggle without a group cannot work.

The toggle resolves its group once, when it is created, by walking the element injector. Angular resolves it from where the toggle is declared, not from where it ends up in the DOM. A toggle inside an `ng-template` declared within the group finds it even when the template is rendered somewhere else. A toggle written as content of a component that wraps `<ng-content>` in its own group does not find that group: projected content resolves from the template it was written in. A component created dynamically (a dialog, `ViewContainerRef.createComponent`) resolves from the injector passed to it, or from the view container's, so pass one that sees the group. A toggle that sees both group kinds reports [CNGX1052](cngx1052.html) instead.
