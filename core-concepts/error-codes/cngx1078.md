# CNGX1078

## Hotkey on a browser-reserved combo

This warning is emitted when a binding is registered in the hotkey registry from `@cngx/common/interactive` with a combo the browser handles before the page sees it.

Browsers keep a set of window and tab commands for themselves: close, reopen and new tab or window (`mod+w`, `mod+shift+w`, `mod+t`, `mod+shift+t`, `mod+n`, `mod+shift+n`), quit (`mod+q`), tab switching (`ctrl+tab`, `ctrl+shift+tab`, `ctrl+pagedown`, `ctrl+pageup`) and `alt+f4`. A page cannot intercept them reliably, so a binding on one of them fires in some browsers, never in others, and may close the user's tab instead. The binding is still registered; nothing throws.

```ts
// WARNING: mod+w closes the tab before the page sees it
injectHotkey({ id: 'panel.close', combo: 'mod+w', run: () => closePanel() });
```

### Fixing the warning

Pick a combo outside the reserved set, for example `escape` for closing a panel or `mod+shift+k` for an app command.

```ts
injectHotkey({ id: 'panel.close', combo: 'escape', run: () => closePanel() });
```

### Debugging the warning

The message starts with `CNGX1078: [CngxHotkeyRegistry] hotkey "<id>" uses "<combo>", which the browser handles before the page.` The context object carries the id and the combo. The comparison is per platform: `mod+w` and `meta+w` are reserved on macOS, `mod+w` and `ctrl+w` elsewhere.

The check runs in development mode only, at registration. In production the binding registers the same, without a warning.
