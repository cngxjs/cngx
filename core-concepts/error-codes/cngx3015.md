# CNGX3015

## Alert bridge without a CngxAlerter

This error is thrown when `[cngxAlertOn]` from `@cngx/ui/feedback` is created and no `CngxAlerter` can be injected for it.

The bridge turns an async state's `success` and `error` transitions into alerts by calling `CngxAlerter`. The alerter is not provided in root: it is scoped on purpose, so alerts land in the stack that belongs to the form or dialog that raised them. Without one there is nowhere to send an alert, and the bridge throws in its constructor instead of dropping every alert silently.

```typescript
// ERROR: provideFeedback() without withAlerts(), and no component provides CngxAlerter
bootstrapApplication(AppComponent, {
  providers: [provideFeedback(withToasts())],
});
```

### Fixing the error

#### Option 1: Provide it app-wide

Add `withAlerts()` to `provideFeedback()`, and render the alerts with a `<cngx-alert-stack>`:

```typescript
bootstrapApplication(AppComponent, {
  providers: [provideFeedback(withAlerts())],
});
```

The stack shows the alerts of the alerter above it, filtered by its `[scope]` (a stack without one shows all of them), so `alertScope="form"` on the bridge and `scope="form"` on the stack pair them up.

#### Option 2: Provide it for one subtree

Add `CngxAlerter` to the `providers` of a component that contains the bridge. Alerts then stay inside that component's subtree:

```typescript
@Component({
  selector: 'app-profile-form',
  providers: [CngxAlerter],
  template: `
    <cngx-alert-stack />
    <form [cngxAlertOn]="saveState" alertError="Saving failed">...</form>
  `,
})
export class ProfileForm {
  readonly saveState = createManualState<void>();
}
```

### Debugging the error

The message reads `CNGX3015: [cngxAlertOn] CngxAlerter not found. Add withAlerts() to provideFeedback() or provide CngxAlerter in an ancestor component.` In a production build the message is the bare code `CNGX3015`; the check still runs there.

`<cngx-alert-stack>` creates an alerter of its own, but in `viewProviders`: it is visible only inside the stack's template, not to a `[cngxAlertOn]` next to the stack. A bridge beside a stack therefore needs one of the options above.

The lookup follows the element injector tree from where the element is declared, then the environment injectors. Projected content resolves from the template it was written in, and a component created dynamically (a dialog, `ViewContainerRef.createComponent`) resolves from the injector passed to it.
