# CNGX1014

## Second dialog title or description registered

This warning is emitted when a second `cngxDialogTitle` or `cngxDialogDescription` registers with a `CngxDialog` while the first one is still alive.

A dialog has one accessible name and one primary description. `CngxDialog` binds `aria-labelledby` to one title id and `aria-describedby` to one description id, and when it opens it announces the title's text through its live region. Each `cngxDialogTitle` and `cngxDialogDescription` registers with the nearest dialog when it is created. The registry holds one slot per kind, and the id each directive takes is derived from the dialog id (`<dialog-id>-title`, `<dialog-id>-desc`), so two titles in one dialog render two elements with the same `id`.

Which element ends up naming the dialog then depends on how it was built. In a template-declared dialog, the dialog's content query picks the first title for the announcement, while `aria-labelledby` resolves to whichever element with that id comes first in the DOM. In a dialog opened from code, the content query cannot see the dynamic view and the newest registration is used for the announcement. Either way, the duplicate id is invalid HTML and the name or description may not be the text you expect:

```html
<dialog cngxDialog #confirm="cngxDialog">
  <h2 cngxDialogTitle>{{ deleteTitle() }}</h2>
  <!-- WARNING: second title in the same dialog -->
  <app-dialog-header [title]="deleteTitle()" />
  <p cngxDialogDescription>{{ deleteHint() }}</p>
</dialog>
```

Here `app-dialog-header` is a reusable header whose template also carries a `cngxDialogTitle`.

### Fixing the warning

#### Option 1: Keep one title and one description per dialog

Remove the extra directive. If a shared header component already renders the title, let it own the `cngxDialogTitle` and drop the one in the dialog:

```html
<dialog cngxDialog #confirm="cngxDialog">
  <app-dialog-header [title]="deleteTitle()" />
  <p cngxDialogDescription>{{ deleteHint() }}</p>
</dialog>
```

#### Option 2: Merge extra descriptive text into the one description

For several paragraphs of description, wrap them in a single element that carries `cngxDialogDescription`, rather than marking each paragraph. Everything inside that element becomes the description.

### Debugging the warning

The message names the dialog by its id and the kind, for example `CNGX1014: [cngxDialog] dialog "cngx-dialog-3" has a second title registered while another is live`. Search the rendered DOM for elements whose `id` is `cngx-dialog-3-title` (or `-desc`); there will be two.

The check runs in development mode only, at registration time, so it fires when the second directive is created. A title that is destroyed before the next one is created does not warn, because it unregisters on destroy; only two live at the same time are reported. The non-modal announcement check for the same dialog is [CNGX1015](cngx1015.html).
