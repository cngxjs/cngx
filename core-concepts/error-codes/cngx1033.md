# CNGX1033

## Scroll-spy section not found

This warning is emitted when `[cngxScrollSpy]` is given section ids that do not exist in the document.

`CngxScrollSpy` takes a list of ids, looks each one up with `document.getElementById(id)` and observes the elements it finds. The active section is the observed one with the largest visible ratio. An id that is not found is skipped: it is never observed, so it can never become active.

A table of contents or a nav bar wired to the spy then shows an entry that is never highlighted while the reader is on that section, and the previously active entry stays highlighted instead. `CngxScrollSpy` sets no ARIA itself; if your template binds `aria-current` on the active link from `spy.activeId()`, screen-reader users hear the same stale entry.

```html
<!-- WARNING: the section id is "pricing", not "prices" -->
<nav [cngxScrollSpy]="['intro', 'features', 'prices']" #spy="cngxScrollSpy">...</nav>
<section id="intro">...</section>
<section id="features">...</section>
<section id="pricing">...</section>
```

### Fixing the warning

#### Option 1: Fix the ids

Make every id in the list match an element id in the document, character for character. Ids are case-sensitive.

#### Option 2: Re-bind the list once late sections exist

The spy looks the ids up when it builds its observer, not continuously. Sections rendered later (after data loads, inside `@defer`, behind an `@if`) are not picked up on their own. Derive the id list from the same data that renders the sections, so the list changes when they appear and the spy rebuilds its observer:

```ts
readonly sectionIds = computed(() => this.sections().map((s) => s.id));
```

```html
<nav [cngxScrollSpy]="sectionIds()">...</nav>
@for (section of sections(); track section.id) {
  <section [id]="section.id">...</section>
}
```

### Debugging the warning

The message starts with `CNGX1033: [cngxScrollSpy] section id(s) not found:` and lists every missing id, comma-separated. Check each one with `document.getElementById('<id>')` in the browser console.

The check runs in development mode only, each time the spy rebuilds its observer: after the first render and whenever the section list, `[threshold]`, `[root]` or `[rootMargin]` changes. It is not deduplicated. When none of the ids is found, the spy observes nothing and returns before it resolves `[root]`, so a wrong root selector in that state is not reported as [CNGX1032](cngx1032.html) until at least one section exists.
