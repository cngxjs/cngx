# CNGX1008

## More than one chart overlay

This warning is emitted when more than one `<ng-template cngxChartOverlay>` is projected into a `<cngx-chart>`.

The overlay slot puts HTML on top of the drawn marks: crosshair readouts, annotation callouts, hover tooltips. The chart renders it in one frame that it insets to the plot area, and it has exactly one such frame. It collects every projected `cngxChartOverlay` template but stamps only the first one into the frame.

Every overlay after the first is dropped without an error. The template compiles and its bindings are valid; its content just never appears:

```html
<cngx-chart [data]="series()">
  <svg:g cngxAxis position="left" [domain]="[0, 100]"></svg:g>
  <svg:g cngxLine></svg:g>
  <ng-template cngxChartOverlay>
    <div class="target-callout">{{ targetLabel() }}</div>
  </ng-template>
  <!-- WARNING: second overlay template, never rendered -->
  <ng-template cngxChartOverlay let-plot="plot">
    <div class="crosshair-readout">...</div>
  </ng-template>
</cngx-chart>
```

### Fixing the warning

#### Option 1: Compose all overlay content in one template

Merge the content into a single overlay template. The frame is already positioned and inset to the plot area, so the children can position themselves inside it:

```html
<cngx-chart [data]="series()">
  <svg:g cngxAxis position="left" [domain]="[0, 100]"></svg:g>
  <svg:g cngxLine></svg:g>
  <ng-template cngxChartOverlay let-plot="plot">
    <div class="target-callout">{{ targetLabel() }}</div>
    <div class="crosshair-readout">...</div>
  </ng-template>
</cngx-chart>
```

The frame is `pointer-events: none`; give interactive children `pointer-events: auto` explicitly. Overlay content is visual only: the chart host is a single labelled graphic, so anything that has to reach assistive technology belongs in the summary or the data table, not here.

### Debugging the warning

The message is fixed text and does not name the chart. Search the template of the chart that shows only part of its overlay content for a second `cngxChartOverlay`.

The check runs in development mode only, once per chart, after the first render. It counts only overlay templates that are direct content children of `<cngx-chart>`. The slot that actually renders is resolved with a descendant query, so an overlay template nested inside another element in the chart's content is still a candidate for the one rendered slot, but is not counted here. An overlay template that appears after the first render is not reported either.
