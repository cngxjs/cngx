# CNGX1085

## Failed first load without an error template

This warning is emitted when a `*cngxAsync` from `@cngx/common/data` reaches the error view on a first load and has no error template bound.

On a first load there is no data to keep on screen, so the directive renders the error template in place of the content. Without one it renders nothing: the host stays empty, nothing is announced, and the failure is invisible to sighted and screen reader users alike. Nothing throws.

```html
<!-- WARNING: a failed first load leaves this list empty and silent -->
<ul *cngxAsync="residents; let data">
  @for (r of data; track r.id) { <li>{{ r.name }}</li> }
</ul>
```

### Fixing the warning

Bind an error template through the microsyntax. Its context is `{ $implicit: error }`.

```html
<ul *cngxAsync="residents; let data; error: errTpl">
  @for (r of data; track r.id) { <li>{{ r.name }}</li> }
</ul>

<ng-template #errTpl let-err>
  <li role="alert">Could not load residents.</li>
</ng-template>
```

If the app already reports the failure elsewhere, for example through an alert or toast bridge on the same state, bind a minimal error template anyway. That states the choice in the template and silences the warning.

### Debugging the warning

The message starts with `CNGX1085: [cngxAsync] reached the error state on a first load without an error template`. The context argument is the parent element of the directive's anchor, or the anchor comment when it has no parent element.

The check runs once per directive instance in development mode only, when the directive switches to the error view. A failed refresh does not warn: the directive keeps the previous content on screen there and never renders the error template, so surface that error separately. In production nothing is checked.
