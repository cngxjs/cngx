# CNGX2021

## Field-box control is not a direct child

This warning is emitted when a `cngxFieldBox` from `@cngx/forms/field` has no direct-child form-field control, but a control sits deeper inside it, behind a wrapper element.

The box owns its direct children only. A control that is a direct child resolves to the `bare` skin, drops its own surface, border and padding, and becomes the box's main control: the box paints its invalid, disabled and readonly state. A control behind a wrapper is none of that. It keeps its own skin, so two boxes are drawn, and the outer box paints no control state at all. The box does not search deeper on purpose: a descendant query would reach into composite controls and pick one of their inner inputs as the main control.

```html
<!-- WARNING: the input is wrapped, the box paints nothing -->
<span cngxFieldBox>
  <div class="input-wrapper">
    <input cngxInput [formField]="f.reference" />
  </div>
</span>
```

### Fixing the warning

#### Option 1: Remove the wrapper

Make the control a direct child of the box. Layout belongs on the box itself or on the affixes, not on a wrapper around the control:

```html
<span cngxFieldBox>
  <input cngxInput [formField]="f.reference" />
</span>
```

#### Option 2: Move a composite out of the box

A component that renders its own controls, such as `CngxPhoneInput`, is already its own box. Place it directly in `cngx-form-field`, without a `cngxFieldBox` around it.

### Debugging the warning

The message starts with `CNGX2021: [cngxFieldBox]`. The box element is passed as the second console argument; expand it in the browser console to find the wrapped control inside it.

The check runs in development mode only, once per box, after its first render. A control that an `@if` adds later is not checked. Controls inside a `cngxPrefix` or `cngxSuffix` wrapper do not count once the box has a direct-child main control. Two direct-child main controls are a different warning, [CNGX2020](cngx2020.html).
