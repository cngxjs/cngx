# CNGX1075

## Button brain without a host descriptor

This error is thrown when an element declares `CngxButtonBrain` from `@cngx/common/button` in its `hostDirectives` without providing the host descriptor through `provideButtonHost`.

`CngxButtonBrain` is the state and ARIA contract behind every cngx button: the shipped hosts (`cngxButton`, `cngxIconButton`, `cngxCloseButton`, `cngxMenuButton`, `cngxIconMenuButton`, `cngxActionButton`, `cngxPopoverAction`, `cngxPopoverDismiss`, `cngxPanelToggle`) and any custom host you build on it. It reads a few static facts about its host from the `CNGX_BUTTON_HOST` token: the selector name it prints in development diagnostics and hands to the `aria-describedby` registry, the variant it falls back to, the axes the host pins and whether the host is icon-only (which turns on the accessible-name check, [CNGX1071](cngx1071.html)). Without the descriptor none of that can be resolved, so the brain throws while it is created instead of rendering a button with an unknown default.

```ts
// ERROR: the brain is declared, the descriptor is not
@Component({
  selector: 'button[appChipButton]',
  hostDirectives: [{ directive: CngxButtonBrain, inputs: ['variant: appChipButton', 'disabled'] }],
  template: '<ng-content />',
})
class AppChipButton {}
```

### Fixing the error

Add `provideButtonHost` to the `providers` of the same component or directive that declares the brain:

```ts
@Component({
  selector: 'button[appChipButton]',
  hostDirectives: [{ directive: CngxButtonBrain, inputs: ['variant: appChipButton', 'disabled'] }],
  providers: [provideButtonHost('appChipButton', { defaultVariant: 'outline' })],
  template: '<ng-content />',
})
class AppChipButton {}
```

The first argument is the public selector name, the second the descriptor: `defaultVariant` is required, `fixed` pins axes against the group and the config, and `iconOnly: true` marks a host without visible text.

### Debugging the error

The message names the element the brain sits on, for example `CNGX1075: [cngxButtonBrain] on <button> has no host descriptor.` In a production build the message is the bare code `CNGX1075`; the check still runs there.

The descriptor is looked up on the brain's own element only. A `provideButtonHost` on an ancestor, in `viewProviders`, or on a wrapper component does not count; it has to sit in the `providers` of the component or directive whose `hostDirectives` list the brain.
