# CNGX1079

## Hotkey on Ctrl+Alt collides with AltGr

This warning is emitted when a binding is registered in the hotkey registry from `@cngx/common/interactive` with a combo that names `ctrl` or `mod` together with `alt`, such as `ctrl+alt+e` or `mod+alt+k`.

Windows and Linux report the AltGr key as Ctrl plus Alt. Layouts such as German, French or Polish type characters through AltGr (`€`, `@`, `{`), so `matchesKeyCombo` reads every press with AltGr held as character input and never matches it to a Ctrl+Alt combo. Without that guard, typing `€` would trigger the binding. The consequence: on those layouts a Ctrl+Alt binding cannot be pressed at all. On macOS (`mod` is Cmd, there is no AltGr) it works. Nothing throws.

```ts
// WARNING: never fires for a user typing on a German layout
injectHotkey({ id: 'export', combo: 'ctrl+alt+e', run: () => exportFile() });
```

### Fixing the warning

Use Ctrl+Shift or `mod+shift` instead, which no layout reserves for characters.

```ts
injectHotkey({ id: 'export', combo: 'mod+shift+e', run: () => exportFile() });
```

### Debugging the warning

The message starts with `CNGX1079: createHotkeyRegistry(): hotkey "<id>" uses "<combo>"; Ctrl+Alt is AltGr on Windows and Linux,`. The context object carries the id and the combo. It is emitted on every platform, because the same combo string ships to every user.

The check runs in development mode only, at registration. In production the binding registers the same, without a warning.
