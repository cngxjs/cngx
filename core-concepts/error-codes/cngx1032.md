# CNGX1032

## Root selector matched no element

This warning is emitted when the `[root]` input of `[cngxIntersectionObserver]`, `[cngxInfiniteScroll]` or `[cngxScrollSpy]` holds a CSS selector that matches nothing in the document.

All three directives build an `IntersectionObserver`. `[root]` names the scroll container the observer measures against; the directive resolves it with `document.querySelector(root)` each time it (re)creates the observer. When the selector finds nothing, the directive does not fail: it passes `root: null`, which means the viewport.

Inside a scrolling panel that is the wrong reference. The observed elements move inside the panel while the panel itself stays put in the viewport, so intersection changes fire late, early or not at all: `[cngxInfiniteScroll]` stops loading the next page, `[cngxScrollSpy]` highlights the wrong section, and `(intersectionChange)` reports a state the user does not see.

```html
<!-- WARNING: the panel has class "results", not "result-list" -->
<div class="results" style="overflow-y: auto; block-size: 30rem">
  @for (row of rows(); track row.id) { <app-row [row]="row" /> }
  <div cngxInfiniteScroll root=".result-list" (loadMore)="loadMore()"></div>
</div>
```

### Fixing the warning

#### Option 1: Fix the selector

Point `[root]` at the element that actually scrolls. The selector is matched against the whole document, so give the container a class or id that is unique on the page:

```html
<div class="result-list" style="overflow-y: auto; block-size: 30rem">
  ...
  <div cngxInfiniteScroll root=".result-list" (loadMore)="loadMore()"></div>
</div>
```

#### Option 2: Bind the selector once the container exists

The selector is resolved when the observer is created, not on every scroll. If the container renders later than the directive (inside an `@if`, a deferred block or an async view), bind `[root]` only once it is there, so the change re-creates the observer:

```html
<div cngxIntersectionObserver [root]="panelReady() ? '#panel' : null"></div>
```

#### Option 3: Drop `[root]`

If the content scrolls with the page, leave `[root]` unbound. The viewport is then the intended root and nothing is logged.

### Debugging the warning

The message starts with `CNGX1032: ` and the directive (`[cngxIntersectionObserver]`, `[cngxInfiniteScroll]` or `[cngxScrollSpy]`) and quotes the selector that matched nothing. For example `CNGX1032: [cngxScrollSpy] root selector "#toc-scroller" matched no element - falling back to the viewport.` Run `document.querySelector('<selector>')` in the browser console on the same page to confirm it returns `null`.

The check runs in development mode only, each time the directive re-creates its observer: on the first render and whenever `[root]`, `[rootMargin]` or `[threshold]` changes (for `[cngxInfiniteScroll]` also `[enabled]` and `[debounceMs]`; for `[cngxScrollSpy]` also the section list). It is not deduplicated, so a selector that never matches logs again on every re-creation. `[cngxScrollSpy]` checks the root only when at least one section was found; a spy with no sections logs [CNGX1033](cngx1033.html) instead.
