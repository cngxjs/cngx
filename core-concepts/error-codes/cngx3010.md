# CNGX3010

## Sidenav auto mode without a layout

This warning is emitted when a `<cngx-sidenav>` resolves its `mode` to `'auto'` and no `CNGX_CONTAINER_SIZE` provider sits above it, which means it is not inside a `<cngx-sidenav-layout>` and not inside an element with `[cngxContainer]`. `'auto'` is the default, so a sidenav with no `mode` binding is affected.

In `auto` mode the sidenav docks beside the content (`side`) when its layout is at least `64rem` wide and overlays it (`over`) below that. The sidenav does not measure anything itself. `<cngx-sidenav-layout>` is a named query container, and a `@container cngx-sidenav-layout (min-inline-size: 64rem)` rule in its stylesheet sets `--cngx-sidenav-layout-wide: 1` on the rail. The sidenav reads that resolved custom property through the container-size service that `CngxContainer` provides. Without that service there is nothing to read.

The sidenav then renders as `over` at every width: a modal overlay with a focus trap, closed by default, even on a wide desktop where you expected a docked rail. Nothing fails; the layout simply never docks.

```html
<!-- WARNING: no <cngx-sidenav-layout> around the rail, mode defaults to 'auto' -->
<div class="shell">
  <cngx-sidenav [ariaLabel]="navLabel()">...</cngx-sidenav>
  <main>...</main>
</div>
```

### Fixing the warning

#### Option 1: Wrap the sidenav in a layout

`<cngx-sidenav-layout>` provides the container, the breakpoint rule, the shared backdrop and scroll lock. The sidenav must be a direct child, because the breakpoint rule targets `cngx-sidenav-layout > cngx-sidenav`:

```html
<cngx-sidenav-layout>
  <cngx-sidenav [ariaLabel]="navLabel()">...</cngx-sidenav>
  <cngx-sidenav-content>...</cngx-sidenav-content>
</cngx-sidenav-layout>
```

#### Option 2: Pin a mode

If the sidenav lives outside a layout on purpose, set the mode it should always use: `mode="over"`, `"push"`, `"side"` or `"mini"`. An explicit mode does not need a container and does not warn.

### Debugging the warning

The message reads `[cngx-sidenav] auto mode needs a <cngx-sidenav-layout> (or [cngxContainer]) ancestor; rendering as over.` It does not identify the instance; check every `<cngx-sidenav>` without an explicit `mode`.

The check runs in development mode only, once per sidenav, after the first render. It reads `mode` at that moment, so switching to `'auto'` later does not warn.

A plain `[cngxContainer]` ancestor silences the warning but does not by itself make `auto` mode respond to width: nothing sets `--cngx-sidenav-layout-wide` unless you add your own `@container` rule that sets it to `1` on the `cngx-sidenav` element. Without such a rule, the rail stays `over` with no warning.
