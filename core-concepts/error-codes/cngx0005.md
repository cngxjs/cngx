# CNGX0005

## Language pack provided below the root injector

This warning is emitted when `provideCngxI18n()` from `@cngx/core/i18n` runs in a child environment injector, such as a lazy route's `providers`, instead of the application config.

The copy of every cngx lib is resolved once in the root injector and reads the root pack. A second `provideCngxI18n()` in a child injector still provides its own `CNGX_LANGUAGE_PACK`, `CNGX_LOCALE` and `CNGX_DIRECTION` for that subtree and rewrites `<html lang>` / `<html dir>` for the whole document, but the labels, announcements and messages the libs already resolved stay on the root pack.

The result is a mixed page: numbers, dates and the writing direction follow the child pack, while the text stays in the root language. Nothing throws.

```ts
export const routes: Routes = [
  {
    path: 'de',
    // WARNING: switches locale and direction here, but not the copy
    providers: [provideCngxI18n(withPack(CNGX_LANGUAGE_DE))],
    loadChildren: () => import('./de/routes'),
  },
];
```

### Fixing the warning

Call `provideCngxI18n()` once, in the application config, and remove the call from the child injector. Then pick the tool for what the child call was meant to do.

#### Option 1: Different copy in one subtree

Use the per-token overrides there, for example `provideTabsI18n(withTabsI18nLabels(...))` from `@cngx/common/tabs`. They apply on top of the pack, key by key, also in a subtree:

```ts
providers: [provideTabsI18n(withTabsI18nLabels({ tabsLabel: 'Bereiche' }))],
```

#### Option 2: Different number and date format in one subtree

Use `provideLocaleAt(...)` from `@cngx/core/utils`. It scopes `CNGX_LOCALE` to that DI subtree and leaves the copy and the document language alone:

```ts
providers: [provideLocaleAt('de-AT')],
```

#### Option 3: Switching the whole app's language at runtime

Pass a `Signal` to `withPack` (or `withPartialPack`) in the application config and set it from the part of the app that changes the language:

```ts
const pack = signal<CngxCompleteLanguagePack | undefined>(undefined);
bootstrapApplication(App, { providers: [provideCngxI18n(withPack(pack))] });

// later, when the user picks German
pack.set((await import('@cngx/core/i18n/de')).CNGX_LANGUAGE_DE);
```

See "One pack per app" in the i18n guide.

### Debugging the warning

The message is fixed text and names no route or injector: `provideCngxI18n() in a child injector switches the locale and the direction but not the copy`. Search the code for every `provideCngxI18n(` call; all but the one in the application config are candidates. Route `providers` and `createEnvironmentInjector` calls are the usual places.

The check runs in development mode only, through an environment initializer, so it fires once each time a child environment injector with the call is created, for example on the first navigation into the lazy route. It compares that injector with `ApplicationRef.injector` and nothing else; a call in the application config never warns.
