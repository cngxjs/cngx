# CNGX3009

## Data-grid-accordion row has more cells than columns

This warning is emitted when a `<cngx-dga-row>` inside `<cngx-data-grid-accordion>` projects more `[cngxDgaCell]` cells than the accordion's column source has.

The accordion lays every band (header, rows, footer) on one shared CSS grid: each band is a subgrid of the host's `grid-template-columns`, published as `--cngx-dga-columns`. The column count comes from a single source, the cells of `<cngx-dga-header>`, or the cells of the first row when there is no header. Each source cell's `col` intent (`sm`, `md`, `grow` and so on) becomes one track.

A row with more cells than tracks pushes the extra cells into implicit grid tracks that the header does not have. The columns stop lining up: the extra cell wraps or squeezes into an auto-sized track, and the row no longer reads as part of the table. There is no error and nothing is clipped, so it is easy to miss with short test data.

```html
<cngx-data-grid-accordion>
  <cngx-dga-header>
    <span cngxDgaCell col="sm">{{ idLabel() }}</span>
    <span cngxDgaCell col="grow">{{ nameLabel() }}</span>
  </cngx-dga-header>

  <!-- WARNING: three cells, but the header defines two columns -->
  <cngx-dga-row panelId="1">
    <span cngxDgaCell>INV-1</span>
    <span cngxDgaCell primary>Northwind Traders</span>
    <span cngxDgaCell align="end">$1,280</span>
    ...
  </cngx-dga-row>
</cngx-data-grid-accordion>
```

### Fixing the warning

#### Option 1: Add the column to the header

Every column needs a header cell, even when its label is empty. Add the missing cell with its track intent:

```html
<cngx-dga-header>
  <span cngxDgaCell col="sm">{{ idLabel() }}</span>
  <span cngxDgaCell col="grow">{{ nameLabel() }}</span>
  <span cngxDgaCell col="md" align="end">{{ amountLabel() }}</span>
</cngx-dga-header>
```

#### Option 2: Move the extra content into the panel

If the value belongs to only some rows, it is detail, not a column. Leave it out of the cells and put it in the row's panel content, the part that shows when the row expands.

### Debugging the warning

The message names the cell count of the first offending row and the track count, for example `CNGX3009: [cngx-data-grid-accordion] a row projects 3 cells but the shared column template has 2 tracks`. It does not name the row; look for rows whose cells are rendered conditionally (`@if` around a cell) or built in a `@for`, since those are the rows whose count changes with the data.

The check runs in development mode only, inside an effect, and destroys itself after the first warning: one warning per accordion, however many rows overflow, and later rows added at runtime are not reported after that. Rows with fewer cells than tracks are not reported; they leave the trailing columns empty. The track count comes from the header (or first-row) cells, or from the `[columns]` input when it is set: line names are skipped and `repeat(n, ...)` is expanded. A `[columns]` value whose track count is not fixed (`repeat(auto-fill, ...)`, `subgrid`) is not checked.
