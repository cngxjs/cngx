# CNGX3006

## Mat-tabs aggregator slot half-wired

This warning is emitted when the aggregator decoration behind `[cngxMatTabs]` is set up with only one of the two inputs its template path needs: the slot template (from `<ng-template cngxMatTabAggregatorContent>`) or the `ViewContainerRef` that mounts it.

The aggregator decoration writes a visually hidden descriptor span onto each Material tab button whose panel reports errors, and links it through `aria-describedby`. The descriptor has two render paths. With a template and a view container, it renders an embedded view of your `*cngxMatTabAggregatorContent` template per tab. Without them, it writes the aggregator's announcement string as plain text. A half-wired setup cannot render the template, so the projector falls back to plain text. Because that fallback is graceful, a diagnostic sink is the only signal that the template is being ignored.

The consequence is silent: screen reader users hear the default announcement instead of the copy in your template. Nothing changes visually.

```ts
// WARNING: internal setup reached with a template but no view container
createMatTabAggregatorDecoration({ /* ... */, contentTemplate, viewContainerRef: undefined });
```

### Fixing the warning

#### Option 1: Report it as a cngx bug

`createMatTabAggregatorDecoration` is internal. `[cngxMatTabs]` always passes both halves: the slot is read as a signal from the projected `<ng-template cngxMatTabAggregatorContent>` (which may resolve to `null` when no template is projected; that is not half-wired), and the view container is the directive's own. There is no consumer input that supplies either half on its own. If you see this warning with `[cngxMatTabs]` as shipped, report it with the template you project.

#### Option 2: Route the condition to your own sink

The sink is configurable. In development the default prints this warning; in production the default is silent. To forward the condition to telemetry or fail a test run, install your own sink:

```ts
provideMatTabsConfig(
  withHalfWiredSlotSink((missing) => logger.warn('cngx mat-tabs half-wired slot', missing)),
);
```

`provideMatTabsConfigAt(...)` scopes the sink to one component subtree.

### Debugging the warning

The message names the missing half in backticks: `contentTemplate` or `viewContainerRef`. The check runs once, when `[cngxMatTabs]` creates the aggregator decoration in its constructor, not on every error change. With a custom sink installed through `withHalfWiredSlotSink`, this code is not printed at all; your sink receives the same `missing` value instead.

The rejection decoration (`*cngxMatTabRejectionContent`) has the same two-path design but no half-wired diagnostic. For decorations that never appear at all, see [CNGX3005](cngx3005.html).
