# CNGX2002

## Filter builder has no fields

This warning is emitted when `<cngx-filter-builder>` (or any host of `CngxFilterBuilderPresenter`) has rendered and its `fields` input is an empty array.

Every expression row binds one field, one operator and one value, and the field list is where the row's field picker, its operator list and its value editor come from. The add-filter button creates a new row with the first entry of `fields`; with no entries it has nothing to create the row from and does nothing.

So the builder renders, but stays in its empty state for good: the add-filter button is visible and clickable, and clicking it silently changes nothing. A common cause is a field list that loads asynchronously and starts as `[]`:

```html
<!-- WARNING: fields() is [] on the first render -->
<cngx-filter-builder [fields]="fields()" [(value)]="filter" />
```

### Fixing the warning

#### Option 1: Render the builder once the fields are there

```html
@if (fields().length > 0) {
  <cngx-filter-builder [fields]="fields()" [(value)]="filter" />
}
```

The check runs once, after the first render, so a list that arrives later still triggers it unless the builder waits for it.

#### Option 2: Pass the field list you meant to pass

If the list is static, check that `[fields]` is bound to the populated array and not to a placeholder. Each entry needs a `key` that matches a property of your items, a `label` (copy, from your own i18n) and an `editorType`.

### Debugging the warning

The message carries no identifier; it reads `[CngxFilterBuilder] no fields provided`. Look for builders whose `fields` binding can be empty at the time the component first renders.

The check runs in development mode only, once per builder instance, after its first render. It does not re-run when `fields` changes later, so the warning can describe a state that was already corrected. A missing `[fields]` binding is a different failure: `fields` is a required input, and reading it unbound throws Angular's NG0950. When the field list is present but the bound `value` names keys that are not in it, see [CNGX2003](cngx2003.html).
