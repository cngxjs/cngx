# CNGX1023

## Option without a label

This error is reported when a `CngxOption` (`[cngxOption]`, or `<cngx-option>` inside a select shell) has no `[label]` and no text content after the first render.

`CngxOption` resolves its `label` signal from the `[label]` input and falls back to the element's trimmed `textContent`. Several consumers read that one signal: typeahead matching, the search filter of a select shell, the trigger text of a select once the option is chosen, and the `{ value, label }` record a projected option contributes to the select's option model.

An option whose label is empty still renders and can still be clicked, but it has no text to match, so typeahead and search skip it, and after selection the select trigger shows nothing. Assistive technology computes the option's name from its content, so an option that contains only an icon or an image without `alt` text is announced as an unnamed option.

```html
<cngx-select-shell [label]="languageLabel()">
  <!-- ERROR: an image with empty alt text is no label -->
  <cngx-option value="en"><img src="flag-en.svg" alt="" /></cngx-option>
</cngx-select-shell>
```

### Fixing the error

#### Option 1: Give the option text content

Text inside the option is both its visible label and its name:

```html
<cngx-option value="en">{{ languageNames().en }}</cngx-option>
```

#### Option 2: Bind `[label]` next to visual content

When the option content is visual, set `[label]` for typeahead, search and the trigger, and give the visual content a text alternative for screen readers:

```html
<cngx-option value="en" [label]="languageNames().en">
  <img src="flag-en.svg" [alt]="languageNames().en" />
</cngx-option>
```

Labels are user-facing copy; route them through your own i18n.

### Debugging the error

The message names the option by its generated id, for example `CNGX1023: [cngxOption] option cngx-option-12 has no label and no textContent`. That id is the `id` attribute on the option element (the one `aria-activedescendant` points at); search the rendered DOM for it. The message says `<cngx-option>` for the `[cngxOption]` attribute form too.

The check runs in development mode only, once per option, after the first render. The text content is captured at that moment and not re-read: an option whose text arrives later (an async pipe, a deferred block) logs this error and keeps an empty fallback label, so bind `[label]` for dynamic text. An `aria-label` on the option is not read by this check.
