# CNGX1012

## Per-index size estimate on a large recycler

This warning is emitted when `injectRecycler` gets `estimateSize` as a plain `(index) => number` function and `totalCount()` returns more than 10 000 items when the recycler is created.

`estimateSize` takes three forms: a fixed `number`, a `Signal<number>` for one reactive uniform height, or a function that returns a height per index. In list mode the recycler resolves item heights through a size cache: a measured height wins, otherwise it falls back to `estimateSize`. To place the rendered window, it walks every item and sums those heights, and it repeats that walk whenever the scroll position, the viewport height, the item count or a measurement changes. With a per-index function, each walk calls your function once per unmeasured item, so every scroll frame runs your code n times, including any signal reads and lookups inside it.

On a short list the cost does not matter. On a long one, each scroll frame spends time in your function proportional to the list length, and on lower-end devices the rendered window starts to lag behind the scroll position. Nothing fails:

```ts
// WARNING: a per-index function over 50 000 rows
readonly recycler = injectRecycler({
  scrollElement: '.log-scroll',
  totalCount: () => this.entries().length,
  estimateSize: (index) => (this.entries()[index].expanded ? 96 : 32),
});
```

### Fixing the warning

#### Option 1: Use a uniform estimate and measure the real heights

Pass one typical height and let `[cngxMeasure]` record the real height of each rendered row. Measured heights go into the size cache and replace the estimate for that index, and unmeasured items cost a constant instead of a call into your code:

```ts
readonly recycler = injectRecycler({
  scrollElement: '.log-scroll',
  totalCount: () => this.entries().length,
  estimateSize: 32,
});
readonly visibleEntries = this.recycler.sliced(this.entries);
```

```html
@for (entry of visibleEntries(); track entry.id; let i = $index) {
  <div [cngxMeasure]="recycler" [cngxMeasureIndex]="recycler.start() + i">
    ...
  </div>
}
```

`CngxMeasure` and `injectRecycler` come from `@cngx/common/data`.

#### Option 2: Use a signal for a reactive uniform estimate

When the typical height depends on state, such as a density setting, pass a `Signal<number>`. A signal resolves to one value for every index, so each item costs a signal read instead of a call into your code, and the warning does not fire.

### Debugging the warning

The message includes the item count at creation time, for example `CNGX1012: injectRecycler(): estimateSize as a function with 50000 items`. It does not name the component; search for `injectRecycler` calls whose `estimateSize` is an arrow function or a method reference.

The check runs in development mode only, once per `injectRecycler` call, and reads `totalCount()` only at that moment. A list that starts empty and loads its data asynchronously is never reported, however large it grows; check those call sites by hand. The fixes reduce the cost per item; the list-mode walk over all items itself remains, so a very long list still pays a linear pass per recompute.
