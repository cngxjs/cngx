# CNGX1063

## Paginate add-on without a paginate directive

This error is thrown when `[cngxPaginateResetOn]` or `[cngxPaginateRouting]` from `@cngx/common/data` is created without a `[cngxPaginate]` on the same element or above it.

Both add-ons extend a `CngxPaginate` they find in the element tree. `[cngxPaginateResetOn]` jumps back to the first page when its key changes, for example a filter term. `[cngxPaginateRouting]` mirrors the page index and page size into the URL. Neither holds a page index of its own. `<cngx-paginator>`, `<cngx-incremental-list>` and `[cngxMatPaginator]` carry `CngxPaginate` for you. Without one the add-on has no page to reset or sync, so the constructor throws instead of leaving a filter that keeps a stale page or a URL that is never written.

```html
<!-- ERROR: the reset sits on a sibling of the paginator, not on it -->
<input [cngxPaginateResetOn]="query()" />
<cngx-paginator [total]="total()" />
```

### Fixing the error

Put the add-on on the element that carries `CngxPaginate`, or inside it:

```html
<cngx-paginator [total]="total()" [cngxPaginateResetOn]="query()" cngxPaginateRouting />
```

```html
<div cngxPaginate [total]="total()" [cngxPaginateResetOn]="query()">...</div>
```

### Debugging the error

The message names the add-on, for example `CNGX1063: [cngxPaginateResetOn] must be placed on or inside an element with [cngxPaginate], such as <cngx-paginator>.` In a production build the message is the bare code `CNGX1063`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A parent that another component renders in its own template, around content you project into it, is not above the projected element. A missing `Router` for `[cngxPaginateRouting]` is a different case: it is reported as the warning [CNGX1031](cngx1031.html), and the directive becomes a no-op.
