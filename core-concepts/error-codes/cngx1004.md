# CNGX1004

## DOM-event key bound on `[cngxAudioStatus]`

This error is reported when the `[cngxAudioStatus]` binding contains a DOM-event key: `click`, `focus`, `blur`, `pointerenter`, `pointerleave`, `submit`, `change` or `input`.

`[cngxAudioStatus]` plays earcons on async-state transitions. It watches the status of a `CngxAsyncState` and plays the earcon mapped to the status it moves into. The accepted keys are `idle`, `loading`, `pending`, `refreshing`, `success` and `error`, plus the aliases `succeeded` and `failed`. The directive attaches no DOM listeners at all, so an event key is set aside by the parser and has nothing to fire it.

The status pairs in the same binding keep working; the event earcon simply never plays:

```html
<!-- ERROR: "click" is a DOM event, not a status -->
<button
  type="button"
  [cngxAsyncClick]="save"
  #saveClick="cngxAsyncClick"
  [cngxAudioStatus]="'click:tap, succeeded:success'"
  [state]="saveClick.state"
>
  Save
</button>
```

### Fixing the error

#### Option 1: Move the event keys to `[cngxAudio]`

Both directives can sit on the same element. Keep the events on `[cngxAudio]` and the statuses on `[cngxAudioStatus]`:

```html
<button
  type="button"
  [cngxAsyncClick]="save"
  #saveClick="cngxAsyncClick"
  [cngxAudio]="'click:tap'"
  [cngxAudioStatus]="'succeeded:success, failed:error'"
  [state]="saveClick.state"
>
  Save
</button>
```

### Debugging the error

The message lists the offending keys, for example `DOM-event keys "click" are not lifecycle statuses`. Search for `[cngxAudioStatus]` bindings that contain them.

The check runs in development mode only, once per directive instance, after the first render, against the binding value at that moment. Keys that are neither statuses nor events are ignored without a message. The reverse mistake, a status key on `[cngxAudio]`, is [CNGX1002](cngx1002.html). A missing state source on the same directive is [CNGX1005](cngx1005.html).
