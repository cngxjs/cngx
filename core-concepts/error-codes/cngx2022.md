# CNGX2022

## Display-shaped value written to a raw value channel

This warning is emitted when a value written into `cngxInputMask` or `cngxNumericInput` from `@cngx/forms/input` has the shape of the display text instead of the raw value the directive stores.

Both directives keep two values apart: the text in the element and the raw value in their `value` model, which is also what a bound form holds. For `cngxInputMask` the raw value is the slot characters only, `'1430'` for the mask `00:00`, never the display string `'14:30'`. For `cngxNumericInput` it is a `number` or `null`, never a formatted string such as `'1.234,5'`.

A write from your code reaches the model as given: `control.setValue(...)` through `CngxFormBridge`, a Signal Forms model update, or a `[(value)]` binding. Neither directive rewrites it, because normalising on write would change your form state behind your back (the control would emit and turn dirty without a user edit). So a display-shaped value stays in the form: a mask keeps its literals in the value and renders a shifted display, a numeric input treats the string as empty.

```ts
readonly at = new FormControl('', { nonNullable: true });
// <input cngxInputMask="00:00" [formControl]="at" />

this.at.setValue('14:30'); // WARNING: display string, the form now holds '14:30'
```

### Fixing the warning

#### Option 1: Write the raw value

Strip the literals before you write to a masked input, and parse to a number before you write to a numeric input:

```ts
this.at.setValue('1430'); // mask 00:00
this.amount.setValue(1234.5); // numeric input
```

When the value comes from an API in display form, convert it at the boundary where it enters the form, for example `value.replace(/\D/g, '')` for a digits-only mask.

#### Option 2: Let the user type it

A value the user types always goes through the mask or the number parser, so typed input never triggers this warning. Only programmatic writes need the raw shape.

### Debugging the warning

The message starts with `CNGX2022: [cngxInputMask]` or `CNGX2022: [cngxNumericInput]`. It never repeats the written value, since masked fields often hold phone numbers or account IDs; the element is passed as the second console argument instead. Inspect it in the browser console and look for the code that writes that field's form control or model.

The check runs in development mode only and warns once per directive instance, on the first display-shaped value it sees; later writes to the same input are not reported again. For a mask preset whose region table loads lazily (`phone`, `date`, `iban`, `zip`), the check waits until the table has loaded, so a value that is valid for the real pattern is not flagged against the temporary fallback.

`cngxInputFormat` is not covered: its raw value is free text, and telling a raw value from a formatted one would need `parse` to be the exact inverse of `format`. Write the unformatted value there too; `setValue('$77')` under a `$` formatter renders `$$77`.
