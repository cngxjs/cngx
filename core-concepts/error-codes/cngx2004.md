# CNGX2004

## Filter group exceeds the maximum nesting depth

This warning is emitted when `addGroup(path, group)` is called on `CngxFilterBuilderPresenter` at a path where the new group would sit deeper than the configured `maxNestingDepth` (default 8).

The root group is depth 0, and a group added under the group at `path` lands at depth `path.length + 1`. The builder's own add-group button reads the same limit: it is disabled once the next group would cross it, so the user cannot build a deeper tree from the UI. `addGroup` enforces the limit for programmatic calls the same way, so code cannot build a tree the UI would refuse.

When the limit is hit, the call is ignored and the tree stays as it was. Nothing throws, so code that assumes the group now exists, for example by writing expressions into it at `[...path, index]`, writes to a path that does not exist:

```ts
private readonly builder = viewChild(CngxFilterBuilderPresenter);

addNested(): void {
  // WARNING: path.length is 8, so the new group would sit at depth 9
  this.builder()?.addGroup([0, 0, 0, 0, 0, 0, 0, 0], createFilterGroup('or'));
}
```

### Fixing the warning

#### Option 1: Add the group at a shallower path

Most deep paths come from code that nests a new group into the last group on every call. Add sibling groups instead, or flatten the structure the code produces.

#### Option 2: Raise the limit

When deeper trees are intended, raise `maxNestingDepth` for the builder:

```ts
import { provideFilterBuilderConfig, withMaxNestingDepth } from '@cngx/forms/filter-builder';

provideFilterBuilderConfig(withMaxNestingDepth(12));
```

Use `provideFilterBuilderConfigAt(withMaxNestingDepth(12))` in a component's `providers` to raise it for one builder only. The add-group button follows the new limit too.

### Debugging the warning

The message names the depth the group would have had and the active limit, for example `CNGX2004: [cngxFilterBuilderPresenter] addGroup at depth 9 exceeds maxNestingDepth 8 - ignored`. If the limit shown is not the one you configured, the builder resolves `CNGX_FILTER_BUILDER_CONFIG` from a different injector than the one you provided it in.

The check runs on every `addGroup` call; the warning text is emitted in development mode only, but the call is ignored in production too. It only covers `addGroup`: a tree bound through `[(value)]` that is already deeper than the limit is accepted as is, and the add-group buttons inside it are disabled. The builder's add-group button never reaches this warning, because it checks the limit before calling `addGroup`.
