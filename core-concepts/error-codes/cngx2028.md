# CNGX2028

## Grouped options under a configured virtualization

This warning is emitted when a select panel renders grouped options while a virtualising panel renderer is configured, for example through `provideSelectConfig(withVirtualization({...}))` or a custom `CNGX_PANEL_RENDERER_FACTORY`.

Virtualization windows a flat option list: the recycler renders a contiguous slice and reserves the remaining scroll height with spacer divs. Groups break that model. A windowed slice cannot start and end on clean group boundaries, and the aria-setsize / aria-posinset counting is per group, not per flat index. The panel therefore renders grouped options in full and bypasses the renderer, so the configured virtualization has no effect on them. The spacer divs are dropped too (there is no window to pad), which is why a grouped list under virtualization never shows `.cngx-select__virtual-spacer`.

```ts
// WARNING: virtualization is configured, but the options are grouped,
// so the window and its spacers are dropped and every option renders.
bootstrapApplication(App, {
  providers: [provideSelectConfig(withVirtualization({ threshold: 200 }))],
});
```

```html
<cngx-select [label]="'Team'" [options]="groupedOptions" />
```

### Fixing the warning

Pick one model per select. For a large list, flatten the options so the window applies:

```ts
readonly options = computed(() => this.teams().flatMap((t) => t.members));
```

For a grouped list, drop the virtualization config for that select - grouped lists are small enough to render in full:

```ts
provideSelectConfigAt(withVirtualization(false));
```

### Debugging the warning

The message starts with `CNGX2028: Grouped select options ignore the configured virtualization` and fires once per panel instance, the first time an open panel's rendered items contain a group. The check runs in development mode only. In production the panel renders the same - grouped options in full, no spacers - without a warning.
