# CNGX1080

## Unparseable hotkey combo

This warning is emitted when a binding is registered in the hotkey registry from `@cngx/common/interactive` with a combo string the registry cannot read.

A combo is modifiers and one key joined by `+`: the modifiers are `ctrl`, `meta`, `mod`, `shift` and `alt`, the key is a character (`k`, `?`, `+`) or a key name (`escape`, `enter`, `arrowup`, `f2`, `space`). A combo with an unknown modifier (`hyper+k`), a missing key (`ctrl+`) or only modifiers (`ctrl+shift`) is rejected, and the binding never fires. It is not read loosely, because `hyper+k` read as a bare `k` would fire on every typed k. The binding stays registered; nothing throws.

```ts
// WARNING: never fires
injectHotkey({ id: 'zoom.in', combo: 'ctrl+', run: () => zoomIn() });
```

### Fixing the warning

Name exactly one key after the modifiers. The literal plus key is written as a trailing `++`.

```ts
injectHotkey({ id: 'zoom.in', combo: 'ctrl++', run: () => zoomIn() });
```

### Debugging the warning

The message starts with `CNGX1080: [CngxHotkeyRegistry] hotkey "<id>" has the unparseable combo "<combo>"; it never fires.` The context object carries the id and the combo.

The check runs in development mode only, at registration. In production the binding registers the same, without a warning, and does not fire.
