# CNGX1002

## Lifecycle key bound on `[cngxAudio]`

This error is reported when the `[cngxAudio]` binding contains an async-status key: `idle`, `loading`, `pending`, `refreshing`, `success`, `succeeded`, `error` or `failed`.

`[cngxAudio]` maps DOM events to earcons. It parses its `event:earcon` pairs and adds one `addEventListener` call per recognised event (`click`, `focus`, `blur`, `pointerenter`, `pointerleave`, `submit`, `change`, `input`). A status key is not a DOM event, so the parser sets it aside and no listener is ever attached for it. Status transitions are the job of the sibling directive `[cngxAudioStatus]`, which watches a `CngxAsyncState`.

Nothing throws. The rest of the binding keeps working, and the status earcon never plays:

```html
<!-- ERROR: "success" is a status, not a DOM event -->
<button type="button" [cngxAudio]="'click:tap, success:complete'">Save</button>
```

### Fixing the error

#### Option 1: Move the status keys to `[cngxAudioStatus]`

Keep the DOM events on `[cngxAudio]` and put the status keys on `[cngxAudioStatus]` on the same host. `[cngxAudioStatus]` needs a state to watch; here it comes from the `[cngxAsyncClick]` on the same button:

```html
<button
  type="button"
  [cngxAsyncClick]="save"
  #saveClick="cngxAsyncClick"
  [cngxAudio]="'click:tap'"
  [cngxAudioStatus]="'success:complete, error:error'"
  [state]="saveClick.state"
>
  Save
</button>
```

`save` is a component method that returns a `Promise` or an `Observable`. `CngxAudio` and `CngxAudioStatus` come from `@cngx/common/audio`, `CngxAsyncClick` from `@cngx/common/interactive`.

### Debugging the error

The message lists the offending keys, for example `CNGX1002: [cngxAudio] Lifecycle keys "success" are not DOM events`. Search for `[cngxAudio]` bindings that contain them.

The check runs in development mode only, once per directive instance, after the first render. It parses the binding as it stands at that moment; a later change to the bound string is not checked again. Keys that are neither events nor statuses are reported separately as [CNGX1003](cngx1003.html). The reverse mistake, a DOM event on `[cngxAudioStatus]`, is [CNGX1004](cngx1004.html).
