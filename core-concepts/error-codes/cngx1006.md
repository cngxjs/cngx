# CNGX1006

## Invalid Date bound to a timestamp

This warning is emitted when the `[date]` input of `<cngx-time>` or `<cngx-card-timestamp>` resolves to an Invalid Date.

Both components coerce `[date]` into a `Date`: a `Date` is used as is, anything else goes through `new Date(value)`. `<cngx-time>` accepts a `Date`, a string or an epoch-milliseconds number; `<cngx-card-timestamp>` accepts a `Date` or a string. When the result has a `NaN` time value, formatting it would fail: `toISOString()` throws and `Intl.DateTimeFormat` cannot format it. Both components guard against that and render nothing instead of breaking change detection.

The result is an empty `<time>` element with no `datetime` attribute. Nothing crashes, so the gap in the layout is the only visible sign. `new Date(string)` reliably parses ISO 8601 only; a locale-formatted string from the backend is the usual cause:

```html
<!-- WARNING: "13.10.2026" is not an ISO date, new Date() returns Invalid Date -->
<cngx-time [date]="'13.10.2026'" />
```

### Fixing the warning

#### Option 1: Pass a `Date` or an ISO 8601 string

Parse the value where it enters the app, in the API mapping, and bind the result:

```html
<cngx-time [date]="order.createdAt" />
<cngx-card-timestamp [date]="order.createdAt" [prefix]="createdLabel()" />
```

with `createdAt` as a `Date`, or as a string such as `2026-10-13` or `2026-10-13T09:30:00Z`. For `<cngx-time>`, an epoch timestamp in milliseconds works too. The `prefix` is copy, so route it through your own i18n.

#### Option 2: Render the component only when the value is valid

If the value can be missing or malformed, check it once in the component and render the timestamp only for a real date:

```ts
protected readonly createdAt = computed(() => {
  const date = new Date(this.order().createdAt ?? Number.NaN);
  return Number.isNaN(date.getTime()) ? null : date;
});
```

```html
@if (createdAt(); as createdAt) {
  <cngx-time [date]="createdAt" />
}
```

A plain `@if (order.createdAt)` is not enough: it filters a missing value, but a malformed string such as `'13.10.2026'` is truthy and still reaches the component.

### Debugging the warning

The message starts with `CNGX1006: ` and the component, `[cngx-time]` or `[cngx-card-timestamp]`, and says the bound value resolved to an Invalid Date. For `<cngx-time>` it reads `CNGX1006: [cngx-time] [date] resolved to an Invalid Date - rendering empty. Check the bound value (bad ISO string?).` It does not include the value; inspect the empty `<time>` element and read the binding of its host component, or log the value at its source.

The check runs in development mode only, per component instance. It warns each time the instance moves from a valid date to an invalid one, so one instance that stays invalid reports once, and a list of rows with the same bad field reports once per row. `undefined` behaves differently in the two components: `<cngx-time>` turns it into an Invalid Date and warns, while `<cngx-card-timestamp>` throws a `TypeError` before the check runs. `null` is not caught by `<cngx-time>` either: `new Date(null)` is the 1970 epoch, which is a valid date.
