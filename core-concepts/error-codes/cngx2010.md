# CNGX2010

## Filter path index out of range

This error is thrown when a `createFilterBuilderState` mutator from `@cngx/forms/filter-builder` receives a path whose index does not exist in the tree.

The filter builder stores its tree as nested `FilterGroup` and `FilterExpression` nodes and addresses a node by a path of child indexes: `[]` is the root group, `[2, 0]` is the first child of the root's third child. A mutator that edits or appends at a path walks it one index at a time; when a group has no child at the given index, there is no node to change. Writing anywhere else would edit a different filter than the caller meant, so the mutator throws.

```typescript
const state = createFilterBuilderState({ fields });
// the root has two children: indexes 0 and 1
state.setValue([2], 'Vienna'); // ERROR: CNGX2010
```

`addExpression`, `addGroup`, `setLogic`, `toggleNegated`, `setField`, `setOperator`, `setValue` and `applyFieldChange` check the path this way. `removeNode` does not: a path that resolves to nothing is a no-op there.

### Fixing the error

Build paths from the tree as it is now, not from an earlier snapshot. Read `state.tree()` or `state.getNodeAtPath(path)` before a mutation that runs later, for example after an await or a timer, and check that the node still exists.

### Debugging the error

The message shows the full path that failed. It starts with `CNGX2010: updateAtPath(): invalid path` followed by the path. In a production build the message is the bare code `CNGX2010`; the check still runs there.

Indexes shift when a node is removed: after `removeNode([0])` the former `[1]` is `[0]`. A path stored in a component and reused after a removal is the usual cause. Compare the path with `state.tree()` at the moment of the call; `state.lastMutation()` shows the change that ran before it.
