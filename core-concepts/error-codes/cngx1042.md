# CNGX1042

## Timeline date accessor produced an invalid date

This warning is emitted when the `dateAccessor` of a timeline grouping returns a value that is not a valid date for at least one item.

`createTimelineGrouping` (the default `CNGX_TIMELINE_GROUPING_FACTORY` behind `<cngx-timeline>`, which groups entries by day, week or month) reads a date from every item through `dateAccessor`, converts it to a `Date` and sorts the items into bands with a header such as "July 2026". A value that cannot be parsed (`undefined`, an empty string, `'31/07/2026'` in a format `Date` does not read) becomes an invalid `Date`. Nothing throws, and their position in the sort order is undefined. With `groupBy` set to `'day'`, `'week'` or `'month'`, all such items land together in one band whose header renders "Invalid Date". With `'none'` every item shares the one band anyway, so the invalid ones only sort unpredictably; a custom grouper function decides itself where an invalid date goes.

The type of `dateAccessor` accepts any string, so the usual cause is a value that type-checks and fails at runtime, such as a date string the API sends in a locale format:

```ts
// WARNING: the API sends "31/07/2026", which new Date() cannot parse
readonly grouping = createTimelineGrouping({
  items: this.events,
  dateAccessor: (event) => event.createdAt,
  groupBy: signal('month'),
});
```

### Fixing the warning

#### Option 1: Parse the raw value

If the source delivers dates in a format the `Date` constructor does not read, parse them in the accessor and return a `Date` or a timestamp:

```ts
dateAccessor: (event) => {
  const [day, month, year] = event.createdAt.split('/').map(Number);
  return new Date(year, month - 1, day);
},
```

#### Option 2: Read the right field

If the item type allows a loose value (an `any` from an untyped response, an index signature), make sure the accessor reads the field that holds the date, and type the response so a wrong field name fails to compile.

#### Option 3: Filter undated items

If some items legitimately have no date, filter them out of `items` before grouping, or render them in a separate list.

### Debugging the warning

The message starts with `createTimelineGrouping: dateAccessor produced an invalid date for at least one item`. It does not name the items; filter them in the console with `items.filter((item) => Number.isNaN(new Date(accessor(item)).getTime()))`, or look for the "Invalid Date" band in the rendered timeline.

The check runs in development mode only and logs at most once per grouping instance, the first time a computation finds an invalid date. Later recomputations stay silent even if the set of invalid items changes, so fix the accessor and reload rather than watching the console.
