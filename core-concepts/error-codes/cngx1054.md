# CNGX1054

## HTTP response without a body

This error is raised when `tapHttpAsyncState(state)` from `@cngx/common/data` receives the final HTTP response event with a `null` or missing body.

The operator wires an `HttpClient` request made with `observe: 'events'` into an async state: progress events drive `state.progress()`, and the final response sets `state.data()` to the response body. A `null` body would mark the request `success` with no data, so every consumer of `data()` would have to tell "loaded, nothing there" apart from "not loaded yet". The operator treats it as a failure instead.

Unlike most errors on these pages, this one does not escape into your code as an uncaught exception. The operator catches it in the same pipe and calls `state.setError(err)`, so the state moves to `error` and `state.error()` holds the `CngxRuntimeError`. The observable also errors, so an `error` callback on `subscribe` sees it too.

```typescript
// ERROR: DELETE /api/items/42 answers 204 No Content, so the body is null
this.http
  .delete(`/api/items/${id}`, { observe: 'events' })
  .pipe(tapHttpAsyncState(this.removal))
  .subscribe();
```

### Fixing the error

#### Option 1: Do not use the body operator for empty responses

`tapHttpAsyncState` is for requests whose result is the body: uploads, downloads, and other calls with progress. For a call that answers without content (`204`, or a `DELETE` / `PUT` that returns nothing), use `tapAsyncState` on a request without `observe: 'events'` and map the empty result yourself:

```typescript
this.http
  .delete(`/api/items/${id}`)
  .pipe(
    map(() => id),
    tapAsyncState(this.removal),
  )
  .subscribe();
```

#### Option 2: Make the server send a body

If the endpoint is meant to return data, a `null` body is a server-side bug. Fix the response, or check the request's `responseType`: a JSON request against an endpoint that returns an empty string parses to `null`.

### Debugging the error

What a user sees depends on what renders the error state. With `@cngx/ui` feedback (`CngxAlertOn`, `CngxToastOn`, `CngxBannerOn` with their error-detail input set, or `CngxActionButton`), the error detail comes from `withErrorDetail(...)`. Without a mapping, a development build shows the raw `Error.message`, here `CNGX1054: tapHttpAsyncState: response body is null` followed by the doc link, and a production build shows no detail.

In a production build the message is the bare code `CNGX1054`. Code that reads `err.message` from `state.error()`, such as a custom `withErrorDetail` mapping or an error logger, gets `CNGX1054` there. Branch on `err instanceof CngxRuntimeError && err.code === 'CNGX1054'` instead of matching the text.

Check the network panel for the response that ends the request: a `204` status or a `content-length: 0` header confirms an empty body.
