# CNGX1065

## Popover sheet on an auto popover

This warning is reported when a `[cngxPopoverSheet]` opens as a modal sheet or fullscreen panel on a `[cngxPopover]` whose `mode` is not `'manual'`.

The sheet never closes itself. A swipe on the header, a tap outside the panel and the Android back gesture arrive as `closeRequested` with a reason, so the consumer can keep the sheet open, for example while a save is pending. With `mode="auto"` the browser owns light dismiss: an outside tap or Escape hides the native popover directly, without `closeRequested`, and the consumer's dismiss policy never runs. The sheet still cleans up (the page is live again, the scroll lock is released), but the close could not be refused.

```html
<!-- WARNING: native light dismiss bypasses closeRequested -->
<div cngxPopover mode="auto" cngxPopoverSheet>
  ...
</div>
```

### Fixing the warning

Drop `mode="auto"`. `'manual'` is the default for `[cngxPopover]`:

```html
<div cngxPopover cngxPopoverSheet (closeRequested)="handleClose($event)">
  ...
</div>
```

Escape keeps working: `CngxPopover` closes a manual popover on Escape through its own listener, gated by `[closeOnEscape]`. On desktop, an anchored popover that should close on an outside click can use `[closeOnOutsideClick]`; the sheet handles outside taps itself while it is modal.

### Debugging the warning

The check runs in development mode only, once per sheet, when it first opens as a modal sheet. The popover host's `popover` attribute shows the mode: `popover="auto"` triggers the warning.
