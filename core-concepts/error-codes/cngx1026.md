# CNGX1026

## Submenu popover without position fallbacks

This warning is emitted when the popover of a `[cngxMenuItemSubmenu]` has no `position-try-fallbacks` value in its computed style after the first render, in a browser that implements the property.

`CngxPopover` positions itself with CSS Anchor Positioning. A submenu usually opens to the right of its parent row (`placement="right-start"`). When that row is close to the right edge of the viewport, only a `position-try-fallbacks` chain lets the browser flip the submenu to the other side or upwards. `CngxPopover` writes that property from its `[positionTryFallbacks]` input, which defaults to an empty list, so a submenu popover has no fallbacks unless you add them.

Without fallbacks, the submenu is placed where its placement says, even if that is partly off screen. Nothing fails: the items that overflow the viewport are simply cut off or force a horizontal scroll, which is easy to miss on a wide development screen.

```html
<!-- WARNING: no position-try-fallbacks on the submenu popover -->
<div cngxPopover #recentPop="cngxPopover" placement="right-start">
  <ul cngxMenu #recentMenu="cngxMenu" [label]="recentFilesLabel()">...</ul>
</div>
```

### Fixing the warning

#### Option 1: Bind the recommended fallback chain

`@cngx/common/interactive` exports `CNGX_SUBMENU_TRY_FALLBACKS` (`flip-inline`, `flip-block`, `flip-block flip-inline`). Expose it on the component and bind it:

```ts
import { CNGX_SUBMENU_TRY_FALLBACKS } from '@cngx/common/interactive';

export class FileMenu {
  protected readonly submenuFallbacks = CNGX_SUBMENU_TRY_FALLBACKS;
}
```

```html
<div cngxPopover #recentPop="cngxPopover" placement="right-start" [positionTryFallbacks]="submenuFallbacks">
  <ul cngxMenu #recentMenu="cngxMenu" [label]="recentFilesLabel()">...</ul>
</div>
```

#### Option 2: Set the property in CSS

The check reads the computed style, so a stylesheet rule on the popover element satisfies it too, for example `position-try-fallbacks: flip-inline, flip-block;` on a class you put on the submenu popovers.

### Debugging the warning

The message starts with `CNGX1026: [cngxMenuItemSubmenu] the companion popover ships without [positionTryFallbacks]` and does not name the popover. Check every popover bound to `[cngxMenuItemSubmenu]` or provided through `CNGX_MENU_SUBMENU_WIRING`.

The check runs in development mode only and logs at most once per document, for the first offending submenu; fixing that one can reveal the next on reload. It runs once per submenu directive after the first render, for the popover resolved at that time: the `[cngxMenuItemSubmenu]` input, else the popover of `CNGX_MENU_SUBMENU_WIRING`. A popover that resolves only later is not checked. It treats an empty computed value and `none` as missing. It runs only where `CSS.supports('position-try-fallbacks', 'flip-block')` is true: a browser without the property reports an empty value whatever is bound and cannot flip the submenu anyway, so nothing is reported there.
