# CNGX1048

## Chart layer outside a chart

This error is thrown when a chart layer is created without a `<cngx-chart>` above it in the injector tree. It comes from `injectChartContext()`, which every built-in layer and the axis call: `cngxLine`, `cngxArea`, `cngxBar`, `cngxScatter`, `cngxThreshold`, `cngxBand` and `cngxAxis`. A custom layer directive that calls `injectChartContext()` reports it the same way.

`<cngx-chart>` provides `CNGX_CHART_CONTEXT`: the plot area, the x and y scales and the SVG render hooks. A layer draws nothing on its own; it reads its geometry from that context. Without a chart there are no scales to map the data through, so the layer throws instead of rendering an empty group.

```html
<!-- ERROR: the layer is not a content child of <cngx-chart> -->
<svg>
  <svg:g cngxLine [strokeWidth]="2"></svg:g>
</svg>
```

### Fixing the error

Project the layer into `<cngx-chart>`. The chart renders the `<svg>` itself, so the layers go straight inside the element:

```html
<cngx-chart [data]="points()" aria-label="Weekly sign-ups">
  <svg:g cngxArea></svg:g>
  <svg:g cngxLine [strokeWidth]="2"></svg:g>
</cngx-chart>
```

For a custom layer, call `injectChartContext('myLayer')` with the layer's attribute selector, without brackets, in a directive placed the same way. The selector you pass names the layer in the dev message.

### Debugging the error

The message starts with `CNGX1048: ` and the selector the layer passed to `injectChartContext()` in brackets (`[cngxLine]`, `[cngxAxis]`, or your own), followed by `must be placed inside <cngx-chart>.`, so it tells you which layer is misplaced. For a line it reads `CNGX1048: [cngxLine] must be placed inside <cngx-chart>.` In a production build the message is the bare code `CNGX1048`; the check still runs there, because a layer without a chart cannot draw.

The lookup happens when the layer is created and only walks the element injector. Angular resolves it from where the layer is declared, not from where it ends up in the DOM. A layer inside an `ng-template` declared within the chart finds it even when the template is rendered somewhere else. A layer written as content of a component that wraps `<ng-content>` in its own `<cngx-chart>` does not find that chart: projected content resolves from the template it was written in. A component created dynamically (a dialog, `ViewContainerRef.createComponent`) resolves from the injector passed to it, or from the view container's, so pass one that sees the chart.
