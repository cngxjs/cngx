# CNGX1082

## Action status brain without an async run

This error is thrown when an element declares `CngxActionStatusBrain` from `@cngx/common/interactive` in its `hostDirectives` without a co-hosted `CngxAsyncClick`.

`CngxActionStatusBrain` is the status layer of an action host (`cngxActionButton`, `cngxPopoverAction`, or a host of your own): the effective status, the stacked label cells and the settle announcement. It reads the run it reports on from `CNGX_ASYNC_RUN_STATE`, which `CngxAsyncClick` provides on the same element. The lookup is lazy, because the runner reads the host interaction state that reads the brain, so the error surfaces on the first read (the first change detection of the host), not at creation.

```ts
// ERROR: the status brain is declared, the run is not
@Component({
  selector: 'button[appSave]',
  hostDirectives: [CngxButtonBrain, CngxActionStatusBrain],
  providers: [provideButtonHost('appSave', { defaultVariant: 'solid' }), provideActionStatusHost()],
  template: '<ng-content />',
})
class AppSave {}
```

### Fixing the error

Add `CngxAsyncClick` to the same `hostDirectives` list and forward its action input:

```ts
@Component({
  selector: 'button[appSave]',
  hostDirectives: [
    CngxButtonBrain,
    { directive: CngxAsyncClick, inputs: ['cngxAsyncClick: action'] },
    CngxActionStatusBrain,
  ],
  providers: [provideButtonHost('appSave', { defaultVariant: 'solid' }), provideActionStatusHost()],
  template: '<ng-content />',
})
class AppSave {}
```

A bound `[externalState]` does not replace the run: the brain still reads the busy gate and the live region from it.

### Debugging the error

The message names the element the brain sits on, for example `CNGX1082: [cngxActionStatusBrain] on <button> has no co-hosted run.` In a production build the message is the bare code `CNGX1082`; the check still runs there.

The run is looked up on the brain's own element only. A `cngxAsyncClick` on an ancestor or a wrapper does not count.
