# CNGX1044

## Standalone chip inside a chip group

This error is thrown when a chip carrying `[cngxChipInteraction]` is placed inside a `<cngx-chip-group>` or a `<cngx-multi-chip-group>`.

`CngxChipInteraction` is the standalone chip: it owns its selection as a local `[(selected)]` model. Inside a group the selection belongs to the group's selection controller, so the chip would hold a second copy of the same state. Clicking it flips the local model while the group's `[(selected)]` stays unchanged, and the group's keyboard navigation and `aria-selected` disagree with what the chip shows.

```html
<!-- ERROR: a standalone chip inside a group -->
<cngx-chip-group label="Size" [(selected)]="size">
  <cngx-chip cngxChipInteraction [value]="'m'">M</cngx-chip>
</cngx-chip-group>
```

### Fixing the error

Use `[cngxChipInGroup]` for every chip inside a group. It reads its selected state from the group as a `computed()` and writes through the group, so there is one source of truth:

```html
<cngx-chip-group label="Size" [(selected)]="size">
  <cngx-chip cngxChipInGroup [value]="'m'">M</cngx-chip>
</cngx-chip-group>
```

Drop the chip's own `[(selected)]` binding when you switch; the group's `[(selected)]` holds the value. Keep `[cngxChipInteraction]` only for a chip that stands alone, such as a removable filter tag outside any group.

### Debugging the error

The message reads `CNGX1044: [cngxChipInteraction] must not be used inside <cngx-chip-group> / <cngx-multi-chip-group>; use [cngxChipInGroup] instead.`

The check runs in development mode only, once per chip, after the first render (`afterNextRender`). A production build drops it, so a misplaced chip there fails silently with the split state described above.

The error reaches Angular's `ErrorHandler`, which logs it to the console by default. The check asks the chip's element injector for an ancestor group, so it fires for a chip written inside a group element in the same template. Search the template for `cngxChipInteraction` inside a `<cngx-chip-group>` or `<cngx-multi-chip-group>` element, or inside a `[cngxChipGroup]` or `[cngxMultiChipGroup]` host.
