# CNGX1050

## Chart buffer capacity is not a positive integer

This error is thrown when a chart ring buffer is created with a capacity that is zero, negative or not a whole number. The public entry point is `injectChartBuffer({ capacity })` from `@cngx/common/chart`, which creates the ring internally; the check sits in that ring.

The buffer is a fixed-size ring: it allocates `capacity` slots once and overwrites the oldest row when full, so a realtime chart keeps a bounded window. A capacity of `0` would hold nothing, a negative one cannot be allocated, and a fraction such as `2.5` has no meaning as a slot count. The factory throws instead of allocating a ring that silently drops every row.

```typescript
// ERROR: capacity must be a positive integer
private readonly buffer = injectChartBuffer<Sample>({
  capacity: 0,
  xAccessor: (s) => s.t,
  yAccessor: (s) => s.value,
});
```

### Fixing the error

Pass a whole number of at least `1`, the maximum number of rows the chart keeps:

```typescript
private readonly buffer = injectChartBuffer<Sample>({
  capacity: 1000,
  downsampleTo: 600,
  xAccessor: (s) => s.t,
  yAccessor: (s) => s.value,
});
```

When the capacity is derived (window length times sample rate, a value from settings), round it and clamp it to at least `1` before passing it in, for example with `Math.max(1, Math.round(seconds * hz))`.

### Debugging the error

The dev message starts with `CNGX1050: createRingBuffer(): ` and ends with the value it received (`got 0`, `got 2.5`, `got NaN`). `NaN` usually means the capacity was computed from a value that was not loaded yet. In a production build the message is the bare code `CNGX1050`; the check still runs there.

The capacity is read once, when the buffer is created, which for `injectChartBuffer` is the injection context of the component or directive that calls it. Changing the source value later has no effect; recreate the component to change the window size.
