# CNGX0001

## Locale is not a BCP 47 tag

This warning is emitted when cngx is asked to format for a locale that `Intl.getCanonicalLocales` rejects, such as `de_AT` (underscore instead of hyphen) or an empty string. The locale comes from the `locale` of the active language pack (`provideCngxI18n(withPack(...))`), from `provideLocale` / `provideLocaleAt`, or from the third argument of a direct `formatMessage` call.

cngx formats numbers and picks plural forms with `Intl.NumberFormat` and `Intl.PluralRules`, and both throw on an invalid tag. Instead of letting every message throw, cngx canonicalizes the tag once and, when that fails, reads it as English (`en`).

The app keeps running, so the failure is quiet: numbers come out in English format (`1,200` instead of `1.200`), plural forms follow English rules, and `provideCngxI18n` writes `<html lang="en">`. A pack without an explicit `dir` also derives its direction from `en`, so an RTL pack such as `ar_EG` renders left to right.

```ts
import { provideCngxI18n, withPack } from '@cngx/core/i18n';
import { CNGX_LANGUAGE_DE } from '@cngx/core/i18n/de';

bootstrapApplication(App, {
  providers: [
    // WARNING: "de_AT" is not a BCP 47 tag; cngx formats it as English
    provideCngxI18n(withPack({ ...CNGX_LANGUAGE_DE, locale: 'de_AT' })),
  ],
});
```

### Fixing the warning

#### Option 1: Use a BCP 47 tag

Separate the subtags with hyphens: `de-AT`, `pt-BR`, `zh-Hant-TW`. Case does not matter; cngx canonicalizes `DE-at` to `de-AT` without a warning.

```ts
provideCngxI18n(withPack({ ...CNGX_LANGUAGE_DE, locale: 'de-AT' }));
```

If the tag comes from a backend or a user profile in the `de_AT` form, convert it before it reaches cngx, for example `tag.replace('_', '-')`, and check the result with `Intl.getCanonicalLocales(tag)` in the browser console: it throws exactly when cngx would warn.

### Debugging the warning

The message quotes the rejected tag, for example `"de_AT" is not a BCP 47 locale`. Search your pack files, `provideLocale` / `provideLocaleAt` calls, `LOCALE_ID` and direct `formatMessage` calls for that string.

The check runs in development mode only. The result is cached per tag, so each bad tag warns once, not once per formatted message; after a runtime pack switch to a new bad tag you see a new line. Production builds apply the same English fallback without logging anything.

A valid tag that the browser has no data for (a rare region or script) is not reported; `Intl` falls back to its closest supported locale on its own. Missing plural counts and missing placeholder arguments are separate warnings: [CNGX0002](cngx0002.html) and [CNGX0003](cngx0003.html).
