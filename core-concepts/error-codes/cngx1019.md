# CNGX1019

## Two directives bind `aria-busy` on one element

This warning is emitted when `[cngxAsyncStatus]` and `[cngxAsyncClick]` are applied to the same element.

The two directives split one job in two. `CngxAsyncClick` runs an action on click and owns its lifecycle: it binds `aria-busy` from its own pending state (or its `[busy]` input) and `aria-disabled` while pending. `CngxAsyncStatus` reflects a state someone else owns, such as a presenter's `commitState` or a resource, and binds `aria-busy` (and, with `disableWhilePending`, `aria-disabled` and `disabled`) from that state. Each directive assumes it is the only writer of these attributes.

On one element, both host bindings write the same attributes from two unrelated sources. Whichever binding updates last wins, so `aria-busy` follows neither state reliably: a screen reader may hear the button as idle while the click action is still running, or as busy after the external state has settled.

```html
<!-- WARNING: both directives write aria-busy -->
<button [cngxAsyncClick]="save" [cngxAsyncStatus]="presenter.commitState">
  Save
</button>
```

### Fixing the warning

#### Option 1: Let `CngxAsyncClick` carry the external state

If the button runs the action and should also look busy while an outside operation is in flight, keep `[cngxAsyncClick]` and feed the external state into its `[busy]` input:

```html
<button
  [cngxAsyncClick]="save"
  [busy]="presenter.commitState.isBusy()"
  [enabled]="!presenter.commitState.isBusy()"
>
  Save
</button>
```

`[busy]` only sets `aria-busy`; gate clicks with `[enabled]` when the button must not start the action again.

#### Option 2: Use `CngxAsyncStatus` alone

If the element does not start the operation itself, for example a "Continue" button whose state is driven by a stepper presenter, drop `[cngxAsyncClick]` and handle the click yourself:

```html
<button [cngxAsyncStatus]="presenter.commitState" [disableWhilePending]="true" (click)="next()">
  Continue
</button>
```

### Debugging the warning

The message reads `CngxAsyncStatus: [cngxAsyncStatus] and [cngxAsyncClick] on the same element both bind aria-busy` and does not name the element. Search your templates for elements that carry both attributes, including components that add one of them as a host directive.

The check runs in development mode only, once per `CngxAsyncStatus` instance, when it is created. It only looks for a `CngxAsyncClick` on the same element; the two directives on a parent and a child element are fine.
