# CNGX2017

## Form-field part outside a form field

This error is thrown when one of the parts of a form field is created without a form field above it. The parts are `[cngxLabel]`, `[cngxHint]`, `[cngxError]`, `<cngx-required>` and `<cngx-field-errors>` from `@cngx/forms/field`, and `<cngx-char-count>` from `@cngx/forms/input`.

The parts hold no state of their own. They read it from the form field's presenter: the label takes the control's id for its `for` attribute, the hint and the error take the ids the control lists in `aria-describedby`, the required marker reads whether the field is required, the error list reads the field's errors, and the character count reads the current length and the length limits. `<cngx-form-field>` carries the presenter; a hand-built field gets it from `[cngxFormFieldPresenter]`. Without it a part has no field to describe, so the constructor throws instead of rendering a label, hint or error that no control is linked to.

```html
<!-- ERROR: the hint sits next to the form field, not inside it -->
<cngx-form-field [field]="form.email">
  <label cngxLabel>Email</label>
  <input cngxInput />
</cngx-form-field>
<span cngxHint>We never share your address.</span>
```

### Fixing the error

Put every part inside the form field it belongs to:

```html
<cngx-form-field [field]="form.email">
  <label cngxLabel>Email <cngx-required /></label>
  <input cngxInput />
  <span cngxHint>We never share your address.</span>
  <cngx-field-errors />
</cngx-form-field>
```

### Debugging the error

The message names the part, for example `CNGX2017: [cngxHint] must be placed inside <cngx-form-field> or an element with [cngxFormFieldPresenter].` In a production build the message is the bare code `CNGX2017`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A parent that another component renders in its own template, around content you project into it, is not above the projected element. A wrapper component that renders `<cngx-form-field>` in its template therefore has to place the parts in that template too, or project them into the form field with `<ng-content>` inside it.
