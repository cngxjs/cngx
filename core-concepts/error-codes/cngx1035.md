# CNGX1035

## Confirm popover action without an action

> Retired in 0.3.0.

Retired in 0.3.0: a confirm without `[action]` is now a compile error, use `button[cngxPopoverDismiss]` to close. No current CNGX release emits this code; the page stays because a code is never reused.

Until 0.3.0 this warning was emitted when a `<cngx-popover-action>` had `role="confirm"` (the default) and no `[action]` bound. The button rendered with `aria-disabled="true"`, but its click ran nothing and left the popover open.

From 0.3.0 the element is gone. The confirm is `button[cngxPopoverAction]`, a button-family host that co-hosts `cngxAsyncClick`, and `[action]` is its required input: a template that leaves it out does not compile. Closing without a run is the separate `button[cngxPopoverDismiss]`.

```html
<!-- before 0.3.0: warned CNGX1035 -->
<cngx-popover-action>Save</cngx-popover-action>
```

### Fixing the warning

#### Option 1: Bind the action

```html
<button cngxPopoverAction="solid" tone="primary" [action]="save">Save</button>
```

`save` is a function on the component, for example `readonly save = () => this.api.save(this.draft())`. A confirm that must not run yet stays focusable and says why: `[disabled]="!canSave()" disabledReason="Fill in the name first"`.

#### Option 2: Use the dismiss host

If the button should only close the popover (Cancel, Close, Got it), use the dismiss host:

```html
<button cngxPopoverDismiss>Cancel</button>
```

### Debugging the warning

On 0.3.0 and later the code never appears. On an older release, the message started with `CNGX1035: [cngx-popover-action] role="confirm" without an [action] renders a button whose click runs nothing`; search your templates for `<cngx-popover-action` without `[action]`. When upgrading, every `<cngx-popover-action>` has to move to one of the two hosts above; the compiler names each one that does not.
