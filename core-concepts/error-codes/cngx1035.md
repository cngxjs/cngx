# CNGX1035

## Confirm popover action without an action

This warning is emitted when a `<cngx-popover-action>` has `role="confirm"` (the default) and no `[action]` bound.

`CngxPopoverAction` has two roles. `role="dismiss"` closes the popover on click. `role="confirm"` runs the bound `[action]` (a function returning a promise or an observable), shows the pending, succeeded and failed templates while it runs, and closes the popover after it succeeds. A confirm action is a button that commits something; without `[action]` there is nothing to commit.

The button still renders and still looks like the primary button of the panel, but clicking it does nothing: no action runs, no status is shown, the popover stays open. Users press the confirm button and nothing happens.

```html
<!-- WARNING: role defaults to "confirm" and no [action] is bound -->
<cngx-popover-action>Save</cngx-popover-action>
```

### Fixing the warning

#### Option 1: Bind the action

```html
<cngx-popover-action role="confirm" [action]="save" variant="primary">Save</cngx-popover-action>
```

`save` is a function on the component, for example `readonly save = () => this.api.save(this.draft())`.

#### Option 2: Use the dismiss role

If the button should only close the popover (Cancel, Close, Got it), say so:

```html
<cngx-popover-action role="dismiss">Cancel</cngx-popover-action>
```

### Debugging the warning

The message is `CngxPopoverAction: role="confirm" without an [action] renders a button whose click does nothing.` It does not identify the instance. Search your templates for `<cngx-popover-action` without `[action]`, including the ones that omit `role`, since `confirm` is the default.

The check runs in development mode only, once per action, after the first render, and reads `role()` and `action()` at that moment. An `[action]` bound to a value that is `undefined` on the first render (a late-initialised field) also triggers it.
