# CNGX1061

## Breadcrumb item outside a breadcrumb

This error is thrown when `[cngxBreadcrumbItem]` from `@cngx/common/interactive` is created without a breadcrumb above it.

The item directive marks one crumb of a hand-built breadcrumb trail. It holds no state of its own: whether it is the current page (`aria-current="page"`) and whether it is collapsed come from the surrounding `[cngxBreadcrumb]`, which counts its items and applies the collapse strategy. Without it the item cannot tell its position, so the constructor throws instead of rendering a crumb that is never marked as current.

```html
<!-- ERROR: no breadcrumb above the items -->
<ol>
  <li><a cngxBreadcrumbItem href="/">Home</a></li>
  <li><a cngxBreadcrumbItem>Settings</a></li>
</ol>
```

### Fixing the error

Put the items inside the element that carries the breadcrumb:

```html
<nav cngxBreadcrumb aria-label="Breadcrumb">
  <ol>
    <li><a cngxBreadcrumbItem href="/">Home</a></li>
    <li><a cngxBreadcrumbItem>Settings</a></li>
  </ol>
</nav>
```

`<cngx-breadcrumb>` from `@cngx/ui/breadcrumb` renders its crumbs itself, from its items input or its router sync; you do not place `[cngxBreadcrumbItem]` inside it.

### Debugging the error

The message reads `CNGX1061: [cngxBreadcrumbItem] must be placed inside an element with [cngxBreadcrumb].` In a production build the message is the bare code `CNGX1061`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A parent that another component renders in its own template, around content you project into it, is not above the projected element.
