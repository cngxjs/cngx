# CNGX1034

## Sticky header in a container that cannot scroll

This warning is emitted when a `[cngxStickyHeader]` element sits inside a scroll container whose content fits, so the container never scrolls and the header can never pin.

`position: sticky` resolves against the nearest ancestor that is a scroll container: the first ancestor whose computed `overflow-y` is `auto`, `scroll` or `hidden`. `overflow: clip` clips without creating a scroll container, so a header passes through a clipping ancestor to the next one up. An `overflow-x` of `auto`, `scroll` or `hidden` also turns an element into a scroll container in both axes, so an ancestor that only scrolls sideways (a wide table wrapper) captures the sticky header too. `CngxStickyHeader` finds that same ancestor and observes against it to report `isSticky()` and `(stickyChange)`.

When that ancestor has no bounded height, its client height equals its scroll height. It grows with its content and moves with the page, and the header inside it scrolls away like any other element. `isSticky()` stays `false`, which is accurate, but the header never does what the attribute promises.

```html
<!-- WARNING: overflow-x makes this wrapper the scroll container, but it has no height -->
<div style="overflow-x: auto">
  <header cngxStickyHeader>Results</header>
  <table>...</table>
</div>
```

### Fixing the warning

#### Option 1: Give the scroll container a bounded block size

If the header should pin inside the container, let the container scroll vertically:

```html
<div style="overflow: auto; max-block-size: 60vh">
  <header cngxStickyHeader>Results</header>
  <table>...</table>
</div>
```

#### Option 2: Move the header out of the container

If the header should pin to the page, place it outside the wrapper that sets `overflow`, or move the `overflow-x` onto a wrapper around the table only. With no scrolling ancestor the header sticks to the viewport.

#### Option 3: Drop `cngxStickyHeader`

If the header does not need to pin, remove the attribute.

### Debugging the warning

The message starts with `CNGX1034: [cngxStickyHeader] resolves against a scroll container that cannot scroll`. The second console argument is an object with `host` (the header element) and `scrollport` (the ancestor it resolved to); expand it in the console, or hover it to highlight both elements on the page. Look at the computed `overflow-x` / `overflow-y` of `scrollport` to see why it became the scroll container.

The check runs in development mode only, once per header, after the first render. A scroll range of 1px or less counts as "cannot scroll", which absorbs sub-pixel and zoom rounding. The check reads the layout at that moment. A container whose content arrives after the first render (rows loaded over HTTP, say) is measured while it still fits and logs the warning, even though it scrolls and the header pins once the content is there; that warning is a false positive. A header that has no scrolling ancestor at all sticks to the viewport and is not reported.
