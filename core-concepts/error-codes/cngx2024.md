# CNGX2024

## patchData or clearLocalItems called on the select shell

This warning is emitted when code calls `patchData()` or `clearLocalItems()` on a `CngxSelectShell` (`<cngx-select-shell>`).

The data-driven selects (`CngxSelect`, `CngxMultiSelect`, `CngxCombobox`, `CngxTypeahead`, the action selects and the reorderable multi-select) render their panel from `[options]` plus a local-items buffer. `patchData()` adds an item to that buffer, for example after a quick-create, and the panel shows it next to the server options.

The shell is different. Its panel renders the `<cngx-option>` elements you project, nothing else. The two methods exist only because every select host implements the same panel-host contract. On the shell a patched item never reaches the panel: the user cannot see it, highlight it or pick it again. What you project is what renders.

```html
<cngx-select-shell [(value)]="color">
  @for (c of colors(); track c.value) {
    <cngx-option [value]="c.value">{{ c.label }}</cngx-option>
  }
</cngx-select-shell>
```

```ts
// WARNING: the shell does not render patched items
shell.patchData({ value: 'teal', label: 'Teal' });
```

### Fixing the warning

#### Option 1: Project the option

Add the item to the list your template iterates, so a new `<cngx-option>` is projected:

```ts
this.colors.update((list) => [...list, { value: 'teal', label: 'Teal' }]);
```

Removing an option works the same way: drop it from the list instead of calling `clearLocalItems()`.

#### Option 2: Use a data-driven select

If the options come from a server or a create flow, bind them through `[options]` on one of the data-driven selects. They own the local-items buffer and render patched items.

### Debugging the warning

The message starts with `CNGX2024: [cngx-select-shell] patchData()` or `CNGX2024: [cngx-select-shell] clearLocalItems()`. Search your code for the call on a shell reference (a `viewChild(CngxSelectShell)` or a template reference variable).

The check runs in development mode only. In production both calls stay silent and change nothing in the panel; the patched item still takes part in resolving the current value, as before.
