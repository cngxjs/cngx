# CNGX3011

## Icon-only tabs without an icon template

This warning is emitted when a `<cngx-tab-group>` resolves its icon layout to `'only'` and resolves no icon template: no `<ng-template cngxTabIcon>` is projected into it and none is set app-wide with `withTabIconTemplate(...)`. The layout comes from the `iconLayout` input, then from `withTabsIconLayout(...)` in the tabs config, then from the default `'start'`.

`iconLayout="only"` reflects onto the `[data-icon-layout]` host attribute, and the tab styles clip each tab's label so that only the icon shows. The label stays in the DOM and in the accessibility tree, so the tab keeps its accessible name. The icon, however, is not built in: each tab button renders an icon only when the group resolves an icon template, and without one the icon span is not rendered at all.

The result is a row of tab buttons with neither a visible icon nor a visible label. Screen reader users still hear the tab names, but sighted users see empty buttons and cannot tell the tabs apart.

```html
<!-- WARNING: icon-only layout, but no *cngxTabIcon template -->
<cngx-tab-group iconLayout="only" [attr.aria-label]="workspaceLabel()">
  <div cngxTab [label]="overviewLabel()">
    <ng-template cngxTabContent>...</ng-template>
  </div>
</cngx-tab-group>
```

### Fixing the warning

#### Option 1: Project an icon template

Add a `cngxTabIcon` template to the group. It renders once per tab, with the tab handle, `active` and `index` in its context:

```html
<cngx-tab-group iconLayout="only" [attr.aria-label]="workspaceLabel()">
  <ng-template cngxTabIcon let-tab="tab">
    <svg width="20" height="20"><use [attr.href]="iconFor(tab.id)" /></svg>
  </ng-template>
  <div cngxTab [label]="overviewLabel()">
    <ng-template cngxTabContent>...</ng-template>
  </div>
</cngx-tab-group>
```

Give each tab a distinct glyph; identical icons are as unusable as no icons.

#### Option 2: Keep the labels visible

Use `iconLayout` `'start'`, `'end'` or `'top'`. The labels stay visible, and an icon template becomes optional.

### Debugging the warning

The message names the host, `[cngx-tab-group]`, and the layout `'only'`. It starts with `CNGX3011: [cngx-tab-group] iconLayout='only' but no *cngxTabIcon template is provided`. It does not identify the instance; check every tab group whose `iconLayout` input or app-wide `withTabsIconLayout('only')` resolves to `'only'`.

The check runs in development mode only, once per tab group, after the first render. It reads the layout and the resolved template at that moment, so a layout switched to `'only'` later, or a template removed later, is not reported.

The check reads the icon template the tabs actually render: a `cngxTabIcon` template projected into the group, else an app-wide one set with `withTabIconTemplate(...)` in `provideTabsConfig()` / `provideCngxTabs()`. Either one silences it.
