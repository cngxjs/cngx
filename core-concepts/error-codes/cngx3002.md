# CNGX3002

## No state source for a feedback bridge

This error is reported when a feedback bridge (`[cngxAlertOn]`, `[cngxBannerOn]` or `[cngxToastOn]`) has no async state to watch after its first render: the directive input is unbound or bound to `undefined`, and no `CNGX_STATEFUL` provider exists on the element or an ancestor.

Each bridge turns a `CngxAsyncState` into feedback by watching its `status()` and reacting to the transition into `success` or `error`. The state comes from the directive's own input, or, when the input is unbound, from `CNGX_STATEFUL`, the contract that stateful hosts such as `CngxSelect`, `CngxActionSelect`, `CngxTimeline` or the tab and stepper presenters provide. A bare attribute (`cngxToastOn` with no value) counts as unbound, so the fallback can take over.

With neither source, the bridge reads the status as `idle` forever. The template compiles, the toaster or alerter is present, and no toast, alert or banner ever appears; nothing else fails.

```html
<!-- ERROR: bare attribute on a plain button, no CNGX_STATEFUL anywhere above it -->
<button type="button" (click)="save()" cngxToastOn [toastError]="saveFailedLabel()">Save</button>
```

### Fixing the error

#### Option 1: Bind the state explicitly

Pass the `CngxAsyncState` the bridge should watch. `CngxAsyncClick` exposes one as `state`:

```html
<button
  type="button"
  [cngxAsyncClick]="save"
  #btn="cngxAsyncClick"
  [cngxToastOn]="btn.state"
  [toastSuccess]="savedLabel()"
  [toastError]="saveFailedLabel()"
>
  Save
</button>
```

The same works with a state from `createAsyncState()` or `createManualState()` in `@cngx/common/data`. Route the messages through your own i18n, like any other copy.

#### Option 2: Use the fallback from a stateful host

Put the bare attribute on, or inside, a component that provides `CNGX_STATEFUL`. On `<cngx-select>` it reports the commit state:

```html
<cngx-select [options]="statuses" [commitAction]="saveStatus" cngxToastOn [toastError]="saveFailedLabel()" />
```

### Debugging the error

The message starts with `CNGX3002: ` and the directive's selector, `[cngxAlertOn]`, `[cngxBannerOn]` or `[cngxToastOn]`, so you can tell which bridge is affected.

The check runs in development mode only, once per directive instance, after the first render. It reads the input at that moment: an input bound to a value that is still `undefined` on first render (for example a state created later in `ngOnInit` or after an HTTP call) triggers the error even though the bridge starts working once the value arrives. Create the state in a field initializer so it exists from the start.

The `CNGX_STATEFUL` lookup walks the element injector tree from the directive's element upward, so a provider on the same host or any ancestor counts. A state held only in a parent component's class field does not; bind it explicitly. A missing `CngxToaster`, `CngxAlerter` or `CngxBanner` is a different failure: the directive throws in its constructor before this check runs.
