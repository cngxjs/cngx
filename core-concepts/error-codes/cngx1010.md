# CNGX1010

## Chart preset without an accessible name

This warning is emitted when one of the meter presets, `<cngx-mini-bar>`, `<cngx-donut>`, `<cngx-bullet>` or `<cngx-deviation-bar>`, renders without an accessible name.

These presets show a single bounded value, so their host carries `role="meter"` with `aria-valuenow`, `aria-valuemin` and `aria-valuemax`. A meter needs a name that says what is being measured. The presets set the host `aria-label` from their inputs: `<cngx-mini-bar>` and `<cngx-donut>` use `[aria-label]`, falling back to their visible `[label]`; `<cngx-bullet>` and `<cngx-deviation-bar>` have no visible label and use `[aria-label]` only.

Without a name, the meter still renders and still reports its value. A screen reader announces something like "meter, 72" with no subject, and in a row of KPI tiles every meter sounds the same:

```html
<!-- WARNING: nothing names this meter -->
<cngx-bullet [actual]="revenue()" [target]="revenueTarget()" />
```

### Fixing the warning

#### Option 1: Bind the name input

Use `[aria-label]` on any of the four presets, or the visible `[label]` on `<cngx-mini-bar>` and `<cngx-donut>`. The text is copy, so route it through your own i18n:

```html
<cngx-bullet [actual]="revenue()" [target]="revenueTarget()" [aria-label]="revenueLabel()" />
<cngx-mini-bar [value]="cpu()" [label]="cpuLabel()" />
```

When both are bound on the mini-bar or the donut, `[aria-label]` wins over `[label]` for the accessible name.

#### Option 2: Point at a visible heading

If the meter already sits under a visible title, reference it instead of repeating the text:

```html
<h3 id="revenue-heading">{{ revenueHeading() }}</h3>
<cngx-bullet [actual]="revenue()" [target]="revenueTarget()" aria-labelledby="revenue-heading" />
```

### Debugging the warning

The message starts with the preset's selector and the host role, for example `cngx-bullet: role="meter" has no accessible name`, and ends with the inputs that preset accepts (`Bind [aria-label].` or `Bind [label] or [aria-label].`).

The check runs in development mode only, once per preset instance, after the first render. It treats the host as named when the name input is a non-empty string, or when the host element has a non-empty `aria-label` or `aria-labelledby` attribute at that moment. It does not resolve the `aria-labelledby` target, so an id that points nowhere passes. A name input that is still `null` on first render and set later is reported anyway. `<cngx-sparkline>`, `<cngx-mini-area>` and `<cngx-stacked-bar>` do not run this check.
