# CNGX3017

## Banner without a CngxBanner

This error is thrown when `<cngx-banner-trigger>` or `[cngxBannerOn]` from `@cngx/ui/feedback` is created and no `CngxBanner` can be injected for it.

Both hand their banners to the `CngxBanner` service, which `<cngx-banner-outlet>` renders from. `<cngx-banner-trigger>` shows a banner while its `[when]` input is `true` and dismisses it when it turns `false`; `[cngxBannerOn]` shows one when an async state turns to `error` and dismisses it when the state returns to `success` or `idle`. The service is not provided in root, so an app that never set it up has nowhere to show banners, and both throw in their constructor instead of dropping every banner silently.

```typescript
// ERROR: provideFeedback() without withBanners()
bootstrapApplication(AppComponent, {
  providers: [provideFeedback(withToasts())],
});
```

### Fixing the error

Add `withBanners()` to `provideFeedback()` and render the banners with one `<cngx-banner-outlet>`, usually at the top of the root component:

```typescript
bootstrapApplication(AppComponent, {
  providers: [provideFeedback(withBanners())],
});
```

```html
<cngx-banner-outlet />
<router-outlet />
```

To scope banners to one part of the app, add `CngxBanner` to the `providers` of a component and place a `<cngx-banner-outlet>` inside it.

### Debugging the error

The message starts with `CNGX3017: ` and the selector that threw: `[cngx-banner-trigger]` or `[cngxBannerOn]`. For the bridge it reads `CNGX3017: [cngxBannerOn] CngxBanner not found. Add withBanners() to provideFeedback().` In a production build the message is the bare code `CNGX3017`; the check still runs there.

The lookup follows the element injector tree from where the element is declared, then the environment injectors. Projected content resolves from the template it was written in, and a component created dynamically (a dialog, `ViewContainerRef.createComponent`) resolves from the injector passed to it.
