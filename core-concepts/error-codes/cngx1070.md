# CNGX1070

## Command source factory returned no source

This warning is emitted when a factory passed to `provideCommands` from `@cngx/common/command` returns something that is neither a command array nor a `Signal` of one, such as `undefined` or a plain object.

`provideCommands` runs a factory source once, as a provider factory, and merges what it returns into the registry `injectCommands` reads. A result that is not a source cannot be merged, so the factory contributes no commands. The other sources at that level and the levels around it keep working. Nothing throws.

The type `CngxCommandSourceFactory` rules this out in TypeScript, so the usual causes are a JavaScript caller, a cast, or a factory that reads a field before the service has set it:

```ts
// WARNING: the arrow has a block body and no return statement
provideCommands(() => {
  inject(EditorStore).commands;
});
```

### Fixing the warning

Return the source itself. Return the `Signal` to stay reactive, or an array when the set is fixed:

```ts
provideCommands(() => inject(EditorStore).commands);
```

When the source is only known later, keep a `Signal` on the service from the start and write to it, rather than returning a field that is still unset when the factory runs.

### Debugging the warning

The message starts with `CNGX1070: provideCommands() factory returned ` and names the type of the value the factory returned. Search the `providers` and `viewProviders` arrays for `provideCommands(() =>` calls and check what each arrow returns.

The check runs in development mode only. In production the invalid result is still dropped, without a warning.
