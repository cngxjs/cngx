# CNGX4001

## Treetable column has no header label

This warning is emitted when a `<cngx-treetable>` renders a data column that has neither a `columnLabels` entry nor a projected `<ng-template [cngxHeader]="'key'">` for that column.

The treetable derives its columns from the primitive keys of the first node's value (or from `options.customColumnOrder`), so a column exists whether or not anyone gave it a label. Its header text comes from `columnLabels`, set through `withTreetableLabels` or the `treetable` section of the language pack. Without an entry, a development build shows the column key, capitalised, so you can spot it; a production build shows the `unlabeledColumn` text instead (`Column 2` by default), because a data key is not a label a user should read or a screen reader should announce.

Development and production therefore render different headers. The table looks finished during development and ships with generic `Column 1`, `Column 2` headers that tell neither sighted nor screen reader users what the column holds.

```html
<!-- WARNING: the "size" column has no label; production shows "Column 2" -->
<cngx-treetable [tree]="files" />
```

```ts
protected readonly files: CngxTreetableNode<FileRow> = {
  value: { name: 'src', size: 4096 },
  children: [/* ... */],
};
```

### Fixing the warning

#### Option 1: Add the column to `columnLabels`

Set the labels app-wide with `provideTreetable`, or for one subtree with `provideTreetableAt` in a component's `providers`. Both come from `@cngx/data-display/treetable`. Route the label text through your own i18n, like any other copy; `withTreetableLabels` also accepts a `Signal`, so a language switch reaches the headers:

```ts
provideTreetable(withTreetableLabels({ columnLabels: { name: 'Name', size: 'Size' } }));
```

With a language pack, put the labels in its `treetable` section instead (`treetable: { columnLabels: { size: 'Größe' } }`); `columnLabels` from `withTreetableLabels` merges over the pack's key by key.

#### Option 2: Project a header template for the column

A header template replaces the header cell. Its context carries the column key and the resolved default `label`:

```html
<cngx-treetable [tree]="files">
  <ng-template [cngxHeader]="'size'">{{ sizeHeader() }}</ng-template>
</cngx-treetable>
```

### Debugging the warning

The message names the column key, for example `[CngxTreetable] column "size" has no header label`. The key is the property name on the node value, or the entry in `options.customColumnOrder`.

The check runs in development mode only, after the labels, the columns or the header templates change, and warns once per column key per treetable instance. It counts only `columnLabels` and a `[cngxHeader]` template projected for that exact key. A global header template from `withTreetableTemplates({ header })` and a custom `unlabeledColumn` function do not silence it, because neither gives the column a label of its own.
