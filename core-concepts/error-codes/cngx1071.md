# CNGX1071

## Icon button without an accessible name

This warning is emitted when a `button[cngxIconButton]` or `a[cngxIconButton]` from `@cngx/common/button` renders without an `aria-label`, an `aria-labelledby` or a `title` on the host.

An icon button shows a glyph and no text. A screen reader computes the button's name from its content, finds an icon marked `aria-hidden` or an SVG with no title, and announces "button" and nothing else (WCAG 4.1.2 Name, Role, Value). Voice control users cannot address it either, because there is no name to speak (WCAG 2.5.3 Label in Name). The button still works with a mouse, so the gap is easy to miss. Nothing throws.

```html
<!-- WARNING: the bin icon is the only content, the button has no name -->
<button cngxIconButton (click)="remove()">
  <cngx-icon name="delete" />
</button>
```

### Fixing the warning

Name the action, not the icon, on the host:

```html
<button cngxIconButton aria-label="Delete row" (click)="remove()">
  <cngx-icon name="delete" />
</button>
```

The name is your copy, so route it through your own translations. Use `aria-labelledby` when visible text elsewhere already names the action. A tooltip (`[cngxTooltip]`) is optional and does not replace the name: it describes, it does not label, and it never shows on touch. When the icon alone is ambiguous, a `cngxButton` with the icon in `cngxButtonStart` and a visible label is often the better control.

### Debugging the warning

The message starts with `CNGX1071: [cngxIconButton] has no accessible name.` and passes the host element as context, so the console links straight to the button. The check runs once after the first render, so a name bound later through `[attr.aria-label]` still counts if it is set by then.

The check runs in development mode only. In production the button renders the same, without a warning.
