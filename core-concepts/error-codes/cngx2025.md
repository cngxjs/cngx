# CNGX2025

## commitAction completed without emitting a value

This error is raised when the `[commitAction]` of a select returns an Observable that completes without emitting a value.

Every select in `@cngx/forms/select` accepts a `[commitAction]` that writes the user's pick to a server. When it returns an Observable, the select takes the first emitted value as the committed value and settles the commit. A source that completes before it emits anything, such as `EMPTY`, a `filter` that drops every value, or `take(1)` on a subject that already completed, gives the select nothing to settle with. Left alone, the commit would stay pending forever: the option row keeps its spinner, and in `pessimistic` mode the panel cannot be closed by Escape, an outside click or the sheet's Done button.

The select therefore settles such a commit as an error. The optimistic value rolls back, the commit error UI and its Retry button appear, and the failure is announced like any other failed commit.

```ts
readonly save: CngxSelectCommitAction<string> = (intended) =>
  // ERROR: the filter drops the response, the stream completes empty
  this.api.save(intended).pipe(filter((res) => res.changed));
```

### Fixing the error

#### Option 1: Emit before completing

Map the response to the committed value, so the stream always emits once:

```ts
readonly save: CngxSelectCommitAction<string> = (intended) =>
  this.api.save(intended).pipe(map(() => intended));
```

#### Option 2: Emit undefined when the server returns nothing

When the server confirms without a body, emit `undefined`. The select then keeps the intended value:

```ts
readonly save: CngxSelectCommitAction<string> = (intended) =>
  this.api.save(intended).pipe(map(() => undefined));
```

`of(undefined)` and a Promise that resolves to `undefined` settle as a success as well.

### Debugging the error

The settled error is a `CngxRuntimeError` with `code` set to `'CNGX2025'`. In development mode its message starts with `CNGX2025: commitAction() completed without emitting a value`; in production the message is the bare code, `CNGX2025`. The error reaches the commit error UI, the live-region announcement and `CNGX_STATEFUL` consumers such as `CngxToastOn` as an ordinary `error` transition.

Search your code for the `[commitAction]` binding of the select that failed and check every operator that can complete the stream early.

An Observable that neither emits nor completes is not covered: it stays pending until the next commit supersedes it. Add a `timeout` to the stream if the server can hang.
