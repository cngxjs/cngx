# CNGX2008

## Chip removal handler without its standard fields

This error is thrown when `createChipRemovalHandler(options)` from `@cngx/forms/select` is called without `removeOverride` and without one or more of the fields the standard removal body needs.

The handler is what a chip's remove button calls in `CngxMultiSelect`, `CngxCombobox`, `CngxReorderableMultiSelect`, `CngxActionMultiSelect` and `CngxTreeSelect`. Its standard body filters the removed value out of `values` with `compareWith`, then either starts a commit through `beginCommit` (when `commitAction` returns an action) or writes the value and calls `onSyncFinalize`. Each of `values`, `compareWith`, `commitAction`, `commitMode`, `beginCommit` and `onSyncFinalize` is used on one of those branches. The handler checks them once, when it is created, rather than failing on the first chip a user removes.

```typescript
// ERROR: no removeOverride, and the standard fields are missing
const handler = createChipRemovalHandler<string>({ disabled: this.disabled });
```

### Fixing the error

#### Option 1: Pass the standard fields

```typescript
const handler = createChipRemovalHandler<string>({
  disabled: this.disabled,
  values: this.values,
  compareWith: this.compareWith,
  commitAction: this.commitAction,
  commitMode: this.commitMode,
  beginCommit: (next, previous, item, action) => this.commits.beginToggle(next, previous, item, action),
  onSyncFinalize: (item, previous) => this.emitChange(item, previous),
});
```

#### Option 2: Replace the body

When removal works differently for your control, pass `removeOverride`. The standard fields are then ignored, and only `disabled` and the per-item closure cache still apply. `CngxTreeSelect` does this.

```typescript
const handler = createChipRemovalHandler<string>({
  disabled: this.disabled,
  removeOverride: (item) => this.deselect(item.value),
});
```

### Debugging the error

The message lists every missing field. In a production build the message is the bare code `CNGX2008`; the check still runs there.

The built-in select components always pass a complete set. When the error comes from one of them, look for a custom `CNGX_CHIP_REMOVAL_HANDLER_FACTORY`. The components call the factory in a field initializer, so the error surfaces while the component is created. A wrapper that rebuilds the options object instead of forwarding it can drop fields; dropping `removeOverride` breaks `CngxTreeSelect` in particular, because it passes only `disabled` and `removeOverride`. Forward the options unchanged and add your behavior around the returned handler.
