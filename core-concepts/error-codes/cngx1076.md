# CNGX1076

## Push drawer requested as modal

This warning is emitted when an element with `cngxDrawerPanel` from `@cngx/common/layout` combines `mode="push"` with `modality="page"` or `modality="contained"`.

A push drawer lays the panel out next to the content and shifts the content aside. The content stays visible and in use while the drawer is open, so the panel cannot be modal: a page-modal panel would trap focus, make the page `inert` and lock its scrolling, and a contained one would still make the content beside it `inert` under a scrim, which leaves visible content the user cannot operate. `CngxDrawerPanel` therefore resolves a push panel to `modality="none"` and ignores the requested modality. The drawer still opens and closes; Escape, the back gesture and a press outside the panel still close it, and focus returns to the opener. Nothing throws.

```html
<!-- WARNING: push is never modal -->
<nav [cngxDrawerPanel]="drawer" mode="push" modality="page">…</nav>
<nav [cngxDrawerPanel]="drawer" mode="push" modality="contained">…</nav>
```

### Fixing the warning

For a modal drawer, overlay the content with `mode="over"` (`page` by default, `contained` to keep everything outside the `[cngxDrawer]` host live). For a drawer next to the content, drop `modality` or set it to `none`.

```html
<nav [cngxDrawerPanel]="drawer" mode="over">…</nav>
<nav [cngxDrawerPanel]="drawer" mode="over" modality="contained">…</nav>
<nav [cngxDrawerPanel]="drawer" mode="push">…</nav>
```

### Debugging the warning

The message starts with `CNGX1076: [cngxDrawerPanel] mode="push" is never modal; a page or contained modality resolves to "none".` The requested modality follows as the context object (`{ modality: 'page' }`). It is emitted whenever the panel reaches the push + modal combination, so a mode switch at runtime warns again.

The check runs in development mode only. In production the panel renders the same, without a warning.
