# CNGX2019

## Filter-builder form-field control without a filter builder

This error is thrown when `[cngxFilterBuilderFormFieldControl]` from `@cngx/forms/filter-builder` is created on an element that has no filter-builder presenter on it or above it.

The directive makes a filter builder the control of a `<cngx-form-field>`: it registers the builder's presenter as the field's control, so the field's label, hint, errors and touched state apply to the whole filter tree, and it tracks focus moving in and out of the builder. It holds no tree of its own. `<cngx-filter-builder>` carries the presenter; a hand-built skin gets it from `[cngxFilterBuilderPresenter]`. Without one there is no control to register, so the constructor throws instead of leaving a form field with no control.

```html
<!-- ERROR: the directive sits on a wrapper, not on the builder -->
<cngx-form-field [field]="form.filter">
  <div cngxFilterBuilderFormFieldControl>
    <cngx-filter-builder [fields]="fields" [(value)]="tree" />
  </div>
</cngx-form-field>
```

### Fixing the error

Put the directive on the filter builder itself:

```html
<cngx-form-field [field]="form.filter">
  <cngx-filter-builder cngxFilterBuilderFormFieldControl [fields]="fields" [(value)]="tree" />
</cngx-form-field>
```

### Debugging the error

The message reads `CNGX2019: [cngxFilterBuilderFormFieldControl] must be placed on <cngx-filter-builder> or an element with [cngxFilterBuilderPresenter].` In a production build the message is the bare code `CNGX2019`; the check still runs there.

The check runs once, in the constructor, and looks at the element and its ancestors. Angular resolves the parent from where the element is written in a template, not from where it ends up in the DOM. A parent that another component renders in its own template, around content you project into it, is not above the projected element.
