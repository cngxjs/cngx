# CNGX1074

## Menu trigger without an ARIA writer

This warning is emitted when an element with `cngxMenuTrigger` from `@cngx/common/interactive` renders without `aria-expanded`, which means no `cngxPopoverTrigger` sits on the same element.

`CngxMenuTrigger` owns the keyboard model of a dropdown menu: it opens the menu, moves focus into it and routes the submenu keys. It writes no ARIA state of its own. The co-hosted `CngxPopoverTrigger` is the single writer of `aria-haspopup`, `aria-expanded` and `aria-controls`; the menu trigger only hands it two hints, `menu` for `aria-haspopup` and the menu's id for `aria-controls`. Without the popover trigger the button announces neither that it opens a menu nor whether the menu is open, and a screen reader user cannot tell the state from the trigger. The menu still opens and closes. Nothing throws.

```html
<!-- WARNING: no cngxPopoverTrigger, so no aria-expanded / aria-haspopup / aria-controls -->
<button type="button" [cngxMenuTrigger]="menu" [popover]="pop">Actions</button>
<div cngxPopover #pop="cngxPopover">
  <ul cngxMenu label="Actions" tabindex="0" #menu="cngxMenu">
    <li cngxMenuItem value="cut">Cut</li>
  </ul>
</div>
```

### Fixing the warning

Co-host `[cngxPopoverTrigger]` on the trigger element and point it at the same popover. It also anchors the popover to the trigger.

```html
<button type="button" [cngxMenuTrigger]="menu" [popover]="pop" [cngxPopoverTrigger]="pop">
  Actions
</button>
```

`cngxMenuButton` and `cngxIconMenuButton` compose both directives already; prefer them for a button that opens a menu.

### Debugging the warning

The message starts with `CNGX1074: [cngxMenuTrigger] has no aria-expanded writer.` and passes the trigger element as context, so the console links straight to it. The check runs once after the first render.

The check runs in development mode only. In production the trigger renders the same, without a warning.
