# CNGX1068

## Group chip outside a chip group

This error is thrown when `[cngxChipInGroup]` from `@cngx/common/interactive` is created without a chip group above it.

The directive turns a `<cngx-chip>` into an option of a chip group. It holds no selection of its own: whether the chip is selected, disabled or removable comes from the surrounding `<cngx-chip-group>` or `<cngx-multi-chip-group>`, and every click and key press is forwarded to that group. Without it the chip would render as an option that can never be selected, so the constructor throws instead.

```html
<!-- ERROR: no chip group above the chips -->
<div>
  <cngx-chip cngxChipInGroup [value]="'sm'">Small</cngx-chip>
  <cngx-chip cngxChipInGroup [value]="'md'">Medium</cngx-chip>
</div>
```

### Fixing the error

#### Option 1: Put the chips inside a chip group

```html
<cngx-chip-group label="Size" [(selected)]="size">
  <cngx-chip cngxChipInGroup [value]="'sm'">Small</cngx-chip>
  <cngx-chip cngxChipInGroup [value]="'md'">Medium</cngx-chip>
</cngx-chip-group>
```

Use `<cngx-multi-chip-group [(selectedValues)]>` for a multi-selection.

#### Option 2: Use a standalone interactive chip

A chip that toggles on its own, without a group, takes `[cngxChipInteraction]` instead of `[cngxChipInGroup]`.

### Debugging the error

The message reads `CNGX1068: [cngxChipInGroup] must be placed inside <cngx-chip-group> or <cngx-multi-chip-group>.` In a production build the message is the bare code `CNGX1068`; the check still runs there.

The check runs once, in the constructor. It looks at the element and its ancestors up to the host of the template the chip is written in, and does not cross into an outer component. Angular resolves the group from where the chip is written in a template, not from where it ends up in the DOM: a group that another component renders in its own template, around content you project into it, is not above the projected chip.
