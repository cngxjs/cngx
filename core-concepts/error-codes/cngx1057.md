# CNGX1057

## Menu radio item outside a menu group

This error is thrown when `[cngxMenuItemRadio]` from `@cngx/common/interactive` is created without a `[cngxMenuGroup]` above it. `<cngx-context-menu-item-radio>` from `@cngx/ui/context-menu` is built on it and throws the same error.

A radio item is one choice out of several, and the choice belongs to the group, not to the item: `[cngxMenuGroup]` holds the selected value (`[(selectedValue)]`), and each radio item reads whether it is checked from it and writes its own value into it when activated. Without a group there is no value to select, so a click would do nothing and `aria-checked` would stay `false` for good. The constructor throws instead, the same way a button toggle outside its group does ([CNGX1053](cngx1053.html)).

```html
<!-- ERROR: radio items directly in the menu, without a group -->
<ul cngxMenu label="View">
  <li cngxMenuItemRadio value="list">List</li>
  <li cngxMenuItemRadio value="grid">Grid</li>
</ul>
```

### Fixing the error

Wrap the radio items that exclude each other in a group, and bind the selected value there:

```html
<div cngxMenu label="View">
  <div cngxMenuGroup label="Layout" [(selectedValue)]="layout">
    <div cngxMenuItemRadio value="list">List</div>
    <div cngxMenuItemRadio value="grid">Grid</div>
  </div>
</div>
```

For an on/off item that stands alone, use `[cngxMenuItemCheckbox]` instead.

### Debugging the error

The message reads `CNGX1057: [cngxMenuItemRadio] must be placed inside an element with [cngxMenuGroup].` In a production build the message is the bare code `CNGX1057`; the check still runs there.

The check runs once, in the constructor, and looks only at the element injector. Angular resolves it from where the item is declared, not from where it ends up in the DOM, so a radio item passed as content into a component that renders the group in its own template does not find that group.
