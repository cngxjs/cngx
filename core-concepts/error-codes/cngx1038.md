# CNGX1038

## Stepper control and async click on one element

This warning is emitted when `[cngxStepperNext]` or `[cngxStepperPrevious]` is applied to the same element as `[cngxAsyncClick]`.

The stepper controls derive their state from the stepper: `[cngxStepperNext]` is disabled on the last step and while a commit is in flight, `[cngxStepperPrevious]` on the first step and while a commit is in flight. They express this with `aria-disabled` only, so the button stays focusable and announces why it does nothing. `CngxAsyncClick` runs its own action on click and also sets `aria-disabled` while that action is pending.

On one element, two host bindings write `aria-disabled` from two unrelated sources, and whichever updates last wins. The button can announce itself as enabled while the stepper is committing, or stay disabled after the async action settled. Both directives also handle the click, so one click can run the async action and move the stepper.

```html
<!-- WARNING: both directives write aria-disabled and both handle the click -->
<button cngxStepperNext [cngxAsyncClick]="saveDraft">Next</button>
```

### Fixing the warning

#### Option 1: Let the stepper run the async work

Move the async work into the stepper's commit action. The stepper then gates the move on the result and drives the busy and disabled state itself:

```html
<cngx-stepper [commitAction]="saveStep">
  ...
  <button cngxStepperNext>Next</button>
</cngx-stepper>
```

#### Option 2: Use separate buttons

If saving and moving on are separate actions, give each its own button: `[cngxAsyncClick]` on a Save button and `[cngxStepperNext]` on the Next button.

### Debugging the warning

The message starts with `CNGX1038: CngxStepperNext:` or `CNGX1038: CngxStepperPrevious:` and says both directives gate `aria-disabled`. Search your templates for elements that carry both attributes.

The check runs in development mode only, once per control, when it is created. It looks for `CngxAsyncClick` on the same element only; an async click on a wrapper or a sibling does not trigger it. The same conflict between `[cngxAsyncStatus]` and `[cngxAsyncClick]` over `aria-busy` is [CNGX1019](cngx1019.html).
