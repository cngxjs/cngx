# CNGX1077

## Two hotkeys tie on one press

This warning is emitted when two live bindings in the hotkey registry from `@cngx/common/interactive` match the same key press at the same scope depth, and neither is the one the user should get for a reason the scope tree can see.

The registry resolves every press from the focused element outwards: a binding registered in a deeper hotkey scope on the focus path wins over an outer one, and that shadowing is intended and silent. Two bindings at the same depth (two app-level bindings, or two bindings in sibling scopes off the focus path) have no such order, so the one registered last runs and the other never fires. The press is not lost and nothing throws.

```ts
// WARNING: both are app-level and both bind mod+s
injectHotkey({ id: 'editor.save', combo: 'mod+s', run: () => saveDraft() });
injectHotkey({ id: 'form.save', combo: 'mod+s', run: () => submit() });
```

### Fixing the warning

Give one of the bindings another combo, or move it into the region it belongs to with `[cngxHotkeyScope]` so the deeper scope wins while focus is there. A binding that should only fire while its region has focus takes `reach: 'focus'`.

```html
<form cngxHotkeyScope>
  <!-- form.save registered in here wins while focus is inside the form -->
</form>
```

### Debugging the warning

The message starts with `CNGX1077: createHotkeyRegistry(): hotkeys "<a>" and "<b>" both matched one press at the same scope depth;` and names the binding that ran. The context object carries both ids (`{ winner, shadowed }`). It is emitted on the first tied press of an id pair only, so repeated presses stay quiet.

The check runs in development mode only. In production the last registration still wins, without a warning.
