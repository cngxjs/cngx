# CNGX2014

## Filter group, expression or expression row outside a filter builder

This error is thrown when `[cngxFilterGroup]`, `[cngxFilterExpression]` or `<cngx-filter-expression-row>` from `@cngx/forms/filter-builder` is created without a filter builder above it.

The two directives are the building blocks of a custom filter-builder skin: each one addresses a node of the filter tree by its index path (`[cngxFilterGroup]="[0]"`, `[cngxFilterExpression]="[0, 2]"`) and exposes that node, its labels and its state to the template. They hold no tree of their own; they read it from the presenter of the surrounding builder. `<cngx-filter-builder>` carries that presenter, and a hand-built skin gets it from `[cngxFilterBuilderPresenter]` on its root element. `<cngx-filter-expression-row [path]>` is the built-in row skin for one expression node and reads and writes it through the same presenter. Without it a path points into nothing, so the constructor throws instead of rendering an empty group, expression or row.

```html
<!-- ERROR: no presenter above the group -->
<div [cngxFilterGroup]="[]" #group="cngxFilterGroup">
  ...
</div>
```

### Fixing the error

Put the directives inside the element that carries the presenter, and bind the presenter's inputs there:

```html
<div cngxFilterBuilderPresenter [fields]="fields" [(value)]="tree">
  <div [cngxFilterGroup]="[]" #group="cngxFilterGroup">
    ...
  </div>
</div>
```

Inside `<cngx-filter-builder>`, the built-in body already renders the groups and expressions; a custom row or group template projected into it finds the builder's presenter the same way.

### Debugging the error

The message names the directive or component, for example `CNGX2014: [cngxFilterGroup] must be placed inside <cngx-filter-builder> or an element with [cngxFilterBuilderPresenter].` In a production build the message is the bare code `CNGX2014`; the check still runs there.

The check runs once, in the constructor, and looks only at the element injector. Angular resolves it from where the directive is declared, not from where it ends up in the DOM. A directive passed as content to a wrapper component whose template carries the presenter resolves from the template it was written in, where no presenter is above it, so it throws. Declare the presenter in the same template as the directives.
