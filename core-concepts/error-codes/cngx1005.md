# CNGX1005

## No state source for `[cngxAudioStatus]`

This error is reported when a `[cngxAudioStatus]` directive has neither a bound `[state]` input nor a `CNGX_STATEFUL` provider above it.

`[cngxAudioStatus]` plays earcons on async-state transitions, so it needs a `CngxAsyncState` to watch. It resolves the state the same way the feedback bridges do: an explicit `[state]` input wins, otherwise it injects `CNGX_STATEFUL` from the element injector tree. `CNGX_STATEFUL` is provided by state-owning artifacts such as `[cngxAsyncBoundary]`, the select family in `@cngx/forms/select` and `<cngx-timeline>`. With neither source, the directive tracks a constant `idle` status.

The binding parses, the template renders, and no earcon ever plays. A common cause is copying the directive onto a host whose async state is exposed through an export or a field, without binding it:

```html
<!-- ERROR: the state of cngxAsyncClick is never handed to cngxAudioStatus -->
<button
  type="button"
  [cngxAsyncClick]="save"
  [cngxAudioStatus]="'succeeded:success, failed:error'"
>
  Save
</button>
```

`[cngxAsyncClick]` does not provide `CNGX_STATEFUL`, so placing both directives on one element is not enough.

### Fixing the error

#### Option 1: Bind the state explicitly

```html
<button
  type="button"
  [cngxAsyncClick]="save"
  #saveClick="cngxAsyncClick"
  [cngxAudioStatus]="'succeeded:success, failed:error'"
  [state]="saveClick.state"
>
  Save
</button>
```

Any `CngxAsyncState` works here, for example one from `injectAsyncState(...)` in the component.

#### Option 2: Place the directive under a `CNGX_STATEFUL` provider

Leave `[state]` unbound and put the directive on, or inside, an artifact that provides `CNGX_STATEFUL`:

```html
<section [cngxAsyncBoundary]="reportSources" [cngxAudioStatus]="'success:complete'">
  ...
</section>
```

`reportSources` is an array of `{ key, state }` entries (`AggregateSource` from `@cngx/common/data`); the boundary provides their aggregate as `CNGX_STATEFUL`.

A bare `state` attribute without a value is treated as unbound, so the fallback still applies.

### Debugging the error

The message names only the directive: `[cngxAudioStatus] No state source.` Search for `[cngxAudioStatus]` usages that have no `[state]` binding and check which of them sit outside a `CNGX_STATEFUL` provider.

The check runs in development mode only, once per directive instance, after the first render. It does not re-run, so a state bound later is not reported, and a `[state]` bound to an expression that evaluates to `undefined` at that moment is reported even if it becomes defined afterwards. The same condition on the `@cngx/ui` feedback bridges (`CngxToastOn`, `CngxAlertOn`, `CngxBannerOn`) is [CNGX3002](cngx3002.html). A DOM-event key in the same binding is [CNGX1004](cngx1004.html).
