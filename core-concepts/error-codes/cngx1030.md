# CNGX1030

## Duplicate tree selection key

This error is reported when `createTreeController` gets the same key from `keyFn` for two different nodes.

The node id (from `nodeIdFn`) identifies a node's position for expansion and focus. The key (from `keyFn`) identifies a node's *value* for selection. The controller indexes every node by key for `findByValue`, `childrenOfValue` and `descendantsOfValue`, and selection controllers built on the same `keyFn`, such as the one inside `CngxTreeSelect`, track membership by key. `keyFn` resolves from the options, then from `provideTreeConfig(withDefaultKeyFn(...))`, then falls back to the value itself.

Two nodes with one key are one entry for selection. Selecting one marks both as selected, and every key lookup returns only the node that came later in the tree. With cascading selection, the children of the later node are toggled when the user checks the earlier one. The tree renders normally, so the bug shows up as checkboxes that tick together, not as a crash.

The identity fallback is the usual cause: two nodes whose values are equal primitives collide.

```ts
// ERROR: "Archive" appears under two parents; the string is the key
const tree = createTreeController<string>({
  nodes: this.folderNames,
  nodeIdFn: (name, path) => path.join('/'),
});
```

### Fixing the error

#### Option 1: Use object values with a unique key

Give each node a record with a global key, and return that key from both `nodeIdFn` and `keyFn`:

```ts
const tree = createTreeController<Folder>({
  nodes: this.folders,
  nodeIdFn: (folder) => folder.id,
  keyFn: (folder) => folder.id,
});
```

On `<cngx-tree-select>`, bind the same function to its `[keyFn]` input. The tree select passes its own `keyFn` to the controller, so an app-wide `withDefaultKeyFn` does not apply there.

#### Option 2: Set the key app-wide

If every tree in the app uses the same domain type, provide the key once with `provideTreeConfig(withDefaultKeyFn<Folder>((folder) => folder.id))` from `@cngx/common/interactive`. A per-controller `keyFn` still wins.

### Debugging the error

The message quotes the key as a string, for example `CNGX1030: createTreeController(): duplicate selection key "Archive" from keyFn`. An object key is quoted as `"[object Object]"`, which means two nodes share one object reference. The controller reports each key once per controller, however often the tree re-derives, so one line means one key, not one occurrence; object keys share the string `[object Object]` for this deduplication, so only the first duplicate object key is reported.

The check runs in development mode only. A duplicate node *id* from `nodeIdFn` is a separate error, [CNGX1029](cngx1029.html); the two often fire together when both functions read the same non-unique field.
