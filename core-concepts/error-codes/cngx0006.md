# CNGX0006

## Invalid `dir` on the document root

This warning is emitted when `injectDirection()` from `@cngx/core` reads a `dir` attribute on `<html>` that is not `ltr`, `rtl` or `auto`.

`dir` is an enumerated attribute. The browser matches its value case-insensitively and does not trim it, so `dir="RTL"` is right-to-left, while `dir="rlt"`, `dir="right"` or `dir=" rtl"` are invalid. An invalid value is ignored: the browser lays the page out as if `dir` were absent, which is left-to-right unless an ancestor says otherwise.

cngx follows the browser and reports `'ltr'`, so keyboard navigation and positioning agree with the layout. The page still renders left-to-right when it was meant to be right-to-left, and nothing throws, so the warning names the value instead.

```html
<!-- WARNING: a typo, the browser ignores it and the page stays LTR -->
<html dir="rlt">
```

### Fixing the warning

#### Option 1: A fixed direction

Set one of the two valid values:

```html
<html dir="rtl">
```

Under Angular i18n the framework sets `<html dir>` from the active locale; check the locale data when the value comes from there.

#### Option 2: Direction from the content

Set `dir="auto"`. The browser resolves the root from the first strong character in tree order (the `<title>` included), and `injectDirection()` reports that result. It is read at construction, after the first render and on every change of the root `dir`; content that arrives later does not re-resolve it.

#### Option 3: A direction cngx should report regardless of the DOM

Use `provideDirection('rtl')` in the application config (or `provideDirectionAt('rtl')` in a component's `viewProviders`). It forces what `injectDirection()` reports and never touches the attribute.

### Debugging the warning

The message starts with `CNGX0006: injectDirection() ignores <html dir=` and names the value it read, lowercased. Search the templates, `index.html` and any code that calls `setAttribute('dir', ...)` or sets `document.documentElement.dir`.

The check runs in development mode only. It fires on the first read and again on each root `dir` change to a different invalid value; setting the same invalid value twice warns once, and a valid value in between makes the next invalid one warn again.
