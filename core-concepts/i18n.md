# Localisation

<aside class="cc-tldr">

Every user-facing string CNGX renders is English by default and overridable through a DI token. Today you compose the per-lib providers you actually use into one `Provider[]` const, and that const is your language file. One data file per language behind a single `provideCngxI18n(withPack(...))` call is landing in this release; see [Language files](#language-files).

</aside>

CNGX ships English defaults. It does not ship translations, and it does not extract messages at build time: the contract is a DI token per feature area, overridable app-wide or per subtree, with a value or a `Signal` that switches the language at runtime. A coverage guard (`scripts/__tests__/user-facing-string-coverage.test.mjs`, run by `npm run test:scripts`) keeps it honest - a new hardcoded string fails the suite unless it lives in an override source.

---

## Two levels, no middle

**Per key.** Every area exposes a partial override, so one label changes and the rest stay English:

```ts
provideTabsI18n(withTabsI18nLabels({ tabsLabel: 'Reiter' }))
```

Unset keys keep their default. There is no all-or-nothing bundle to fill in.

**Whole app.** Collect the providers you use into one exported const. That const is your language file:

```ts
// src/i18n/de.ts
import type { EnvironmentProviders, Provider } from '@angular/core';
import { provideCardI18n, withCardI18nLabels } from '@cngx/common/card';
import { provideDialogConfig, withDialogLabels } from '@cngx/common/dialog';
import { provideTabsI18n, withTabsI18nLabels } from '@cngx/common/tabs';
import { provideSelectConfig, withAriaLabels } from '@cngx/forms/select';
import { provideFeedbackI18n } from '@cngx/ui/feedback';

export const DE: (Provider | EnvironmentProviders)[] = [
  provideTabsI18n(withTabsI18nLabels({ tabsLabel: 'Reiter', addTab: 'Neuer Reiter' })),
  provideCardI18n(withCardI18nLabels({ selected: 'Ausgewählt', deselected: 'Abgewählt' })),
  provideDialogConfig(withDialogLabels({ close: 'Dialog schließen' })),
  provideSelectConfig(withAriaLabels({ searchInput: 'Optionen durchsuchen' })),
  provideFeedbackI18n({
    alertsRegionLabel: 'Hinweise',
    announcements: { alertDismissed: 'Hinweis verworfen' },
  }),
];
```

```ts
bootstrapApplication(App, { providers: [...DE] });
```

Both levels resolve to the same tokens. Pick the smallest surface that fits.

## Resolution order

The contract: every user-facing string resolves `input ?? config ?? default`. An explicit binding on the instance wins, else the app-wide token value, else the English default that token ships.

A per-instance input alone does not count as translatable, and neither does a default copied out of the token when the component is created. Every input that renders copy is declared `input<T | undefined>(undefined)` and resolved against the token in a `computed()`, so `undefined` means unbound and nothing is read at construction. Sketched for a hypothetical `AppAlertRegion` built on the feedback token:

```ts
private readonly i18n = inject(CNGX_FEEDBACK_I18N);
readonly landmarkLabel = input<string | undefined>(undefined);
protected readonly resolvedLandmarkLabel = computed(
  () => this.landmarkLabel() ?? this.i18n().alertsRegionLabel,
);
```

Bind `[landmarkLabel]` and the binding wins; leave it unbound and the token decides, for the whole lifetime of the instance. When the token's Signal changes, the unbound label changes with it. Reading `instance.landmarkLabel()` returns what the consumer bound, not the resolved text.

One input keeps the default it read at creation: `CngxPhoneInput.country`, a two-way `model<Country>` whose unbound default region comes from the locale. Widening it would break `[(country)]` bindings to `Country`-typed fields. The country name it shows still follows a locale switch.

**Composed copy is a function.** Anything with a count, a plural, a percentage or an "X of Y" is a `(params) => string` key, not a template the component assembles:

```ts
provideFeedbackI18n({
  announcements: {
    alertOverflow: (count) =>
      count === 1 ? '1 weiteren Hinweis anzeigen' : `${count} weitere Hinweise anzeigen`,
  },
});
```

Word order and plural rules belong to whoever writes the language file. A component never concatenates a translated word with a number.

**Numbers and dates follow the app locale.** A number or date CNGX displays is formatted with the app locale (`CNGX_LOCALE`, default: the nearest `LOCALE_ID`), never with a hand-appended unit or the runtime default. See [Locale](#locale). Counts passed to a composed-copy function arrive as raw numbers so the translator picks the plural form.

## Language files

> Landing in this release. `provideCngxI18n` and the message format are in place; the CNGX areas move onto it one by one. Until an area reads its section of the pack, the per-token providers in [Where each string lives](#where-each-string-lives) remain the way to translate it.

One call in the app config sets the language for the whole app:

```ts
import { signal } from '@angular/core';
import { provideCngxI18n, withPack, type CngxCompleteLanguagePack } from '@cngx/core/i18n';

export const languagePack = signal<CngxCompleteLanguagePack | undefined>(undefined);

bootstrapApplication(App, { providers: [provideCngxI18n(withPack(languagePack))] });
```

`undefined` means English. A pack is a plain data object: `locale` (a BCP 47 tag), an optional `dir`, and one section per CNGX area. Each CNGX entry adds its section to the pack type, so the type asks for exactly the areas your code imports, and a pack that misses a key fails to compile. `withPartialPack(...)` accepts gaps and reads English for every missing key.

**Loading and switching.** The pack Signal is the whole mechanism. Load a pack with your own dynamic import and set the Signal once it has arrived: the current pack stays active until the new one is complete, and the module cache keeps every pack you have loaded.

```ts
const packs = {
  de: () => import('./i18n/de'),
  ar: () => import('./i18n/ar'),
};

export async function useLanguage(lang: keyof typeof packs | 'en'): Promise<void> {
  if (lang === 'en') {
    languagePack.set(undefined);
    return;
  }
  try {
    languagePack.set((await packs[lang]()).default);
  } catch {
    // The current pack stays active; report the failed load your own way.
  }
}
```

Set the start language before bootstrap, or in your own `provideAppInitializer(() => useLanguage(startLanguage))`. The same works under SSR.

**Messages.** A section key holds one of three shapes, all plain data:

- A sentence with `{name}` placeholders: `"Step {position} of {count}"`.
- A plural object: `{ "one": "{count} error", "other": "{count} errors" }`. The form is picked by `Intl.PluralRules` for the pack's locale from the `count` argument; `zero`, `one`, `two`, `few` and `many` are optional, `other` is required and covers every form a message leaves out.
- A record keyed by a value, for a distinction by case: `{ "online": "online", "busy": "beschäftigt" }`.

A number inserted into a message is formatted for the pack's locale. An inserted string is wrapped in Unicode isolates (U+2068 / U+2069), so a name in another script keeps its own direction inside the sentence. A pack written in TypeScript may use a function for a message the data shapes cannot express.

**Locale and direction.** The pack drives `CNGX_LOCALE` (its `locale`) and `CNGX_DIRECTION` (its `dir`, else derived from the locale), and CNGX writes `<html lang>` and `<html dir>` from it. One switch flips copy, number format, plural rules, layout direction and arrow-key direction in the same pass. For regional formats, spread the pack: `{ ...de, locale: 'de-CH' }`. If your app sets `lang` and `dir` itself, pass `withDocumentLanguage('off')`; `CNGX_DIRECTION` then keeps reading `dir` from the DOM. A `provideLocale(...)` or `provideDirection(...)` listed after `provideCngxI18n(...)` wins.

**Per-token overrides stay.** Every `provide*I18n(...)` and `with*Labels(...)` in the table below still applies on top of the pack, key by key, also in a subtree.

## Scoping to a subtree

Every provider is an ordinary Angular provider, so a component's `viewProviders` scopes it to that subtree:

```ts
@Component({
  viewProviders: [provideDialogConfigAt(withDialogLabels({ close: 'Fermer' }))],
})
export class FrenchSection {}
```

Areas that ship a `provide*At` variant name it explicitly; the rest work the same way because the token resolves through the element injector.

## Locale

`CNGX_LOCALE` (`@cngx/core/utils`) is the one locale every CNGX number and date is formatted with. Set it with `provideLocale(...)` at bootstrap or `provideLocaleAt(...)` in a subtree's `viewProviders`; both take a string or a `Signal<string>`. Components read it through `injectLocale()`.

```ts
const lang = signal('de-DE');
bootstrapApplication(App, { providers: [provideLocale(lang)] });
```

- **Precedence.** The nearest `CNGX_LOCALE` provider wins, even over a closer `LOCALE_ID`. Without one, the nearest `LOCALE_ID` applies, so an app that provides only `LOCALE_ID` formats exactly as before. `CngxNumericInput`'s `[locale]` input and `withNumericDefaults({ locale })` still win for that input.
- **Angular pipes.** `DatePipe`, `DecimalPipe`, `PercentPipe`, `CurrencyPipe` and `I18nPluralPipe` read `LOCALE_ID`, not `CNGX_LOCALE`. CNGX templates use none of them; an app that switches `CNGX_LOCALE` at runtime owns its own pipe usage.
- **Sort order.** Collation (`localeCompare`) in the data-source and treetable sort uses the runtime default locale and is not governed by `CNGX_LOCALE`.
- **Mid-edit flips.** A locale flip while a numeric input is focused applies on blur: the typed text is parsed in the locale it was typed in. A filled date mask keeps its digits and re-reads them in the new field order; re-set the value if the order changed.

## Runtime language switching

Every token in the table above accepts a `Signal`. Every `provide*I18n(...)`, `with*I18nLabels(...)` and `with*Labels(...)` takes a value or a `Signal` of one, and `provideLocale(...)` takes a string or a `Signal<string>`. Two take their Signals differently: `withAccordionLabels` takes a `Signal<string>` per key, and `provideRecyclerI18n` takes a complete `RecyclerI18n` (or a Signal of one) and does not merge over the defaults, so its English branch is the full English bundle rather than `{}`. Drive them all from one language Signal and the whole app switches without a reload or a re-created injector:

```ts
// src/i18n/language.ts
import { computed, signal, type EnvironmentProviders, type Provider, type Signal } from '@angular/core';
import { provideDialogConfig, withDialogLabels } from '@cngx/common/dialog';
import { provideTabsI18n, withTabsI18nLabels } from '@cngx/common/tabs';
import { provideLocale } from '@cngx/core/utils';
import { provideSelectConfig, withAriaLabels } from '@cngx/forms/select';
import { provideFeedbackI18n } from '@cngx/ui/feedback';

export const lang = signal<'en' | 'de'>('en');

const de = <T extends object>(bundle: T): Signal<Partial<T>> =>
  computed(() => (lang() === 'de' ? bundle : {}));

export const LANGUAGE: (Provider | EnvironmentProviders)[] = [
  provideLocale(computed(() => (lang() === 'de' ? 'de-DE' : 'en-US'))),
  provideTabsI18n(withTabsI18nLabels(de({ tabsLabel: 'Reiter', addTab: 'Neuer Reiter' }))),
  provideDialogConfig(withDialogLabels(de({ close: 'Dialog schließen' }))),
  provideSelectConfig(withAriaLabels(de({ searchInput: 'Optionen durchsuchen' }))),
  provideFeedbackI18n(de({ alertsRegionLabel: 'Hinweise' })),
];
```

```ts
bootstrapApplication(App, { providers: [...LANGUAGE] });
// later, anywhere:
lang.set('de');
```

An empty override means "English default", so the English branch stays `{}`. Overrides merge exactly as they do with plain values: a partial still merges key by key over the defaults, a nested bundle such as the feedback `announcements` or the stepper `statusLabels` still merges per key, and a `provide*At` in a subtree still resolves against the same base it always did. With plain values every string renders exactly as before.

Three helpers in `@cngx/core/utils` carry the mechanism, and a hand-written feature or a custom component uses the same ones: `coerceSignal` (value or Signal to Signal), `createOverrideMerge` (defaults merged with partial overrides as one memoized `computed()`) and `createNestedOverrideMerge` (the same, with one nested record merged key by key).

**The flip rule.** A language change re-renders every label, name, description and placeholder at once. It never changes what a live region already says: a region keeps its text until its next status change, which then speaks the new language, so a switch never re-announces a stale status. Shown validation messages in `cngx-field-errors` and `cngx-form-errors` are live regions too; they stay in the old language until the field's errors change. A consumer formatter that reads a language Signal itself, such as an error-message function, follows the same rule, because CNGX calls it untracked inside the live region.

Upgrading from a release where the tokens resolved at construction: see the [localisation migration](./i18n-migration.md) for every changed type and its replacement.

## What is not in scope

`$localize` extraction is not part of the contract. CNGX ships no language packs; the language file is yours. Component copy a consumer authors - option labels, titles, messages - was never CNGX's to translate. Angular's locale pipes and Material's own intl classes (`MatPaginatorIntl`, `MatStepperIntl`) follow `LOCALE_ID` and their own services, not `CNGX_LOCALE` or the tokens above.
