# Localisation

<aside class="cc-tldr">

Every user-facing string CNGX renders is English by default and overridable through a DI token. There is no central `CngxI18n` type to configure - you compose the per-lib providers you actually use into one `Provider[]` const, and that const is your language file.

</aside>

CNGX ships English defaults. It does not ship translations, and it does not extract messages at build time: the contract is a DI token per feature area, read at construction, overridable app-wide or per subtree. A coverage guard (`scripts/__tests__/user-facing-string-coverage.test.mjs`, run by `npm run test:scripts`) keeps it honest - a new hardcoded string fails the suite unless it lives in an override source.

---

## Two levels, no middle

**Per key.** Every area exposes a partial override, so one label changes and the rest stay English:

```ts
provideTabsI18n(withTabsI18nLabels({ tabsLabel: 'Reiter' }))
```

Unset keys keep their default. There is no all-or-nothing bundle to fill in.

**Whole app.** Collect the providers you use into one exported const. That const is your language file:

```ts
// src/i18n/de.ts
import type { Provider } from '@angular/core';
import { provideCardI18n, withCardI18nLabels } from '@cngx/common/card';
import { provideDialogConfig, withDialogLabels } from '@cngx/common/dialog';
import { provideTabsI18n, withTabsI18nLabels } from '@cngx/common/tabs';
import { provideSelectConfig, withAriaLabels } from '@cngx/forms/select';
import { provideFeedbackI18n } from '@cngx/ui/feedback';

export const DE: Provider[] = [
  provideTabsI18n(withTabsI18nLabels({ tabsLabel: 'Reiter', previousTab: 'Vorheriger' })),
  provideCardI18n(withCardI18nLabels({ selected: 'Ausgewählt', deselected: 'Abgewählt' })),
  provideDialogConfig(withDialogLabels({ close: 'Dialog schließen' })),
  provideSelectConfig(withAriaLabels({ searchInput: 'Optionen durchsuchen' })),
  provideFeedbackI18n({
    alertsRegionLabel: 'Hinweise',
    announcements: { alertDismissed: 'Hinweis verworfen' },
  }),
];
```

```ts
bootstrapApplication(App, { providers: [...DE] });
```

Both levels resolve to the same tokens. Pick the smallest surface that fits.

## Resolution order

The contract: every user-facing string resolves `input ?? config ?? default`. An explicit binding on the instance wins, else the app-wide token value, else the English default that token ships.

A per-instance input alone does not count as translatable. An input that renders copy takes its default from the token, read once at construction. Sketched for a hypothetical `AppAlertRegion` built on the feedback token:

```ts
private readonly i18n = inject(CNGX_FEEDBACK_I18N);
readonly landmarkLabel = input(this.i18n().alertsRegionLabel);
```

Bind `[landmarkLabel]` and the binding wins; leave it unbound and the token decides. Because the default is read at construction, it is a snapshot: an unbound instance keeps the value the token held when it was created. A newly added input that must follow the token for its whole lifetime is declared `input<string | undefined>(undefined)` and resolved in a `computed()`:

```ts
readonly landmarkLabel = input<string | undefined>(undefined);
protected readonly resolvedLandmarkLabel = computed(
  () => this.landmarkLabel() ?? this.i18n().alertsRegionLabel,
);
```

**Composed copy is a function.** Anything with a count, a plural, a percentage or an "X of Y" is a `(params) => string` key, not a template the component assembles:

```ts
provideFeedbackI18n({
  announcements: {
    alertOverflow: (count) =>
      count === 1 ? '1 weiteren Hinweis anzeigen' : `${count} weitere Hinweise anzeigen`,
  },
});
```

Word order and plural rules belong to whoever writes the language file. A component never concatenates a translated word with a number.

**Numbers and dates follow the app locale.** A number or date CNGX displays is formatted with the app locale (`CNGX_LOCALE`, default: the nearest `LOCALE_ID`), never with a hand-appended unit or the runtime default. See [Locale](#locale). Counts passed to a composed-copy function arrive as raw numbers so the translator picks the plural form.

---

## Why there is no `provideCngxI18n()`

A single aggregator would need a central type tracking every lib's i18n surface forever, and it would re-introduce the cross-lib coupling the per-token design exists to avoid. It would also add nothing: the const above is the same one-file ergonomics, composed by the consumer, maintained by nobody.

This is Pillar 3 applied to configuration - CNGX ships the hooks, you compose them.

---

## Scoping to a subtree

Every provider is an ordinary Angular provider, so a component's `viewProviders` scopes it to that subtree:

```ts
@Component({
  viewProviders: [provideDialogConfigAt(withDialogLabels({ close: 'Fermer' }))],
})
export class FrenchSection {}
```

Areas that ship a `provide*At` variant name it explicitly; the rest work the same way because the token resolves through the element injector.

## Locale

`CNGX_LOCALE` (`@cngx/core/utils`) is the one locale every CNGX number and date is formatted with. Set it with `provideLocale(...)` at bootstrap or `provideLocaleAt(...)` in a subtree's `viewProviders`; both take a string or a `Signal<string>`. Components read it through `injectLocale()`.

```ts
const lang = signal('de-DE');
bootstrapApplication(App, { providers: [provideLocale(lang)] });
```

- **Precedence.** The nearest `CNGX_LOCALE` provider wins, even over a closer `LOCALE_ID`. Without one, the nearest `LOCALE_ID` applies, so an app that provides only `LOCALE_ID` formats exactly as before. `CngxNumericInput`'s `[locale]` input and `withNumericDefaults({ locale })` still win for that input.
- **Angular pipes.** `DatePipe`, `DecimalPipe`, `PercentPipe`, `CurrencyPipe` and `I18nPluralPipe` read `LOCALE_ID`, not `CNGX_LOCALE`. CNGX templates use none of them; an app that switches `CNGX_LOCALE` at runtime owns its own pipe usage.
- **Sort order.** Collation (`localeCompare`) in the data-source and treetable sort uses the runtime default locale and is not governed by `CNGX_LOCALE`.
- **Mid-edit flips.** A locale flip while a numeric input is focused applies on blur: the typed text is parsed in the locale it was typed in. A filled date mask keeps its digits and re-reads them in the new field order; re-set the value if the order changed.

## Reactive-ready surfaces

Some surfaces already accept a `Signal`, so a copy change re-renders without re-creating the injector. Three helpers in `@cngx/core/utils` carry this: `coerceSignal` (value or signal to signal), `createOverrideMerge` (defaults merged with partial overrides as one memoized `computed()`) and the locale family above.

Tokens that accept a `Signal` today:

- `CNGX_INTERACTIVE_I18N`, `CNGX_KPI_I18N`, `CNGX_DISPLAY_I18N`, `CNGX_LAYOUT_I18N`, `CNGX_SPEAK_I18N` - their `with*I18nLabels(...)` take a partial or a `Signal` of one.
- The `labels` sub-bundles of the data-grid-accordion, popover-panel and sidenav configs.
- `CNGX_LOCALE`.

```ts
const labels = computed(() => (lang() === 'de' ? DE_KPI : {}));
provideKpiI18n(withKpiI18nLabels(labels));
```

Two limits. An input a consumer leaves unbound keeps the default it read at construction. A live region keeps the text it shows until the next status change, which then speaks in the new language; a language change never re-announces a stale status.

---

## What is not in scope

Runtime language switching is not part of the contract yet: most tokens resolve at construction, so swapping a language means re-creating the injector, which in practice means a reload. Only the reactive-ready surfaces above follow a live change; full runtime switching is tracked as follow-up work. `$localize` extraction is not part of the contract either. Component copy a consumer authors - option labels, titles, messages - was never CNGX's to translate.
